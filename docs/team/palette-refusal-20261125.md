# 收尾：命令面板残留的四处静默无操作（2026-11-25 第 179 轮）

第 178 轮的 palette 审计留下一条同根因未处理项：CP1 修掉了「复制／粘贴／全选」三行，但「关闭会话」「清屏」「在 Filer 中显示」「向右／向下分屏」四行在**没有活动标签、或活动标签是文件标签**时同样静默无操作。本条已修。

| 位置 | 旧行为 | 新行为 |
| --- | --- | --- |
| `App.tsx` `runShortcut` 的 `closeSession` | 无活动标签时 `return false`，什么都不发生 | 状态栏报「请先打开会话——此操作需要一个作用对象」 |
| 同上 `clear`／`revealCwd` | 无活动标签或文件标签时 `return false`，什么都不发生 | 无会话报上一条；有会话但没有终端（SFTP/FTP 标签）报「此会话没有终端可操作」 |
| 同上 `splitPane` | 无活动标签时 `return false`，什么都不发生 | 报「请先打开会话」 |

## 为什么改在这一处

这三条路径——快捷键、命令面板行、菜单项——**都汇到同一个 `runShortcut`**。改一处，三个界面同时得到解释；而且返回值语义不变（`false` 仍然表示「应用没有应答」，窗口级处理器据此决定是否阻止浏览器默认行为），所以没有引入新的行为分支。

## 验证

- `src/test/refusedShortcut.browser.test.ts` 两条新用例：文件标签按 Alt+K 报「没有终端」；关掉会话后再按报「没有活动会话」。
- 负控制：把两个 helper 改回 `return false`，两条同时红。

## 仍未处理

MenuBar 的 `withActive`（`MenuBar.tsx:364-366`）对同样的状态仍然静默无操作——它不走 `runShortcut`，是另一条代码路径。让菜单也复用 `runShortcut` 是一个较大的重构（MenuBar 拿不到 App 的 dispatcher），单独立项。
