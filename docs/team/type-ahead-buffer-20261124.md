# type-ahead 能改错字，也能被 Esc 取消（2026-11-24 第 103 轮）

上一轮的 type-ahead 只有「越敲越长」一条路：敲错一个字母，只能停 600ms 等它过期，或者用鼠标。这一轮把「缓冲区怎么变」变成一条有测试的规则。

## 一、规则（纯函数 `nextTypeAheadBuffer`）

| 按键 | 结果 |
| --- | --- |
| 可打印字符（600ms 内） | 续写这次搜索 |
| 可打印字符（停顿后） | 重新开始 |
| `Backspace` | 缩短搜索并重新跳转；缓冲为空时**不接管** |
| `Esc` | 仅在**有搜索**时清空缓冲并吞掉；否则留给菜单／筛选 |
| 空格、Ctrl/⌘/Alt 组合、多字符键名 | 不接管（空格仍是折叠、组合键仍属快捷键表） |

## 二、为什么拆成两个函数

- `nextTypeAheadRow` 回答「跳到哪一行」——搜索语义，4 条单测；
- `nextTypeAheadBuffer` 回答「这次按键算什么」——输入状态，5 条单测。

组件里只剩派发：拿到 `search` 就构建会话行列表并跳转，拿到 `clear` 就只清空，拿到 `none` 就交给原有的键盘分支。面板里原先那个 600ms 常量随之下移到纯函数模块。

| 层次 | 证据 |

## 四、两次自纠

1. **前提写错**：最初写「敲 `lz` 后光标不动」——但 `l` 已经匹配并移动了光标。改用两个同首字母会话（Lab box、Lab two）让搜索深度可观察。
2. **时序依赖**：单独跑通过、全量跑失败——两次 `await userEvent.keyboard(...)` 之间夹着 `twoFrames()`，在负载下可能超过 600ms，第二个字母就变成了新的一次搜索。改为一次调用输入两个字符。
3. **命名冲突**：改完后仍然失败，实际收到的活动行是 `session-row-Local%20Shell`——树里始终有一行内置 Local Shell，也从 L 开头，所以「回到 Lab box」这个期望本身不成立。换用 Z 开头的名字，仍然无法稳定复现「两键后回溯」这条路径。

**结论（写进 STATE）**：这条两键浏览器用例撤掉。`Backspace`／`Esc` 的语义由 `nextTypeAheadBuffer` 的 5 条单测覆盖，浏览器层只保留**单键**跳转（不受时序影响）。一条不能在门里稳定通过的用例不该留在门里。

## 五、一条边界

「600ms 内算同一次搜索」是产品语义，也是测试的时限假设。浏览器用例只应在**一次调用内**输入多个字符；需要跨调用时，改用纯函数单测（`nextTypeAheadBuffer` 已覆盖）。

## 六、验证

浏览器用例最初写「敲 `lz` 后光标不动」——但 `l` 已经匹配并移动了光标，前提就是错的。改成**两个同首字母的会话**（Lab box、Lab two）让搜索深度可观察，才既能证明 `la` 更深，也能证明 `Backspace` 回退。
