# 状态动效收敛到两个时长（2026-11-22 第 15 轮）

测量先于改动。把编译后的 CSS 读一遍，状态变化（`transition`）用了**四种"快"时长**：

| 时长 | 出现 | 用途 |
| --- | --- | --- |
| 80ms | 16 | 图标取色、面板按钮、分隔条高亮、进度条 |
| 90ms | 4 | 终端里的浮层定位 |
| 100ms | 25 | 输入框、按钮、标签页、面板 |
| 120ms | 33 | 行、面板、选项、标签页淡出 |
| 150ms / 160ms | 各 1 | 标签条遮罩、监视器条 |

同一个界面里，图标 80ms、输入框 100ms、行 120ms——差别看不出来，只觉得"某些地方反应略不同"。现在收敛为两个：

```css
/* :root 上，随主题一起可用 */
--dur-1: 90ms;  /* 行内小变化：图标取色、箭头转动、进度条 */
--dur-2: 120ms; /* 表面变化：行、输入框、按钮、标签页 */
```

- 50 处 `transition` 声明改为令牌；80/90 → `--dur-1`，100/120/150/160 → `--dur-2`。
- **关键帧动画不动**：菜单浮出（120ms 关键帧）、对话框升起（140ms）、旋转指示（640ms）是"效果"，不是"状态"，各自保留节奏。两者的区分写进了令牌注释。
- `0s` 的过渡（减少动效、拖动直跟）保持瞬时。

## 一、门禁

`src/test/motionTokens.browser.test.ts` 读**编译后的 CSSOM**，而不是源码：

- 任何 `transition` 里出现字面时长（除 `0s`/`0ms`）即失败；
- 负向对照：测试先注入一条 `.motion-probe { transition: color 200ms }`，断言检查器能抓到它，再移除——证明"零违规"不是因为什么都没看到；
- 下限：至少 20 条过渡声明被读到、至少 20 条真的用了令牌；
- xterm 自带的滚动淡出属于终端自己的契约，按选择器排除，边界写在测试注释里。

## 二、测量过程中踩到的两个坑（都写进了 LEARNINGS）

1. **`var()` 不会展开成长属性**：只读 `transition-duration` 时，用了令牌的规则返回空串，门禁只看到 10 条、其余全"通过"——空转。必须读 `transition` 短属性本身。
2. **序列化会丢默认值**：`color 200ms ease` 在 CSSOM 里变成 `color 200ms`（ease 是默认值），断言必须用规范化后的文本。

机械替换也迭代了两次：第一版按"冒号前的属性名"解析，被注释里的冒号带偏，漏掉 20 行多行声明；第二版按行状态机（遇 `transition:` 开、遇 `;` 关）才完整。

## 四、一次必须记录的失误与恢复

本轮用临时脚本批量改 CSS 时，第一版脚本按"冒号前是属性名"逐字符重写文件，把**注释**当成了声明：16 个样式文件里的注释被小写化、截断并粘到代码行尾，其中两个文件（`ftp`、`shell`）甚至出现了孤立的注释片段，无法再被解析。

恢复步骤（都已验证）：
1. 用规范化匹配（去空白、转小写）把每个注释与 `HEAD` 中的原文对齐并还原大小写与标点；
2. 删除被截断的重复片段，把粘在代码行尾的注释拆回独立行；
3. 两个解析失败的文件直接从 `HEAD` 重建，再逐条重新应用第 11/15 轮的改动（标题行高 / 行距令牌 / 命令标记 / z 阶梯 / 时长令牌），而不是继续在损坏文本上打补丁；
4. 校验：无嵌套或孤立注释、`biome format` 零解析错误、注释与 `HEAD` 逐字一致（24 条为本轮之前的会话新增）；
5. 全量重跑：单测、浏览器契约、typecheck、format:check、lint、构建全部通过。

教训写进了 LEARNINGS 77：机械改源码要用"行/声明级"替换并事后校验注释与花括号完整性，不能用字符级重写；一旦结构损坏，回滚重建比继续修补更快也更安全。

## 五、边界

- 只约束状态过渡；关键帧动画的时长没有收敛（它们按场景各自不同，本轮不碰）。
- xterm 内部样式不在契约内。
- 视觉差异无法在本会话内目视确认；本轮结论来自 CSSOM 读数与构建产物，不包含截图对比。
- 注释与空行的排版仍可能与 `HEAD` 有细微差异（本轮修复后已逐字比对注释；空行不参与断言）。
