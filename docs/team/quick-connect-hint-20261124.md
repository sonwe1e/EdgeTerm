# 连接行说清楚它以谁登录（2026-11-24 第 95 轮）

命令行面板的「连接到 …」只列了地址。当地址里省略了用户或端口，读者无法知道实际会以谁、哪个端口连——尤其 `10.0.0.5` 这种只有主机的写法，默认用户名来自空白资料的 `username`（空）而默认端口来自资料（22），两者都不是屏幕上能看到的。

## 一、交付

- 提示行改为由 App 解析出的**实际取值**：`SSH as {user}, port {port}`（中文：`以 {user} 登录，端口 {port}`），为空时给空串，端口缺失时用 22；
- 解析走的是 `quickConnectProfile(target, newSessionProfile())`——**与真正开会话同一段代码**，所以行里写的和实际连的一致；
- 「最近连接过」的行同时给出两段：`最近连接过 · 以 root 登录，端口 2222`。

## 二、一次被用例挡下的回退

第一版让记住的行也用同一个解析提示，于是它丢掉了「最近连接过」——浏览器用例里那句「从哪来的」断言立刻失败。两段信息各有用途：一段区分它和输入框现算的行，另一段说连接参数。现在拼接保留。

| 全量 | 见 STATE 本轮记录 |

## 四、边界

- 提示只解释参数，不解释认证方式：没有凭据时仍由既有认证流程询问；
- 段落文本面向朗读（`role="option"` 的可见文本），没有额外 aria 属性。
