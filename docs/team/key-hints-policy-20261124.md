# 自定义键的可发现性：规则与清单（2026-11-24 第 116 轮）

第 113–115 轮逐个给三个列表加上了 `aria-keyshortcuts`。这一轮把判断标准写下来，后面遇到新界面不用重新推理。

## 一、规则

| 键 | 归属 | 是否用 `aria-keyshortcuts` 声明 |
| --- | --- | --- |
| 方向键、Home/End、PageUp/PageDown | 列表／树／网格**模式自带** | 不声明——读屏软件已知这个模式的约定 |
| Enter 激活、Space 切换（模式里已定义时） | 模式自带 | 不声明 |
| **F2 重命名／编辑** | 本应用 | 声明 |
| **Delete / Backspace 删除当前行** | 本应用（不是 listbox 约定） | 声明 |
| **`/` 聚焦筛选** | 本应用 | 声明在筛选框上 |
| **Ctrl/⌘ + 其它** | 本应用，已进快捷键表 | 由快捷键设置界面负责，不重复声明 |

## 二、必须同时写清的限度

`aria-keyshortcuts` **只是提示**：不改变按键行为、不保证被读出。真实可用的键盘路径必须另有行为测试（本项目已有：F2 改名、Delete 删除、Enter 打开/发送、方向键移动、`/` 过滤、type-ahead）。

**声明不能替代实现**——如果键其实不能用，声明只会误导。

## 四、为什么逐个补而不是一次扫完

「哪些键属于本应用、哪些属于模式约定」只能看代码里实际处理了哪些键，再对照 ARIA 模式判断。批量添加会写出看似完整、实为不实的声明——比不声明更糟。
