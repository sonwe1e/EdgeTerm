# 清空筛选后把键盘还给输入框（2026-11-24 第 118 轮）

会话树筛选查不到东西时，界面会显示「没有匹配的会话」和「清空筛选」按钮。点击它之后——**焦点掉回 body**：按钮本身随消息一起卸载，而焦点没有去处，正在搜索的人必须用鼠标重新点回输入框。

## 一、修复

```
onClick={() => { setFilter(""); filterRef.current?.focus(); }}
```

注释写明理由：按钮即将卸载，读者还在搜索。

## 二、验证

| 层次 | 证据 |
| --- | --- |
| 行为 | `sessionTreeRename.browser.test.ts` 10/10（新增 1 条：点按钮后消息消失且 `activeElement` 是筛选框） |
| 负控制 | 去掉 `focus()` → 失败（`expected <body> to be <input>`）；恢复 → 通过 |
| 全量 | 见 STATE 本轮记录 |

## 三、这类问题的共同形状

**「点完就消失的按钮」必须自己安排焦点去向**：它卸载之后，焦点落到 body，键盘用户就丢了位置。本项目里同样形状的地方还有几处（对话框里的临时操作按钮、空状态入口），后续遇到时按这条规矩检查——不是每次都重新发现。
