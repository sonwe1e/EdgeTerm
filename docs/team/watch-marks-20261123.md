# 关键字的高亮与命中索引：现状核对 + 观察字的行标记（2026-11-23 第 34 轮）

积压清单第四项写的是「终端关键字高亮/命中索引」。先核对现状，再决定做什么。

## 一、现状：查找侧已经完成

`SearchOverlay` + `terminalSearchController` 已经提供：命中索引（`3/12`，超过上限显示 `1000+`）、大小写/整词/正则、仅在选区内查找、历史缓冲区（cold history）搜索、超时与不可用提示、随输出刷新结果。**这一半不需要再做**。

## 二、本轮真正补上的：长期可见的观察字标记

查找是「此刻正在看这一屏」的工具；日志里那条 200 行之前的失败，关掉查找框就消失了。因此本轮加的是**观察字**：行里出现 error/fatal/panic/failed/failure/exception 或 warn/warning/deprecated/retry/timeout 时，行号区的整行淡淡着色，错误红、警告黄，滚回历史仍然可见。

| 位置 | 变化 |
| --- | --- |
| `watchWords.ts`（新） | 纯函数 `watchSeverity(line)`，固定词表，错误优先于警告 |
| `terminalLineGutter.ts` | 按绝对行号记录标记；随输出解析增量更新、随缓冲裁剪清理、随清屏消失；行级缓存只改变化的行 |
| `ftp.styles.css` | 行背景着色（不是左侧竖条），与「命令边界/失败」的竖条互不冲突，可同时出现在一行 |

## 三、为什么是这种画法

1. **行背景而不是新标记**：命令边界用左侧 inset 竖条、失败改竖条颜色（第 48 轮决策）。观察字是另一类事实，用背景着色就能与竖条共存，不必争同一个像素。
2. **固定词表**：可配置词表需要完整的设置界面与持久化，收益不足以抵消复杂度；先覆盖日志里最常见的几个词。
3. **复数不算**：`0 errors, 2 warnings` 是一份报告，不是失败；正则的词边界天然排除复数形式，单测把这条钉住。
4. **全屏程序与 Agent TUI 不标记**：这两个场景行号区本来就是抑制的，标记也一并抑制，不在交互界面上叠色块。

## 五、边界

- 词表不可配置（见上）；
- 只按行首文本判定，不解析 ANSI 颜色：程序自己把失败染红时，我们仍以文字为准；
- 尚无「跳到上一个/下一个观察字」的快捷键，行标记先解决「看得见」，跳转留待后续。
