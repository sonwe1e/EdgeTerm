# 文件列表筛空时说明原因（2026-11-24 第 126 轮）

会话树和常用命令列表在筛选无结果时都会说明；文件列表没有。于是输入一个不匹配的名字后，读者看到的只是一份空列表——**分不清「目录是空的」和「筛选排除了一切」**。

## 一、改动

| 层 | 内容 |
| --- | --- |
| 文案 | 新增 `filer.noMatches`：「没有匹配“{filter}”的文件。」／“No files match “{filter}”.” |
| 渲染 | 仅在「非离线、无错误、有筛选、目录本身有内容、筛完为空」时显示，避免把空目录误说成筛选结果 |
| 动作 | 「清空筛选」按钮，清空后把焦点还给筛选框（第 118 轮的规矩：会消失的按钮要安排焦点去向） |
| 样式 | 复用既有 `.panel-empty` / `.panel-empty-action`，不新增样式 |

## 二、验证

| 层次 | 证据 |
| --- | --- |
| 行为 | `filerSelection.browser.test.ts` 8/8（新增 1 条：`zzz` → 提示含 `zzz` → 清空 → 焦点回输入框、行回来） |
| 全量 | 单测 212 文件／1918 用例；浏览器 72 文件／332 用例 |
| 负控制 | 把英文文案改成 `SENTINEL` → 失败（`expected 'SENTINELClear filter' to contain 'zzz'`） |

## 三、一次自纠

新用例最初追加在文件末尾。它前面的「切目录」用例会把面板导航到上级目录，而 `open()` 内部按 home 路径取行，于是先在那里失败。移到「切目录」用例**之前**即通过——**同一文件里用例的顺序也是夹具的一部分**。
