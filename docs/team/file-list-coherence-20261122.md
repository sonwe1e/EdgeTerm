# 文件列表的一致性（2026-11-22 第 11 轮）

shell 有测量门禁，但**双栏 FTP 从来没有被它看过**。把三套收集器指向这个界面后，抓到一个真实缺陷；顺手把两个文件列表的行距和排序提示统一了。

## 一、门禁发现

| 现象 | 判定 | 处理 |
| --- | --- | --- |
| 未排序的列标题按钮只有 **76×13 / 130×13** | **真实缺陷**：标题是按钮，但只有文字那么高；排序列因为里面多了 16px 箭头才勉强超过 16px 下限 | 标题按钮拉伸整行，行高按内容盒定为 24px（容器 25px 含 1px 分隔线） |
| FTP 行距 29px、Filer 虚拟列表 26px | 同一控件两种节奏 | 统一到一对令牌（见下） |
| 排序列只有一枚 16px 箭头 + 颜色变化 | 颜色/图形单一通道 | 增加 2px 强调色下划线；所有标题预留 2px 透明边框，切换排序不跳 |

## 二、统一的节奏

`foundation.styles.css` 新增两个令牌：

```css
--list-row-h: max(24px, calc(var(--panel-font-size) + 10px));
--list-row-pitch: calc(var(--list-row-h) + 2px);
```

- 双栏 FTP 的行高：29px → `--list-row-pitch`（默认 26px）。
- Filer 的两处 CSS 回退同样改用 `--list-row-h`；它的虚拟化器（`FilerPanel rowHeight = max(24, font + 10) + 2`）是同一公式的 JS 版本，已在代码里互相注明。
- 两个列表在切换标签时读起来是同一个控件，而不是两种密度。

## 三、验证

`src/test/fileLists.browser.test.ts` 2/2：

| 断言 | 说明 |
| --- | --- |
| FTP 界面三套门禁零缺陷 | 对比度/点击尺寸/文字截断，并要求 inspected 下限证明真的看到了内容 |
| 行高 = 独立推导的期望值 | `max(24, 面板字号 + 10) + 2`，不由被测令牌自己证明自己 |
| 六个列标题都 ≥ 24px 高 | 本地与远端两个浏览器各三个 |
| 排序列有 2px 下划线、其余透明 | 且每栏恰好一个排序列 |
| Filer 行槽与双栏同一节奏 | `.virtual-file-rows > div` 高度相同 |

全量：前端单测 175 文件／1724 用例、浏览器契约 48 文件／239 用例、typecheck、format:check（523 文件）、lint（仅生成绑定 2 条既有警告）、生产构建全部通过。

## 四、边界

- 下划线颜色用 `--accent`，测试只断言"存在/透明"，不断言具体色值（四种主题共用同一令牌）。
- JS 虚拟化器与 CSS 令牌仍是两份数值，靠注释与测试维持一致；彻底合并需要把行高从 JS 读回 CSS（或反之），本轮不做。
- 只覆盖 Chromium；FTP 的真实传输、拖拽态未在本轮审计范围内。
