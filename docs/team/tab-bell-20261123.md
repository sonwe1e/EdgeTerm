# 后台标签的响铃提醒（2026-11-23 第 38 轮）

读代码时发现一个空白：整个前端**没有任何 `onBell` 处理**。shell 或程序用 BEL 请求注意（构建结束、安装完成、`read` 等待输入），在别的标签页里什么都没有发生——只能靠猜哪台机器在等。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| 后台标签的会话响铃（BEL） | 该标签出现琥珀色铃铛徽标 |
| 当前正在看的标签响铃 | 不标记（人就在这里，徽标只会活到下一次点击） |
| 同一次后台响铃多次 | 只有一个徽标 |
| 选中该标签 | 徽标清除（与「命令完成」未读用同一个 acknowledge 路径） |
| 命令完成徽标与响铃徽标同时存在 | 并存：状态点在左、铃铛在其右，语义不同 |

## 二、实现

| 位置 | 变化 |
| --- | --- |
| `terminal.ts` / `terminalShared.ts` | `Terminal.onBell` → 回调 `onBell`；xterm 的 BEL 解析由它驱动 |
| `actions.ts` | 回调里调用 `noteTabBell(id)`（会话打开处是回调的唯一装配点） |
| store | `Tab.attention?: boolean` 与 `noteTabBell`；`acknowledgeTab` 同时清掉完成与响铃两种未读 |
| `TabStrip.tsx` | 状态点之后渲染铃铛徽标；tab 的 title 与 aria 文本追加「响铃」说明 |
| CSS | `.tab-bell` 用 `--yellow`，与「命令完成」的强调色区分 |

## 三、验证

| 用例 | 断言 |

## 四、边界

- 只做标签徽标，不发声、不闪窗口、不弹系统通知（Windows 通知需要额外权限与平台验证）；
- 只有 BEL；不解析程序自定义的「注意」序列；
- 当前标签的响铃不记任何状态，因此切走再切回也不会补一个徽标。
