# 新连接也能设「连接后执行的命令」（2026-11-23 第 56 轮）

第 53 轮把登录命令做进了会话对话框，但字段只在**已保存**的连接上出现——理由是新连接还没有 id，记在临时 id 下的命令永远找不回来。结果读者要先保存、再打开一次，才能设第一条命令。这一轮把这个洞补上。

## 一、行为变化

| 情况 | 之前 | 现在 |
| --- | --- | --- |
| 新建 ssh/local 连接 | 看不到该字段 | 可以看到并填写 |
| 点 Save / Save & connect | —— | 用返回的 id 把命令存进去，随后连接时自动发送 |
| 编辑已保存连接 | 每敲一个字就写一次 localStorage | 改为本地草稿，保存时一次写入（少写几十次盘，也不再在取消时留下半条命令） |
| 一次性本地 shell（不保存） | —— | 没有可归属的 id，不记录；行为不变 |

## 二、实现

| 位置 | 变化 |
| --- | --- |
| `SessionDialog.tsx` | 字段改为 `startupDraft` 本地状态（编辑时从 store 预填）；`commitStartup(saved)` 在 Save 与 Connect 两条路径都用返回的 id 写入 |

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `startupField.browser.test.ts`（1） | 新建连接能看到字段；输入后**未保存时不落盘**；点主按钮后命令存在 `p-new` 名下；随后 `write_session` 收到 `cd /srv/app\\r` |

这条用例同时验证了两件事：字段属于新连接，以及第 53 轮的自动发送在真实对话框流程里确实发生（此前只在直接 `openSession` 的路径上验证过）。

## 四、边界

- 一次性本地 shell 仍不记录命令（没有 profile id 可归属，这是刻意的）；
- 命令仍未进入 profile 文件：它是应用设置（D74），换机器不跟着走。
