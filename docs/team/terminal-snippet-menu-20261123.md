# 常用命令来到终端右键菜单（2026-11-23 第 52 轮）

常用命令此前能发的地方：管理弹层、命令面板。可读者真正敲命令时人在终端里——右键那里什么都没有。本轮把它放到手上。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| 终端右键（右键模式为菜单时） | 菜单末尾多出「发送常用命令 ▸」，子菜单列出保存的命令名 |
| 点一条 | 走与弹层、面板**完全相同**的入口发送（含参数询问） |
| 没有保存任何命令 | 不显示该入口 |
| 会话未连接 | 入口禁用 |

## 二、实现

终端面板不拥有对话框，参数询问框属于常用命令功能。于是加一层极小的登记：

| 位置 | 变化 |
| --- | --- |
| `snippetActions.ts` | `registerSnippetRunner(runner)` / `requestSnippetRun(snippet)`：未登记时退回直接发送 |
| `useSnippetRunner.tsx` | 挂载时登记自己的 `runSnippet`，卸载时注销 |
| `TerminalPane.tsx` | 菜单追加子菜单（最多 15 条），点击调 `requestSnippetRun` |

这样终端菜单不需要知道「有参数要先问」，三条入口也永远不会走出两种行为。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `snippetRunner.test.ts`（2） | 登记后调用收到同一个片段对象；未登记时退回直接发送（无 shell 时给出原因） |
| `snippets.browser.test.ts`（11，新增 1） | 右键终端 → 菜单含「发送常用命令」→ 展开子菜单 → 点「Logs」→ IPC 收到 `tail -f app.log\\r` |

## 四、踩到的坑（测试层）

右键模式由组件在渲染时读取。测试里先设置模式、**不等一帧**就派发右键，处理器闭包仍是旧模式（粘贴），菜单不会打开。正确顺序是「设模式 → 等一帧 → 派发」。这类问题只影响测试夹具，不影响产品行为，但值得记录：**状态影响渲染的闭包，夹具要先让渲染发生**。

另有一处类型细节被 typecheck 抓到：`RightClickAction` 的字面量是 `menu`，不是 `contextMenu`；浏览器测试对错误字面量照跑不误。

## 五、边界

- 子菜单最多列 15 条（菜单不是列表页，再多该去弹层或面板）；
- 子菜单只显示名称，不显示命令原文（原文在弹层与面板里已有）；
- 未连接时不显示参数询问（入口禁用），避免「填完才发现发不出去」。
