# 标签名的持久化（2026-11-22 第 26 轮收尾）

上一轮把「标签名不持久化」记成了边界。用户改名正是为了下次还认得出来，重启就丢等于白改——本轮补上。

## 一、实现

- `SavedTab.title`：只有用户真的起过名字才写入；未命名标签的载荷与从前逐字相同（`JSON.stringify` 不写 `undefined`）；
- 写入前统一走 `workspaceTitle()`：去空白、拒空白串、拒控制字符、限长 120——工作区文件是可手改的输入，不能当成可信数据；
- `restoreWorkspace` 把标题带回标签；恢复流程其余部分（新 id、数字、序号、目录、面板）不变。

## 二、验证

workspace.test.ts 新增 2 条（该文件 18/18）：

1. 改名 → 保存 → 解析 → 再恢复：第一个标签带 `deploy db`（保存时已去空白），第二个 `title` 仍为 undefined；原始 JSON 里 `"title"` 只出现一次，证明未命名标签没有被顺手写上;
2. 手工构造的坏输入：纯空白、121 字符、含控制字符、数字类型——全部被丢弃为 undefined。

## 三、F2 为什么不进可改键表

评审指出 F2 只是菜单里的展示字符串。查证后确认**不能**把它放进全局快捷键表：终端里的程序（mc、vim 映射、IDE 的 TUI）本来就接收 F2 的转义序列，全局拦截会让这些程序收不到键。现在的 F2 是**条带局部手势**：焦点在标签或条带上时才生效，终端里的 F2 照常透传。这条写进 DECISIONS，而不是当作遗漏。

## 四、边界

- 标题只随工作区快照走（与标签数字、序号一致），不进会话配置文件；
- 超过 120 字符的名字在保存时被视为无效（当前的输入框没有强制长度，属可接受偏差）。
