# 一个站不住的改动前提：文件面板就是当前标签（2026-11-24 第 87 轮）

想法：第 83 轮的「在终端中打开」只在文件面板所属会话**就是当前活跃 shell** 时可用。直觉上它太严格——我在 A 标签的文件面板里翻到了目录，为什么不能直接 cd A 的 shell，而非得切到 A？于是把动作改成「发给面板自己的会话」。

## 一、验证它是否成立

改完跑既有浏览器夹具，第二条用例（会话不是活跃标签时）**失败**：菜单项仍然禁用。读代码后原因很清楚——

```ts
const tab = useActiveTab();                                 // FilerPanel:80
const remoteId = remote ? (tab?.info.id ?? null) : null;   // :96
```

**文件面板没有「自己的会话」**：它是绑定在当前活跃标签上的单例面板。文件列表、筛选、Reveal 按钮取的都是 `useActiveTab()`。所以「面板的会话 ≠ 活跃标签」这个状态在本面板里**根本不存在**，我改的分支永远走不到。

## 二、处置

- **撤回**：动作恢复为「发送给当前活跃 shell」（`sendCommandText`），菜单启用条件仍是「当前标签是已连接的 shell」；
- **保留**：把发送逻辑拆出 `sendCommandToSession(id, command)`，由 `sendCommandText` 调用——「按 id 发一条命令」只有一个实现，将来做**标签级**文件面板时可直接复用；
- 用例恢复为「不是当前 shell 时禁用，且不写任何字节」。

## 三、留给以后的结论

- 想支持「在 A 标签的面板里 cd A 的 shell」，必须先有**标签级的文件面板**，而不是给单例面板加参数；
- 同一份直觉在两个不同的组件结构里结论相反：**先读实现，再改语义**。
