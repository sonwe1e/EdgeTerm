# 命令面板的提示补上端口（2026-11-24 第 109 轮）

上一轮记下的不一致：树能按端口筛会话，命令面板不能。根因很小——App 里构造会话提示的那段解析只取了 6 个字段，第 7 个 `port` 虽然写在 key 里却没被使用。

## 一、改动

```
- const [id, name, kind, host, username, shell] = JSON.parse(key)
+ const [id, name, kind, host, username, shell, port] = JSON.parse(key)
  const address = host && port ? target + ":" + port : target
```

提示因此变成 `ssh · build@build.internal:2222 · Connect`，而 `commandScore` 给提示也算分，所以 `2222` 能找回这条会话。

| 层次 | 证据 |
| --- | --- |
| 评分 | `commandPalette.test.ts` 31 条通过（新增：hint 带 `:2222` 时 `2222` 与 `build.internal:2222` 都命中） |
| 全量 | 见 STATE 本轮记录 |
| 真实 App | **没有证据**——见下 |

## 三、一条没站住的浏览器用例

我写了「在真实 App 里按端口找到会话」的浏览器用例，三次失败：查询 `2222` 之后 `options()` 返回**空**（断言消息收到空串）。同文件的其它用例能正常取到选项，说明夹具与选择器可用，但本轮没有定位到根因（是提示未更新、还是渲染路径在短列表下有别的行为，未确认）。

按第 103 轮的教训——**不能在门里稳定通过的用例不留在门里**——撤掉它，并把「浏览器层按端口搜索无证据」写进 STATE。这条限制比一个红色用例诚实。

## 四、下一步（如果继续追）

在浏览器夹具里把 `options()` 的文本直接打出来（哨兵法），先确认提示是否真的带上了 `:2222`；若带上了却仍为空，则问题在渲染路径而不在搜索。
