# 终端右键菜单：发送最近用过的命令（2026-11-23 第 62 轮）

上一轮把历史放进了命令行面板。但读者想重跑一条刚用过的命令时，手常常就在终端里——右键比先想起一个快捷键更快。

## 一、交付

| 位置 | 变化 |
| --- | --- |
| 终端右键菜单 | 新增「最近命令」子菜单（最多 10 条，最近在前），未连接时禁用 |
| `snippetActions.ts` | 抽出 `sendCommandText(command)`：与发送已保存命令共用同一条通道与同一句拒绝理由；`sendSnippet` 改为调用它后再报「已发送」 |

## 二、两个判断

1. **历史行不报「已发送」**：读者刚从自己的历史里挑了一条命令，命令已经出现在屏幕上；再弹一行状态提示只是噪音。所以 `sendCommandText` 只说失败原因，成功时不出声。
2. **菜单在绘制时读历史**：右键菜单每次打开都重建，读到的就是此刻的最近 10 条；不需要订阅，也不需要额外的刷新。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `snippets.browser.test.ts`（16，新增 1） | 历史里记一条 `git status` → 右键终端 → 菜单有「最近命令」→ 点 `git status` → `write_session` 收到 `git status\r`，且状态栏**没有**「Sent:」 |

## 四、边界

- 子菜单上限 10 条：它是「刚用过的那几条」的快捷入口，不是历史浏览器（那是面板的事，上限 40）。
- 没有任何历史时不显示该子菜单，而不是显示一个空的子菜单。
- 一次失败：测试最初用 `noteCommandSent` 期望顺带写进历史，实际没有——改为直接 `commandHistory.record`。这也说明历史写入只发生在真实提交路径上，模拟「上一条命令」不等于「已记录」。
## 五、本轮自查抓到的一次回归（已修）

`runShortcut` 里把 `setPaletteOpen(true)` 换成 `openPalette()` 后忘了把 `openPalette` 加进依赖数组：**typecheck 不报，lint 的 `useExhaustiveDependencies` 报了一个 error**。已补上依赖（`openPalette` 由 `useCallback([], …)` 稳定，补进去不引起重建）。

这条值得记下来：把内联调用换成具名回调时，依赖数组是**第二处要改的地方**，而它只有 lint 会提醒——所以 `npm run lint` 不是可选项。
