# 命令行面板列出最近用过的命令（2026-11-23 第 61 轮）

命令历史此前只做两件事：输入时行内补全、以及「清空历史」。想重跑一条几天前的长命令，只能靠记忆打出足够长的前缀等补全。

## 一、交付

| 位置 | 变化 |
| --- | --- |
| `history.ts` | 新增 `recent(limit)`：按最近使用排序，同一文本只出现一行 |
| `commandPalette.ts` | 新增 `history` 数据源与 `sendHistory` 动作；每行 id 为 `history:<n>`，标签就是命令本身，提示行显示它在哪台主机跑过 |
| `App.tsx` | 面板打开时把最近 40 条装进目录；选中即通过**与打字相同的发送通道**执行 |

## 二、三个判断

1. **历史行放在目录最后**：面板不搜索时是目录，读者熟悉的顺序是固定动作在前。历史行放最后，不把 40 行历史压在其他命令之上；搜命令文本时照旧能找到它。
2. **目录在「打开面板」时重建**，不是每次记录命令时重建：后者会让每按一次 Enter 都重渲染整个窗口。代价是同一会话内列表在打开那一刻定格，这正是读者挑选时想要的快照。
3. **发送走同一条通道**：非 shell 会话会被同一条拒绝路径说明原因（`snippets.needsShell`），而不是把字节写到无处可去的地方。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `history.test.ts`（新增 1） | 三条记录（含同一文本两条）→ `recent()` 按最近排序、去重后为 `git diff`、`git status` |
| `paletteHistory.test.ts`（新增 2） | 两行历史的标签与提示正确、`keywords` 含 `history`、`run()` 以命令文本调用 `sendHistory`；没有历史时目录里没有 `history:` 行 |

## 四、边界

- 上限 40 行：面板是挑选面，不是历史浏览器；要看更早的，用行内补全或 `list_command_history` 的数据源。
- 历史关闭（设置里）时 `recent()` 为空，目录里就没有这些行——不需要额外的开关判断。
- 本轮未做「在面板里删除某条历史」：删除已有 `remove()` 与设置页的清空入口，面板删除需要单独的交互决定。
