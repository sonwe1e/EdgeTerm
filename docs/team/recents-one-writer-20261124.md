# 记住的主机现在只有一处来源（2026-11-24 第 94 轮）

第 91 轮把「最近连接过的目标」放在 App 的局部状态里，由命令行面板读写。第 93 轮给终端加了 `ssh://` 链接点击——那条路径在 `actions.ts` 里，拿不到 App 的 React 状态，于是「连过的机器」出现了两种命运：从面板连的会记住，从链接点开的不会。

## 一、交付：把列表移进 store

- `AppStore` 新字段 `quickConnectRecents: string[]`，初始值仍由 `loadRecentTargets()` 从已注册的键读入；
- 新动作 `rememberQuickTarget(label)`：去重前移、写存储、更新状态；面板与链接**都调用它**；
- `App` 不再自己持有状态，只读 store；`actions.ts` 的链接点击也调用同一个动作；
- 「恢复默认设置」把内存里的列表一并清空（键已由 `PANEL_PREFERENCE_KEYS` 删除），「导入设置」后从存储重新读入——两者都不会留下与磁盘不一致的旧值。

## 二、为什么不是加一个参数

两处入口分处 React 组件与普通模块，任何「传一份回调」的写法都要在两处各维护一份状态。放进 store 之后，列表只有一个写者、一个读者，第三个入口出现时也不必再改签名。
