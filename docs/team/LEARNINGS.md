# 缺陷与经验

- **已查源码：验收入口必须等于用户入口。** npm CLI 可以加载打包副本，而 SDK 或未打包入口读取另一个依赖模块。修补后者并通过其测试，不证明前者生效。本轮 Pi 旧验收存在此差异，已改用 `package.json` 的 `bin.pi`。
- **回归已复现：用户按键可发生双重动作。** Alt+方向键既切换标签又向原 Shell 写入序列；只看标签是否切换会误判通过。入口回归应同时检查副作用。
- **回归已复现：保留 UI 不代表保留连接授权。** 控制器为了历史而继续存在，延迟剪贴板读取和 OSC 52 临时允许却必须在连接结束时失效。待确认的弹窗也要一起清理。
- **方法边界：全绿只能说明现有用例通过。** 初始 925 项单元和 169 项浏览器通过，仍被新增时序及输入反例检出缺陷。不要通过修改预期、把旧入口当真实入口或把 jsdom 当原生环境制造通过。
- **真实浏览器回归已复现：hover 不只来自鼠标移动。** 键盘滚动把新行放到静止鼠标下方也会触发 mouseenter。快速打开必须验证“方向键选择 → 自动滚动 → Enter 打开的文件”这一完整路径，同时保留实际移动鼠标的控制用例。
- **固定缩放反例已复现：测试坐标也有单位。** CSS px、iframe 预览外层坐标和设备像素不能直接相加。列宽测试已有起点换算仍漏了距离换算。先固定缩放复现误差，再修正输入；不提高容差来掩盖误报。
- **反向验证已完成：** 7 种变异在隔离 worktree 中均被行为断言检出；正常控制先通过。首次被 Vite fs 限制拒绝导入不算测试检出，调整临时配置后才计结果。临时 worktree 已清理。
- **原生复现：关闭测试终端不能代替应用正常退出。** 旧 Pi 验收通过后直接关闭整个 Shell，遗漏了 Ctrl+D、`/quit`、两次 Ctrl+C 会主动回放历史的默认退出策略。新增验收要等子程序返回 Shell，检查退出后的字节和保存消息。
- **观测边界已核对：TUI 日志不含所有 stdout。** Pi 的恢复会话提示直接调用 `process.stdout.write()`，不在 TUI logger 中。判断回放来源可用 TUI 日志，判断终端最终收到的提示必须同时看 PTY 输出。最初只从 TUI 日志寻找恢复提示的断言已修正，保留首次结果作为证据。
- **候选疑点，不算缺陷：** 已检查连接取消/立即重试、编辑器读写期间输入等路径；只有得到可观察触发证据才能继续修复，不能把代码可疑直接升级为问题根因。
- **已复现：诊断入口会先于任务失效。** 受限主机拒绝 affinity 时，`./dev.ps1 doctor` 在打印任何内容前就退出，真正的工具缺失被这条错误掩盖。入口的预算必须允许降级，并如实报告降级状态。
- **已复现：计时器状态机在“没有目标”时仍然推进。** Sender 重复没有测试文件，一条 jsdom 用例就抓到 `times: 1` 虚报完成。给状态机补测试时，先问“这一步实际做了什么”，而不是“计数加一了没有”。
- **已复现：读路径的“适配”不能当成写路径的“真值”。** `loadPanelSizing` 为了显示把宽度缩到窗口内，App 又把缩后的值存回偏好；于是小窗口一次就把大屏布局永久改小。凡是“加载即适配”的设置，都要区分显示值与用户偏好。
- **方法：只读审计 + Lead 复核的边界。** 两个只读 agent 不能跑测试、不能改文件，报告里的“已排除疑点”同样有用（避免重复查），但每条修复仍要由 Lead 用可执行用例取证；审计者的结论不等于已验证。
- **观测边界：沙箱里的 EPERM 不是产品缺陷。** vitest、vite、cargo 需要给子进程开管道，受限沙箱会以 `spawn EPERM` 拒绝；格式化器给新文件写盘也可能报 `os error 5`（拒绝访问）。这是环境边界，不能记成测试失败，也不能用放宽断言绕过。
- **已复现：命令行 TLS 与 Node 的 TLS 不是一回事。** 同一台机器上，PowerShell/curl 走 Schannel 报 `SEC_E_NO_CREDENTIALS`，Tauri CLI 下载 NSIS 报 `Peer disconnected`，而 Node 的 `fetch` 能拿到 GitHub release；但整包仍被中断，需要 Range 分块 + 重试。工具链可以预置，预置时必须按上游源码里的 SHA-1 核对，不能只按文件名。
- **已复现：用秒级 mtime 判断“安装包是否来自本次构建”会误报。** bundler 先给 `edgeterm.exe` 打补丁再跑 makensis，两者落在同一秒；原判据让脚本拒绝了刚刚构建成功的安装包。改成 5 秒窗口，并把两个时间戳写进错误信息，便于人工判断。
- **方法：手工步骤写进脚本后，先用真实解压器还原一次。** 内存里的断言只能证明字节按自己的解析器可读；用 Windows `Expand-Archive` 还原、再比对 exe 哈希，才证明用户能打开这个包。
- **观测：包体积本身是发布承诺的一部分。** 便携包最初把 10 MiB 可执行文件原样存储，得到 10.3 MB，是历史发布（5.26 MB）的两倍；改成 deflate 后 5,212,734 B，回到同一量级。产物大小要和上一次发布比对，而不是只看“能生成”。
