# 缺陷与经验

## 2026-11-10：1.8.0 全面筛查

- **真实 Chrome 已复现并修复：有焦点不等于可见、可点。** 深层菜单能接收键盘焦点，却仍被父级滚动容器裁掉。测试需覆盖实际绘制命中、原始指针点击、末项滚动和字号变化，不能仅检查 focus 或依赖测试工具自动 scrollIntoView。
- **入口回归已复现：组合输入开始不等于提交。** 在 compositionstart 删除 Shell 选区会使取消候选也丢失输入；应等实际文字提交，重验连接世代与选区快照，再执行一次替换。合成事件通过仍不等于 Windows 原生输入法通过。
- **时序回归已复现：意图必须在第一个 await 前登记。** 打开文件的 cwd 解析、终端懒加载、关闭后的 watcher 注册都可能晚到。新意图或关闭应尽早使旧 owner 失效；这不意味着取消已交给独立传输队列的上传。
- **CI 方法：证据门自身也需要反例。** 未知 IPC、缺失截图场景和实际 Rust 生成失败必须使检查失败。二进制响应登记显式例外，不等于跳过余下类型生成一致性；环境阻塞、夹具缺失和真实产品缺陷要分别记录。

逐项旧失败／修复／复验与适用边界见 [全盘筛查记录](edge-term-1.8-full-audit.md)。以下为历史轮次的经验和当时的证据状态。

- **已查源码：验收入口必须等于用户入口。** npm CLI 可以加载打包副本，而 SDK 或未打包入口读取另一个依赖模块。修补后者并通过其测试，不证明前者生效。本轮 Pi 旧验收存在此差异，已改用 `package.json` 的 `bin.pi`。
- **回归已复现：用户按键可发生双重动作。** Alt+方向键既切换标签又向原 Shell 写入序列；只看标签是否切换会误判通过。入口回归应同时检查副作用。
- **回归已复现：保留 UI 不代表保留连接授权。** 控制器为了历史而继续存在，延迟剪贴板读取和 OSC 52 临时允许却必须在连接结束时失效。待确认的弹窗也要一起清理。
- **方法边界：全绿只能说明现有用例通过。** 初始 925 项单元和 169 项浏览器通过，仍被新增时序及输入反例检出缺陷。不要通过修改预期、把旧入口当真实入口或把 jsdom 当原生环境制造通过。
- **真实浏览器回归已复现：hover 不只来自鼠标移动。** 键盘滚动把新行放到静止鼠标下方也会触发 mouseenter。快速打开必须验证“方向键选择 → 自动滚动 → Enter 打开的文件”这一完整路径，同时保留实际移动鼠标的控制用例。
- **固定缩放反例已复现：测试坐标也有单位。** CSS px、iframe 预览外层坐标和设备像素不能直接相加。列宽测试已有起点换算仍漏了距离换算。先固定缩放复现误差，再修正输入；不提高容差来掩盖误报。
- **反向验证已完成：** 7 种变异在隔离 worktree 中均被行为断言检出；正常控制先通过。首次被 Vite fs 限制拒绝导入不算测试检出，调整临时配置后才计结果。临时 worktree 已清理。
- **原生复现：关闭测试终端不能代替应用正常退出。** 旧 Pi 验收通过后直接关闭整个 Shell，遗漏了 Ctrl+D、`/quit`、两次 Ctrl+C 会主动回放历史的默认退出策略。新增验收要等子程序返回 Shell，检查退出后的字节和保存消息。
- **观测边界已核对：TUI 日志不含所有 stdout。** Pi 的恢复会话提示直接调用 `process.stdout.write()`，不在 TUI logger 中。判断回放来源可用 TUI 日志，判断终端最终收到的提示必须同时看 PTY 输出。最初只从 TUI 日志寻找恢复提示的断言已修正，保留首次结果作为证据。
- **候选疑点，不算缺陷：** 已检查连接取消/立即重试、编辑器读写期间输入等路径；只有得到可观察触发证据才能继续修复，不能把代码可疑直接升级为问题根因。
- **已复现：诊断入口会先于任务失效。** 受限主机拒绝 affinity 时，`./dev.ps1 doctor` 在打印任何内容前就退出，真正的工具缺失被这条错误掩盖。入口的预算必须允许降级，并如实报告降级状态。
- **已复现：计时器状态机在“没有目标”时仍然推进。** Sender 重复没有测试文件，一条 jsdom 用例就抓到 `times: 1` 虚报完成。给状态机补测试时，先问“这一步实际做了什么”，而不是“计数加一了没有”。
- **已复现：读路径的“适配”不能当成写路径的“真值”。** `loadPanelSizing` 为了显示把宽度缩到窗口内，App 又把缩后的值存回偏好；于是小窗口一次就把大屏布局永久改小。凡是“加载即适配”的设置，都要区分显示值与用户偏好。
- **方法：只读审计 + Lead 复核的边界。** 两个只读 agent 不能跑测试、不能改文件，报告里的“已排除疑点”同样有用（避免重复查），但每条修复仍要由 Lead 用可执行用例取证；审计者的结论不等于已验证。
- **观测边界：沙箱里的 EPERM 不是产品缺陷。** vitest、vite、cargo 需要给子进程开管道，受限沙箱会以 `spawn EPERM` 拒绝；格式化器给新文件写盘也可能报 `os error 5`（拒绝访问）。这是环境边界，不能记成测试失败，也不能用放宽断言绕过。
- **已复现：命令行 TLS 与 Node 的 TLS 不是一回事。** 同一台机器上，PowerShell/curl 走 Schannel 报 `SEC_E_NO_CREDENTIALS`，Tauri CLI 下载 NSIS 报 `Peer disconnected`，而 Node 的 `fetch` 能拿到 GitHub release；但整包仍被中断，需要 Range 分块 + 重试。工具链可以预置，预置时必须按上游源码里的 SHA-1 核对，不能只按文件名。
- **已复现：用秒级 mtime 判断“安装包是否来自本次构建”会误报。** bundler 先给 `edgeterm.exe` 打补丁再跑 makensis，两者落在同一秒；原判据让脚本拒绝了刚刚构建成功的安装包。改成 5 秒窗口，并把两个时间戳写进错误信息，便于人工判断。
- **方法：手工步骤写进脚本后，先用真实解压器还原一次。** 内存里的断言只能证明字节按自己的解析器可读；用 Windows `Expand-Archive` 还原、再比对 exe 哈希，才证明用户能打开这个包。
- **观测：包体积本身是发布承诺的一部分。** 便携包最初把 10 MiB 可执行文件原样存储，得到 10.3 MB，是历史发布（5.26 MB）的两倍；改成 deflate 后 5,212,734 B，回到同一量级。产物大小要和上一次发布比对，而不是只看“能生成”。
- **已复现：依赖错误信息里的 NUL 会误导定位。** portable-pty 打印的是 NUL 结尾的命令行与工作目录缓冲区，`\0` 只是打印产物；真正的错误是 os error 2 —— shell 路径带空格且未加引号，被按命令行动词切成两段。读依赖的错误文本时，先分清“打印格式”和“实际参数”。
- **已复现：用户输入形态比字段语义更容易出错。** 字段文档写的是“命令行”，但用户和 shell 选择器会直接粘贴路径。对“程序 + 参数”的字段，应容忍“整串就是一个存在的文件”这种形态。
33. **方法：没有图像输入时，可视质量用"真实渲染的 DOM 测量 + 负向控制"接管。** 截图只能当交付物，不能当判据：本轮的对比度、命中区、截断全部由 Chromium 实测得出，且必须能在注入旧样式后重新报错。测量器本身也要先校准——`sr-only` 文本与 11px 的 sash 伪元素命中区曾让首版报告多出 8 条假缺陷。
34. **已复现：缩放动画作用在交互目标上会改变命中区。** 面板行内按钮为了渐显加了 `transform: scale(0.9)`，按钮 24px 的盒子在静止态实测 21.6px；改为只缩放字形后，目标恒定 24px 且动画保留。凡是"出现/消失"的动画，缩放对象应是内容而不是可点区域。
35. **已复现：拥挤的 flex 行会把声明尺寸压小。** `.panel-action` 声明 24px，实测 21.6px——不是 `--h-control` 写错，而是同一行的收紧；图标按钮需要 `flex: none` 才能让声明尺寸成为真实目标。断言"声明了多大"没有意义，要断言 `getBoundingClientRect()`。
36. **已复现：重复的 React key 是真实缺陷信号，不是噪音。** 命令面板起初按"相邻同组"分组，同一分组在目录里出现三次，控制台报重复 key，过滤后旧行残留在 DOM——页脚写 2 条、屏幕上有 11 条。分组应按分组 id 聚合，并让"扁平顺序"成为方向键、aria 与计数的唯一来源。
37. **已复现：对比度审计必须覆盖叠加状态，而不只是基础表面。** 选中行给提示与键帽加 `opacity: .82`，白字压主题蓝降到 4.37:1；serialx-dark 的键帽用 `--fg-dim` 压在自己的 `--bg-track` 上只有 3.76:1。token 在"自己的画布"达标不等于在"选中/键帽/提示"这些叠加表面上达标；四套主题都要跑一遍。
38. **已复现：受控对话框关闭后内容仍在 DOM 里。** `ModalDialog` 关闭时只是 `dialog.close()`，子元素照常挂载；用"元素是否存在"判断关闭会假失败。断言关闭要读 `dialog.open`。
39. **方法：原始 CDP 键鼠事件发给外层页面，不发给测试 iframe。** 键盘必须走 runner 的 `userEvent.keyboard`（帧作用域）；坐标类指针输入才用 CDP + `pagePoint` 的换算。混淆两者会把"快捷键没生效"误判成产品缺陷。
40. **已校准：`backdrop-filter` 不应让文字对比度变成"不可判定"。** 它只模糊元素背后的内容，元素自身背景仍决定文字对比；只有作用于元素自身（含文字）的 `filter` 才需要标记为不可判定。首版审计把整个毛玻璃菜单判为不可测，等于放过了一个真实缺陷。
41. **已复现：程序化聚焦只在真实键盘模态后匹配 `:focus-visible`。** 没有先发一次 Tab 时，脚本聚焦的按钮在 Chromium 里不匹配 `:focus-visible`，焦点扫查会误报一屏"无焦点样式"。
42. **已复现：焦点环的过渡会让同步快照读到中间值。** 同一颜色在过渡中序列化成 `oklab(...)`，与终态 `color(srgb ...)` 字符串不等，于是"有环"被读成"无变化"。扫查期间冻结过渡再比较。
43. **已复现：roving tabindex 的行不是焦点停靠点。** `aria-activedescendant` 列表里行是 `tabIndex=-1`，给 `div.row` 加 `:focus-visible` 是死规则；判断停靠点要看 `tabIndex>=0` 且 `focus()` 后 `activeElement` 命中。
44. **方法：负向控制要针对"这一条规则"，不是针对整个页面。** 中和菜单的焦点样式验证菜单项被报出；中和复选框的环验证复选框被报出——两条控制分别证明收集器对两类控件都有效。
45. **设计约束：高爆炸半径模式的开关必须常驻可见、可一键关闭、且不跨重启恢复。** 同步输入本轮按此设计：无接收方拒绝开启、状态栏指示即关闭按钮、关标签/断线后自动关闭、绝不持久化。
46. **已复现：xterm 的协议应答与键入同走 `onData`。** 不排除 DA/DSR/CPR/XTVERSION/DCS，同步输入会把一个面板对查询的应答写进所有其它 shell；固定形态精确匹配可排除它们，而方向键（`\x1b[A`）不会被误判——测试同时钉住两侧。
47. **观测：模块级 translator 读的是 store 发布过的语言。** 浏览器测试里直接 `setState({language})` 不会更新它，状态文案会停在上一轮的语言；必须调用 `setLanguage`。
48. **已复现：命令面板与新对话框之间的空窗。** 面板本身是 dialog，Enter 后面板先卸载、目标对话框再挂载；在空窗里查询 `dialog[open]` 会拿到 null。审计要等"面板输入框消失且对话框出现"。
49. **观测：store 的 `language` 字段不驱动 `useT`。** 把 `language` 写进 `setState` 只改状态字段，菜单仍显示旧语言；必须在状态重置之后调用 `setLanguage`。
50. **方法：测量门禁要断言 inspected 下限。** 空树、选错根节点、元素被隐藏都会让三个收集器返回空数组——"0 issues" 只有在有观测数量时才是结论。
51. **已复现：jsdom 不展开 `outline` 简写。** 收集器的单元测试若写 `style.outline = "2px solid #000"`，`outlineStyle/Width` 读出来不是期望值，收集器会当成"没有 outline"；测试要分别写 `outlineWidth/Style/Color`。
52. **设计观察：焦点环的"存在"与"可见"是两件事。** 环与表面同色时所有属性都变、对比度是 1:1；验收必须测颜色，负向控制也要用"环 = 表面色"才有意义。
53. **实现注意：环的背景取决于 offset 的符号。** 负 offset（内嵌）贴在元素自身表面，正 offset 贴在父级表面；选错背景会把可读的环判成缺陷，或反之。
54. **已复现：xterm `selectLines(start, end)` 是闭区间对，不是 (start, length)。** 单行内容时两种理解恰好等价，测试不会失败；两行输出立刻暴露（复制到空行）。任何"复制一段行"的功能都要用多行用例验证。
55. **实现：命令区间必须用 marker，不能用行号。** 回滚裁剪与历史前置都会移动内容，行号会静默指向别的行；marker 被裁剪时能报告 `isDisposed`，据此拒绝复制。
56. **交互：命令面板中有共同前缀的两条命令要让标签本身可区分。** "Copy Last Command" 与 "…Output" 对同一查询并列匹配，Enter 命中取决于排序；改名（…Line）比调排序可靠。
57. **已复现：同时存在的装饰器会让查询读到旧实例。** 连续两次跳转各留一个底纹时，`querySelector(".command-jump")` 命中旧元素，测试判定落点错误；界面上也真的出现两个高亮。"同一时刻只有一个"既是测试可判定性，也是正确的视觉状态。
58. **观测：`scrollToLine` 的落点不等于目标行。** 目标已可见时不滚动，落在最后一屏时贴底；验收要断言"目标在视口内"，落点行用渲染位置反推，不要直接比较 `viewportY`。
59. **交互：走查式导航的参照点必须是"上次落点"。** 以光标为参照，连按两次会回到同一行；以落点为参照，才能像编辑器"上一个匹配"一样逐步后退。
60. **性能：逐行查询"是不是命令"会把集合构造放大到每帧每行。** 在绘制开始时读一次 `ReadonlySet`，行级只做 `has`；空状态用共享常量集合，避免抑制路径上每帧分配。
61. **依赖：行号栏的重绘键不含"新增命令"。** 标记能及时出现是因为命令结束时必然写入新提示符（改变内容末尾）；任何"命令结束后不写内容"的场景，标记会等到下一次滚动或写入。
62. **验证：行高类设置要与"渲染出的单元格高度"比较，而不是容器高度 / 行数。** fit 会取整，两者长期相差 0.5–0.6px；用 `.xterm-rows > div` 的高度做基准，行号栏单元格才能可靠对齐。
63. **实现：新的显示设置必须走字号那条"隐藏时暂存、显示时落地"的路径。** 直接在 `display:none` 的面板上改选项会让 WebKit 留下旧渲染，和字号当初遇到的问题一样。
64. **清单：新偏好要同时进入 reset／export／apply／测试替身四条路径。** 本轮漏掉重置与导出时，`storePreferences.reset` 直接失败；漏掉控制器替身时，12 条焦点用例报 `setLineHeight is not a function`——不是功能坏，是接线没铺满。
65. **交互：排序提示不能只靠小图标。** 增加一条 2px 下划线时，所有标题都要预留 2px 透明边框，否则切换排序列会让文字上下跳 2px。
66. **布局：拉伸到整行的按钮绑定的是"容器内容盒"。** 24px 行高 + 1px 底部边框，内容盒只有 23px；差 1px 就掉出 24×24 目标，行高要按内容盒反算（25px）。
67. **风险：CSS 令牌与 JS 虚拟化器是两份数值。** 它们必须互相注明，且验收用独立推导的期望值；只读令牌自证会让"两边一起错"通过。
68. **覆盖：弹层要测"有内容"的态。** 空弹层只剩标题，门禁全绿也不说明任何行内控件合格；本轮先断言任务名/主机名出现，再跑收集器。
69. **尺寸：22px 的 `--h-control-sm` 不适合关闭/揭示类按钮。** 标题栏和整行揭示都有空间，24×24 才是这些"随时会点"的控件应有的尺寸。
70. **实现：零内边距的整行按钮高度等于行盒。** 14px 的行盒让"选择远程端口"成了 14px 目标；`min-height: 24px` 修好目标又不破坏安静外观。
71. **已复现：计数来自另一个函数就会不同步。** 排除项接进写入路径、却漏了状态栏与自动关闭判断时，弹层显示 1 台、指示写 2 台；把三处收敛到同一个过滤函数才一致。
72. **联动：描述某个模式的弹层必须随模式关闭。** 否则弹层还在，而它描述的模式已经不存在了。
73. **语义：排除项按会话 id 存、运行期保留。** 关闭再开启不应把用户上次排除的机器静默拉回；断线重连的会话按默认（包含）处理。
74. **同一命令两处定义必然分叉。** 命令面板里手写的复制条目与快捷键表各有一份标签与动作；并入表后只有一份来源，菜单/面板/对话框显示同一个和弦。
75. **和弦验收要同时看两侧。** 只断言"剪贴板拿到了内容"会放过"把控制字符写进会话"的实现；记录型 IPC 断言 `write_session` 为空才算证明和弦被应用层吃掉。
76. **流程：改完接线要重跑 lint，不只看 typecheck。** 本轮把新动作接进 `runShortcut` 后 typecheck 通过、lint 却报缺少 hook 依赖；把 `copyFromTerminal` 加进依赖数组才干净。lint 抓的是 typecheck 看不到的规则。
77. **CSSOM 里 `var()` 不展开。** 只读 `transition-duration` 时，用令牌的规则返回空串；门禁会只看到少数规则然后"全绿"——空转。要读 `transition` 短属性本身。
78. **序列化会丢默认值。** `color 200ms ease` 在 CSSOM 里是 `color 200ms`；断言必须用规范化后的文本，否则负向对照自己就假失败。
79. **机械替换要按声明边界走。** 按"冒号前是属性名"解析会被注释里的冒号带偏，漏掉多行声明；行状态机（遇 `transition:` 开、遇 `;` 关）才完整。
80. **动画不是状态。** 菜单/对话框/旋转的时长属于效果，收敛它们会破坏场景；门禁只约束过渡，边界写进测试与令牌注释。
81. **已复现：字符级重写会吃掉注释。** 把"冒号前当属性名"的脚本用在 CSS 上，注释被当作声明重写：小写化、截断、粘到代码行尾，两个文件直接无法解析。机械改源码要用行/声明级替换，并事后校验注释与花括号。
82. **恢复要回滚重建，不是修补。** 结构损坏后继续打补丁会留下孤立片段；从 `HEAD` 重建再按记录重放本轮改动，才是可验证的路径。重建后必须跑全量契约。
83. **注释也能当证据。** 用"去空白、转小写"的规范化键与 `HEAD` 比对，能自动找出被改写但语义相同的注释（本轮 170 处），比肉眼检查可靠。
84. **文案也是契约。** 界面写着“Ctrl+S to save”，就必须有测试真的按一次并断言写入；会撒谎的提示比没有提示更糟。
85. **破坏性操作要测“拒绝”分支。** 只验证“同意后关闭”证明不了保护存在；拒绝后缓冲与对话框都还在，才是保护。
86. **下限要按真实控件数。** 编辑器 chrome 只有两个按钮，最初写“读到 >2 个目标”是我的断言错，不是产品缺陷；下限设错会让覆盖看起来像失败。
87. **重开不等于复活。** 已关闭标签的控制器与连接都已退役，沿用旧 id 会与关闭记账打架；正确做法是同 profile、新 id、新连接。
88. **安全网要有上限，也要有话说。** 栈保留最近 10 条即可；没有可重开的会话时写一句状态栏，静默无反应会让用户以为快捷键没生效。
89. **测试要等副作用，不要等信号。** 新标签在连接请求发出前就已入列——断言 open_session 必须等那次调用发生，而不是等标签数变化。
90. **Enter 和弦到不了应用层。** 终端的键盘处理先把 Enter 当输入转发，matchAppShortcut 根本没机会看到；需要 Enter 类快捷键时要先确认它的实际路径。
91. **缩放是视图状态，不是布局改动。** 只记哪块被放大，布局树不动，还原时分割比例天然一致。
92. **隐藏不等于卸载。** xterm 的滚动缓冲在它的 DOM 元素里；用 display none 隐藏，别把会话从渲染树里移除。
93. **门禁要喂能画出内容的数据。** 资源弹层空态只剩标题；喂了 GPU/NPU 采样后，才真正在测设备行。
94. **测试文件也要过 typecheck。** 本轮留下一个未使用的 `trigger` 变量，typecheck 与 build 都因此失败（浏览器运行本身不受影响）——先把 `expect.poll` 的返回值丢掉再跑。
95. **面板选择器别猜。** 发送面板的根节点是 PanelDocks 挂的 data-panel 属性，不是我自己命名的类名；先查渲染代码再写选择器。
96. **同一视觉形状要有同一行为。** 停靠区与分屏的拖动条长得一样，双击却只有前者生效；这类不一致用户会当成 bug。
97. **只动被点的边界。** 均分重置保持总量、其余节点返回同一引用，既符合直觉，也避免整棵树重渲染。
98. **缩放不要造第二份状态。** 和弦直接改显示设置里的偏好，对话框、导入导出与和弦自然一致；另建一个 zoom 值迟早会和偏好打架。
99. **报告钳制后的值。** 到顶后继续按，状态栏说 8px 比说 7px（没生效）诚实得多。
100. **负向对照要能证明“没做多余的事”。** 普通滚轮那条断言检查的是“没有被 preventDefault”；一个无差别拦截滚轮的实现会在这一步失败。
101. **组件 effect 里触摸控制器成员要留一条“还没到”的路。** `terminal?.term.element` 在 mock 没有 term 时抛错，一次性让 12 个 jsdom 用例失败；写成 `terminal?.term?.element` 并在注释里说明这是 xterm 尚未加载的正常状态。
102. **滚轮监听必须是非被动。** passive 监听里 preventDefault 无效，浏览器会照旧缩放整页；attach 时显式 { passive: false }。
103. **把“批量”的重活抽成纯函数。** Close Others 的过滤写成 closeOthersTargets 后，菜单与单测用的是同一份规则，不会再出现 UI 与测试各写一遍。
104. **顺序即数组时，固定就移动元素。** 不引入第二套排序，拖拽重排的索引语义保持原样。
105. **“在底部”不只由滚动改变。** 只监听 onScroll 会漏掉“输出把 baseY 推远”的情形；onWriteParsed 也要通知。
106. **浮层入口要吞 mousedown。** 否则点击时焦点先离开终端，用户回到终端还要再点一次。
107. **桩不完整该补桩，不是让生产代码判空。** 第 22 轮在组件里加可选链绕过了不完整的 mock；这次选择把 isAtBottom/onScrollState 补进桩并写明它“永不滚动”，生产代码保持诚实。
108. **新增一个不变量，就检查所有会移动它的入口。** 固定引入「最前」的顺序承诺，而拖拽是另一条能改顺序的入口——当轮就该一起守。
109. **落点标记要和落点用同一个函数。** 否则标记先画在固定区里，松手后标签却跳到区外，看起来像“没放准”。
110. **钳制边界要保留“末尾之后”的位置。** 把上限写成 n-1 会让“移到最后一个位置”变成差一位；既有 moveTab 用例抓到了——说明全量单测不是仪式。
111. **自动聚焦永远让位于正在输入的字段。** rAF 里调用 focus() 会在用户已经开始打字后生效；不检查 activeElement 就会把输入吃掉一半。
112. **指针捕获会让 dblclick 不可靠。** 条带为拖拽捕获了指针，浏览器合成的双击可能落到捕获元素上；用两次按下加时间窗自己识别。
113. **起名就该取代歧义后缀。** 用户给标签起名的动机是不再猜序号；保留后缀反而是噪音。
114. **中文输入法下 Enter 是选词，不是提交。** 就地编辑器必须检查 isComposing；否则用户选完候选词，记录的是拼音。
115. **就地编辑默认全选。** 打开就全选，第一次输入才是替换；否则用户得到「旧名新字」的拼接。
116. **提交后要给焦点一个去处。** blur() 之后如果不重新聚焦，焦点落到 body，后续按键全部丢失。
117. **自定义名与派生名相同时要视为清除。** 否则 F2 后直接 Enter 就把「跟随会话名」冻结成一个快照。
118. **改标题要改所有读标题的地方。** 面板最初直接读 info.name，改名后搜索不到；统一走 tabTitle 才能一致。
119. **持久化字段要按需写入。** 只有命名标签才写 title，未命名标签的载荷与从前逐字相同——快照 diff 因此不会因新字段整体抖动。
120. **工作区文件是手改输入。** 恢复路径上的每个字符串都要过校验（空白、控制字符、长度），不能因为“是我们自己写的”就信任。
121. **F2 不该被全局拦截。** 终端程序（mc、vim 映射、TUI）靠 F2 的转义序列工作；把它做成全局快捷键会静默打断这些程序。
122. **焦点归属要顺应应用自己的意图。** 应用把「激活标签」定义为聚焦终端；若重命名提交后硬把焦点留在标签上，就会和第 22 轮那条自动聚焦规则打架。
123. **浏览器用例之间共享 localStorage。** 一个用例写下的工作区会被下一个用例的 App 恢复出额外终端，其挂载聚焦会干扰断言；就地清理比放宽断言诚实。
124. **不知道就不要说成功。** 没有退出码时保持安静，比默认报 0 更诚实，也更容易在测试里被证明。
125. **协议里已有的信息常被解析器丢掉。** OSC 133 D 一直在被消费，只是 status 被省略；接功能前先看现有 handler 拿到过什么。
126. **跨回调的状态要显式清空。** 退出码在 D 到达时暂存、命令闭合时消费；不清理就会把上一条的失败算到下一条头上。
127. **两条完成路径必须收敛到一处登记。** 标记只在提示符匹配路径登记，导致 OSC 133 的 shell 侧栏完全没有命令边界；把登记移进 finishCommand 一次解决。
128. **失败用既有标记的颜色表达。** 再加一种标记会让同一行出现两个边界，读起来像两条命令。
129. **并行数组要一起增删。** commandExits 与 commandStarts 同 push、同 shift，否则失败会标到别的命令行上。
130. **两个相似的导航抽成一个函数。** 命令跳转与失败跳转只在「行集合」上不同；复制一份走查逻辑迟早会在参考行或落点记忆上分叉。
131. **没有默认和弦不等于没有入口。** 快捷键表是菜单与命令面板的唯一数据源，null 绑定的命令照样出现在两处。
132. **选择器没确认就不要写断言。** 浏览器用例里猜 `.palette input` 失败后，撤回该用例比留下一条随实现漂移的断言更诚实。
133. **交付物要能启动，才算交付。** 安装包没法装时，至少直接启动它包裹的二进制并观察存活/响应/窗口标题；这比只报告“构建成功”多证明了最关键的一件事。
134. **界面用例里的语言要显式固定，而且在状态展开之后。** `setState({...initial})` 会把语言带回初始值；先固定再展开等于没固定。
135. **找不到元素时先打印真实 DOM，而不是继续猜选择器。** 两次猜测失败后打印 `.command-palette-*` 的数量与标签，一次就定位到问题是语言而不是选择器。
136. **测量模态框要等它自己拿到焦点。** 打开即测量，可能在入场过渡中读到没有焦点环；等到 modal 内部有 activeElement 再量，抖动消失。
137. **冻结动效要包住整段测量，不只是扫描。** 只在扫描处冻结，前面的可读性采集仍可能读到淡入中的颜色。
138. **一次抖动不能靠重跑收尾。** 单独重跑 3 次确认稳定，再把怀疑的时序原因显式加固，才算处理完。
139. **一次 mount 只对应一棵树。** 为切主题重复 mount 会留下第二棵 App，状态项各开各的弹层，断言查到的与点击的不一定是同一棵。切主题改状态即可。
140. **条件渲染的表单不能假设它存在。** 隧道表单要有活会话才渲染；断言应写成「面板有内容」+「若存在输入框则必须有可访问名」，而不是断言字段数量。
141. **全量日志要落盘。** 输出截断会让偶发失败的测试名消失；把完整日志写进 `.tmp/`，失败时才有据可查。
142. **夹具里的宿主数据要在挂载后再写。** loadGroups/loadProfiles 会用宿主返回覆盖 store，挂载前写死的分组会被清空。
143. **先读 helper 的返回类型再断言。** written(id) 返回拼接字符串，用 toEqual([]) 断言空值只会得到一个奇怪的 diff。
144. **破坏性功能的排除表要能叠加。** 组排除与逐会话排除各管一层，互不覆盖，才能既快又准。
145. **先核对再建设。** 积压项「关键字高亮/命中索引」的查找侧早已完备，真正缺的是滚过去之后的可见性。
146. **绝对行号的辅助索引要在裁剪处清理。** 否则它随会话历史无限增长；挂在 dropLeadingLines 上最省事也最准确。
147. **行级缓存要加新字段，不要复用旧字段。** rowPaint 的 watch 用 undefined 表示未写过，与 null（确定无标记）区分，避免首帧漏画。
148. **jsdom 里短缓冲区不会滚动。** 内容不足一屏时 scrollToLine 被夹到 0，viewportY 恒为 0；断言应改成「落点在可见范围内」，并用超过一屏的内容让滚动真的发生。
149. **新回调必须同时进依赖数组。** App 的快捷键分发器依赖数组漏掉 jumpWatch，typecheck 通过、lint 报错——这类错误只有 lint 抓得住。
150. **复用走查函数时，落点语义要先想清楚。** 共享落点让「上一个」始终相对当前视线，是比各记一份更好的选择。
151. **没有数据的指标不要起指标的名字。** 输入回显延迟可以测准；网络 RTT 在后端没有计时、环境没有服务器时只能编。名字要跟着可验证的事实走。
152. **过期读数要主动撤下。** 订阅者在样本落地时刷新，还要在新鲜窗口结束时再刷新一次，否则旧数字会一直挂在状态栏。
153. **`useSyncExternalStore` 的快照返回字符串最省心。** 每次调用返回新对象的 getter 会让 React 比较永远不相等；返回格式化后的字符串既稳定又便宜。
154. **多入口的同一动作，抽成模块函数。** 回调复制三份时，其中一份（菜单）悄悄少了「走空提示」，用户看到的是「点了没反应」。
155. **回归测试要挑旧实现必然失败的路径。** 新加的菜单用例如果跑在旧代码上会因静默而失败，这才叫回归用例。
156. **静默的协议信号要查一遍。** BEL 从第一个终端就存在，前端却没有 onBell 处理——这类空白在功能清单里找不到，只能靠读代码发现。
157. **新的未读状态挂在既有确认路径上。** 完成与响铃都通过 acknowledgeTab 清除，选标签这一动作对用户只有一种含义。
158. **store 切片的方法要同时登记三处。** AppStore 类型、slice 的 Pick 列表、实现体——漏掉 Pick 会在实现体里变成隐式 any。
159. **协议信号成对排查。** 上一轮查了 BEL，这一轮才发现同一层的 OSC 0/2 也没处理：排查一类空白时要把它整层的兄弟信号都过一遍。
160. **瞬态说辞不要写进长期命名。** 程序标题会随 `vim` 退出而变；标签名是用户的，两者用途不同，位置也该不同。
161. **未复现的失败要保留“未定位”三个字。** 重跑全绿不等于修好；日志法只是让下一次能说出名字。
162. **会话生命周期的临时数据要在重连时清。** 标题、cwd、资源统计都属于「这一次连接」，不清就会把上一个程序的身份带到新 shell 上。
163. **排查任务在跑时不要启动受管理的测试。** 运行器一次只允许一个任务，白等一次调用。
164. **五次全量都不复现，就写「未定位」。** 取证成本可以付，结论不能编。
165. **新加的指示要跟着会话生命周期走。** 标题、铃铛都是「这一次连接」的事实；状态机换了，显示条件也要跟着换。
166. **回归用例先构造成因。** 直接设 `state: "closed"` 只证明渲染分支，真实写入 OSC 再关闭才证明整条链路。两条都写，各证一层。
167. **迟到的 rAF 是抢焦点的常见来源。** 记录调度时的 activeElement，帧里发现变了就放弃，比事后到处加守卫可靠。
168. **「按键没反应」先看焦点在哪。** F2、方向键这类由元素自己处理的键，静默失效往往不是键位问题，是焦点被别的组件拿走了。
169. **落盘日志第一次真正兑现。** 前几轮的未复现失败没名字；本轮同一机制第二次出现时，日志直接给出文件名、行号与截图路径。
170. **片段发送不要另开写入路径。** 复用输入漏斗，同步输入和连接中缓冲等规则自动继续成立。
171. **面板条目要按自身文字可搜。** 片段的关键词包含名称、命令原文和 `snippet`，中英文界面都能用英文词命中。
172. **夹具驱动不了的状态，就换成拒绝路径。** 用不稳定的类合成 OSC 去「制造」已提交命令，只会得到一个时好时坏的绿灯。
173. **同一功能的编辑只留一处。** 面板做发送、弹层做增删，是刻意的分工而不是遗漏。
174. **Vitest 吞掉 console 时用哨兵断言。** 把期望写成不可能命中的字符串，失败差异里就有真实值。
175. **命令跟踪器的开始只能有一次。** 已运行时到达的 OSC 133 C 被忽略；夹具必须先 `noteCommandSent` 再让 shell 宣布开始。
176. **「夹具驱动不了」要先证伪。** 一个两分钟的探针比一句放弃的结论便宜得多。
177. **模板分隔符要与宿主语言错开。** `${}` 和 `{}` 都已被 shell/awk 占用，`{{}}` 才是安全的。
178. **参数不全会拒绝发送。** 少一个参数的部署命令比一条没发出的命令更危险。
179. **生成测试文本时别用模板字符串。** 里面写 `${HOME}` 会被当前脚本插值；用字符串数组拼更稳。
180. **样式类不是身份。** 编辑与删除共用类名后，`querySelector(".snippets-delete")` 取到的是第一个——按 aria-label 定位才对应用例的意图。
181. **验证结论看退出码，不看截断的尾部。** 本轮 format:check 实际失败，尾部两行恰好是空行；是 `EXIT=1` 暴露了它。
182. **原地编辑要保住 id。** 改名换命令都不应改变身份，否则面板与菜单里的同一条命令会变成两条历史。
183. **互相依赖的界面归同一个功能。** 三个对话框要一起出现时，让它们和逻辑住在一起，App 才会停止变长。
184. **重构的证据是既有用例全绿，而不是新写的用例。** 行为没变，就不该需要新的断言。
185. **动手前先查后端与绑定。** 本轮原计划做会话日志，查 `#[tauri::command]` 时发现录制早已存在（含失败事件与对话框勾选）。
186. **半途换方向不是浪费，重复实现才是。** 发现已有能力后立刻改做真正缺的搬运入口，比按原计划硬写一套并行录制更省时间。
187. **整包拒绝好过部分导入。** 部分恢复看起来像成功，读者却不知道少了什么。
188. **版本号是用户的决定，不是流程的自然结果。** 功能攒够了也不等于可以升 minor。
189. **取消构建要在改版本之前。** 先 kill 正在进行的长任务，再改版本文件，避免产物与版本号对不上。
190. **整体覆盖前先核对行数。** `read` 可能只返回文件的一部分；`lines.length` 与 `totalLines` 不一致就是信号。
191. **构建产物能救源码。** `dist/` 里编好的语言包在事故后恢复了 1463 条文案。
192. **正则提取要覆盖引号样式。** 英文值含双引号时，打包器用单引号字面量；只匹配双引号会漏掉，并从另一种语言补错值。
193. **中键是关闭，不是选择。** 它必须与关闭按钮同一路径（含确认），而不是绕过确认直接杀会话。
194. **夹具先让渲染发生。** 影响渲染的状态（右键模式）改完要等一帧，否则处理器闭包仍是旧值。
195. **浏览器测试不查类型。** `setRightClickAction("contextMenu")` 运行时照跑、菜单照开，只有 typecheck 抓到字面量是 `menu`。
196. **同一动作的多个入口共用一个执行器。** 登记表比重写判断便宜，也比三条路径各自演化安全。
197. **延迟比识别更可靠。** 等 shell 提示符要认提示符，认错就永远不发；一段可解释的固定延迟更稳。
198. **迟到的定时器要复查状态。** 400 ms 内标签可能已经关掉，发送前再查一次「仍在且已连接」。
199. **用户已经打了字，脚本就让位。** 登录命令是起点，不是插队者。
200. **IPC 夹具的参数名要照着 api 层抄。** `open_session` 用的是 `sessionId`，写 `id` 会让标签 id 变成 `undefined`、状态永远停在 connecting。
201. **加偏好第二步是登记。** 不登记就没有导出、导入、恢复——而且不会有任何报错告诉你。
202. **既是存储又是状态的偏好，导入/恢复要管两层。** 只删键留下幽灵数据，只写键要等重启。
203. **偶发失败先测量再动手。** 单文件 8 次全绿、只在全量出现，说明它与负载时序有关，不能按稳定复现来修。
204. **让测试变绿的修法，先问它是否改变了产品。** 守卫让全量两次全绿，却让 5 条单测红：那不是修好，是掩盖。
205. **用例制造的状态不是读者会走到的路径。** F2 之前键盘必须在标签栏；跳过这一步是在测一个不存在的场景。
206. **用行数找热点，用有无测试找缺口。** 最大的文件不是最脆的；最大且零测试的才是。
207. **测试写错比代码写错更常见。** 与实现冲突时先读实现：它往往带着一条我没读到的理由。
208. **不变量比逐条颜色更值钱。** 单调、界内、条数上限，任何一条规则改动都逃不掉。
209. **搬动配测试，才是可回退的整理。** 30 行变 5 行之前，19 条断言先把行为钉死。
210. **没有 id 的输入先存草稿。** 「没有归属」不该变成「不给输入」；归属推迟到保存那一刻即可。
211. **每敲一个字都写盘，是在用存储当状态。** 本地草稿 + 一次提交更安静，也避免取消后留下半条数据。
212. **组件 props 的「可选」要按类型走。** `initial` 是 `SessionProfile | null`；浏览器测试照跑，typecheck 才知道。
213. **Tab 顺序不是列表导航。** 元素一多，逐项 Tab 的成本随数量线性上升；方向键才是走列表的键。
214. **借用按键前先确认它在当前焦点上没有含义。** 按钮上的 Backspace 没有文本含义，才敢当删除用。
215. **测试里断言「删除不是发送」** 比只断言数量更值钱：它防的是键位落到错误的处理器上。
216. **入口要放在读者的手边，不是放在功能自己的家里。** 命令库的保存，读者想到它时手在终端上。
217. **`useCallback` 的值不提升。** effect 引用了它，就必须写在它之后；`TS2448` 是这条规则在报信。
218. **注册式回调要允许没有注册者。** 界面先到、能力后到时，空操作比异常诚实。
219. **「照这条改一条」是复制，不是新建。** 缺这一步时，读者被迫重打一条曾经跑通的命令。
220. **复制必须绕开源的名字。** 名字若同时是替换键，覆盖源就是最坏的意外。
221. **追加测试别用正则找 import。** 格式化后的多行 import 会让单行匹配为 null；先读再按当前结构 edit。
222. **重 fill 的答案，是读者最少的工作量。** 但要分清哪些值属于「这次」，哪些属于「这条命令」。
223. **临时上下文不进设置。** 设置会被导出、被恢复、被别的机器读到；一次性代号不该跟着走。
224. **快照比实时更合适**：读者挑选时要的是「打开那一刻的列表」，每按一次 Enter 重渲染整窗是昂贵的实时。
225. **新的一段放进目录的末尾**，别压在读者熟悉的前几项之上；搜索自会把它带到眼前。
226. **去重要在排序之后**：同一命令在多台主机上出现，按最近使用取第一条才是读者想要的。
227. **成功可以不出声。** 结果已经在屏幕上的动作，再报一次只是噪音；失败才需要一句话。
228. **模拟提交 ≠ 已记录。** 历史写入在真实路径上；测试要记历史就调历史本身的接口。
229. **内联调用换成具名回调，依赖数组是第二处要改的地方。** typecheck 不管这个，只有 lint 的 `useExhaustiveDependencies` 会提醒。
230. **新增样式先确认谁最终生效。** 后加载的同名属性会覆盖你刚写的规则，而浏览器不会报错。
231. **让测试打印计算值，比通读样式表快。** `getComputedStyle(panel).maxWidth` 一眼看出上限没生效。
232. **`max-width` 默认不含内边距。** 想让「总宽 ≤ 440」，要么 border-box，要么把 padding 减进上限。
233. **「先拼后裁」会裁掉你刚加的区分后缀。** 上限类的字段，先算后缀，再决定词干多长。
234. **断言长度不等于断言唯一。** 承诺「不会覆盖」就要断言「与既有名字不同」，最好再加一条走界面的用例。
235. **负向对照可以很小**：在新旧两段纯函数上跑同一组断言，几行脚本就能证明缺陷真实存在、修复真实有效。
236. **编辑动作不该跟着连接状态一起禁用。** 断线时读者更要整理自己的命令库。
237. **同一特性的入口用同一套注册约定**：多一个「打开」，比多一种机制便宜。
238. **空状态要写「更快的路」。** 「在这里新增」是最慢的一条；读者手边往往已有现成的东西可保存。
239. **Esc 分层退出**：先退一层（筛选、子层），再关门。一次关到底会让读者重来一遍。
240. **`catch(() => undefined)` 是一个决定，不是一行代码。** 写下它时要能说出为什么这次失败不值得说。
241. **读者特意设置的东西，失败必须可见。** 他希望它生效，所以它没生效这件事必须传达到他。
242. **多目标操作要说清数量。** 「已发送」不等于「发到了你以为的那几台」。
243. **计数和写入用同一个函数**：两处筛选迟早会分叉，而分叉的结果是状态栏撒谎。
244. **测试夹具也别手搓大对象。** 用生产的构造函数（`pendingSessionInfo`）造数据，比手写 10 个字段更短也更稳。
245. **高频面板要有一个键。** 菜单和面板入口是发现路径，键盘组合才是日常路径。
246. **同一条命令只在一个地方列一次。** 面板里的动作行与快捷键表重复时，挑一个当主入口，另一个让位。
247. **筛选要进数据流，不要只进渲染。** 否则选择与键盘指向看不见的行。
248. **筛选框要说清剩多少**：`1 / 1000` 比空白输入框更能让读者确认自己筛对了。
249. **筛选是目录的属性，不是面板的属性。** 换目录就该换筛选。
250. **一个让邻居用例超时的测试不是通过的测试。** 移除它时要同时说清「这条行为现在没有测试」，而不是悄悄算作已覆盖。
251. **一条会拖垮邻居的用例，问题在夹具不在产品。** 先把它搬进独立文件，再看它到底测的是什么。
252. **测试要走读者的路。** 失焦再按 Esc 是测试的想象；「筛出目录名再双击」才是读者会做的事。
253. **同一个概念在两个组件里就要有同一个能力。** 补了一处筛选，另一处缺着就是新的不一致。
254. **夹具的默认语言会变成断言前提。** 断文案前先显式设语言，否则用例读起来像在测翻译。
255. **能用方向键走的地方就要能用 F2。** 键盘用户换手去右键，等于这条路径不存在。
256. **树里的按键跟着光标，不跟着焦点。** 焦点进入时激活的是第一行，未必是读者想改的那一行。
257. **同一个键在三个列表里应当是同一件事。** 只在一个列表里生效的约定，读者不会记住。
258. **F2 负责「交给编辑器」，不负责「保存」。** 改名的最后一步仍由读者按按钮完成。
259. **写入值会移动光标。** 要在受控输入框里全选，必须等渲染写完再选。
260. **多余的 `biome-ignore` 是一条警告，不是零。** 抑制注释本身也要过 lint 的未使用检查。
261. **Esc 是按层级退的：** 筛选 → 编辑 → 关窗。一次退到底，等于让读者一次丢两样东西。
262. **别把「不困住读者」和「不丢改动」混为一谈：** 只对已有对象拦截 Esc，新建时照旧关窗。
263. **零引用的类型也要查一遍注释。** 一段描述不存在机制的注释，会让人以为这里已经有保护。
264. **`/` 是筛选中立键：** 有筛选框的列表都用它入口，组合键不算。
265. **写好了却没人调用的清理函数，就是一个漏洞。** `forgetEditorState` 的注释与实现都在，缺的是调用点。
266. **总量从日志行抄，不要从上一轮转抄。** 连续九轮把「198 文件」写成「199」，用例数却一直是对的——转抄只会在数字上慢慢漂移。
267. **窗口侧的记录要问「它是否还成立」，而不是等一个清理调用。** 按状态派生就不会忘记清理。
268. **一次未复现的失败要写清楚三次运行分别是什么**（全量失败 / 单文件通过 / 重跑全量通过），否则读记录的人无法判断它是否已修。
269. **一个约定出现两次之后，第三处就不再是设计问题，而是照抄问题。**
270. **筛选框的 Esc 只退筛选这一步**，并且要挡住冒泡，别顺手关掉对话框或清掉选择。
271. **自己写的功能也要验收第二遍。** 第 73 轮加的「换目录清筛选」到第 82 轮才有证据——行为和证据不是同一件事。
272. **夹具里让 `path` 由状态驱动**，就能在同一条用例里验证「换目录」而不用真的连服务器。
273. **引号跟着路径走，而不是跟着操作系统走。** 一个客户端同时看本地与远端路径时，平台判断必然出错。
274. **反向动作要成对出现。** 有了「终端 → 文件」，就该有「文件 → 终端」，否则读者只能手抄路径。
275. **浏览器套件里偶发的失败集中在「布局/终端拟合」类用例上。** 两轮各一条、文件不同、单跑都过——先把三次运行的结果写清楚，再谈原因。
276. **菜单项的禁用态是 `disabled`，不是 `aria-disabled`。** 断言前先看组件怎么写的。
277. **先读失败信息再猜原因。** 第 84 轮我记成「布局类偶发失败」，实际是 `Test timed out in 15000ms`——超时与断言失败是两种完全不同的缺陷。
278. **给单条重流程用例单独加预算，而不是给整个套件放水。** 后者会把「真的很慢」也一起藏起来。
279. **第四次复制同一个判断时，它已经是一个函数。** 复制的不只是代码，还有「以后要改几处」的债务。
280. **搬位置的一轮也要跑全量。** 这次没改行为，但改了四处接线；四处浏览器用例正好是这段搬家的护栏。

281. **追加写入要用追加，不要"读全文再写回"。** 第 69–83 轮我给 `DECISIONS.md` 追加的 D91–D102 全部没有落盘（文件仍止于 D78），而我每轮都只读了 STATE 的尾部，从没读过 DECISIONS 的尾部。之后追加长文档一律用 `Add-Content`，写完立刻读尾部确认。
282. **"write 返回成功"不等于"内容在里面"。** 提交前先看一遍要提交的文件里到底有什么，尤其是这类只写不读的账本文件。

283. **同一份直觉，在两个组件结构里结论相反。** 文件面板是绑定活跃标签的单例，所以「面板自己的会话」这个概念在该组件里根本不存在；改语义前先读实现。
284. **用 PowerShell 插行要按行数验证。** 这次我以为 $state[3..] 是「从第 4 行起」，实际把 284 行的状态文件压成了 11 行；从 git 恢复后改为按标记切分原始文本，再核对行数与标题数。

285. **验证门应该是一条命令，而不是一节说明书。** 五条命令靠人串联，条件和顺序就活在人的记忆里。
286. **门的实施时间也要量一次：** 整门 5 分 24 秒，97% 在单测与浏览器契约——这解释了「开发期跑目标文件、收尾跑一次全量」为什么是合理分工。

287. **同一输入在两个功能之间，要先定「谁说得更具体」。** 命令面板的搜索框同时当连接目标框，任何单词都能解析成主机，就会把「没有匹配」的诚实结果换成一个假的连接行；判定标准要写成「目标必须自己说出来」。
288. **既有的空状态用例是这条规则最好的护栏。** 它在我改完解析器的第一次运行里就失败了，比任何人工检查都早。

289. **复合条件里的「不是这个」经常是「写法错了」。** 上一轮把不带方括号的 IPv6 当失败分支混在解析里；拆成独立的 splitAddress 之后，每种写法对应一个明确的返回值。
290. **输入的宽容度要有清单。** 认 ssh://（粘链接来的人需要），不认两侧空格（搜索框不该猜），这类取舍写进文档，下一轮才不用重新推。

291. **插到列表最前面，在分组渲染下并不成立。** 面板空查询时按分组重排（动作在前），我的置顶被覆盖；把「最近」当普通命令交给排序，既没改结构也能被搜到。

292. **断言要能区分来源。** 列表框里「切换到这个标签」和「连接到这个地址」含同一串文本；用 startsWith("Connect to …") 才确认命中的是连接行。

293. **找死代码用「引用次数 = 1」扫，再用仓库全文复核。** 只看 src/ 会把脚本与文档里的引用漏掉，所以候选必须逐个在整仓 grep 一遍；本轮 6 个候选里 3 个是第 78 轮已判定保留的。

294. **没人调用的诊断工具等于不存在。** styleCensus 记了字号／圆角／颜色的频次表却从未被调用；接进外壳视觉门之后，它变成了「字阶漂移立刻失败」的不变量。工具的价值在于被门使用，而不是被写出来。

295. **给 addon 的 urlRegex 不能自带 g 标志。** xterm 的 WebLinksAddon 会拼 `flags + "g"`；自带 `g` 就变成 `gig` 并抛出，而且抛在链接提供者里，连带弄坏同一终端上的其他链接。这类「别人的约定」要写在常量上方，并配一条守卫用例。

296. **全量失败不等于功能坏了，也不等于功能没坏：先读日志。** 这轮全量失败的原因是一行 `SyntaxError`，而不是断言；同一份日志还准确指出受害的是文件链接用例。

297. **第二个入口出现时，就该合并状态。** 「最近连过的主机」先落在 App 的局部状态里没问题；当 `actions.ts` 也需要写入时，正确做法是把唯一写者移进 store，而不是给第二处传一份回调、各存一份。

298. **先确认插入的是哪个 interface。** storeTypes.ts 里 `filerSort` 同时出现在 AppSettings 与 AppStore；我按行号插进前者的字段，typecheck 立刻报出 4 处连带错误。同名字段多的文件里，锚点要带上下文而不是只带字段名。
