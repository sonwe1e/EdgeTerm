# 命令退出状态（2026-11-22 第 27 轮）

「刚才那条命令成功了吗？」目前只能自己往上翻输出。终端的 OSC 133 集成里，shell 在命令结束时发 `D;<code>`——这个状态此前被解析器直接丢掉了。本轮把它接到状态栏。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| `OSC 133;D;7` | 状态栏：Command exited with status 7 |
| `OSC 133;D;0` | 不产生任何提示（安静即成功） |
| 裸 `OSC 133;D` 或非数字状态 | 视为未知，不提示 |
| 没有 OSC 133 的 shell | 完成状态仍然推断（提示符匹配），但退出码未知，不提示 |

## 二、实现

| 位置 | 变化 |
| --- | --- |
| terminal.ts（OSC 133 handler） | 拆出 `D;<code>` 的数字部分；解析不到数字时为 null |
| TerminalCommands | `noteExit(code)` 把状态暂存到命令关闭时（D 与命令闭合不是同一条调用路径） |
| 完成回调 | `onCommandState(state, kind, exit?)` 多带一个可选退出码 |
| actions.ts | 仅当 exit 存在且非 0 时写状态栏；其余保持原有完成行为 |

## 三、验证

| 用例 | 断言 |
| --- | --- |
| 单测 terminalCommandExit.test.ts 3/3 | D;7 → 回调收到 7；D;0 → 0；裸 D → null；**上一条的状态不会泄漏到下一条**；非数字 → null（不猜） |
| 浏览器 commandExitStatus 1/1 | 走真实 App：写入 C/输出/D;7 → `.status-message-text` 恰为 Command exited with status 7；再跑一条 D;0 → 不残留该提示 |

全量（定稿树）：前端单测 182 文件／1752 用例、浏览器契约 60 文件／259 用例、typecheck、format:check（545 文件）、lint（仅生成绑定 2 条既有警告）、生产构建全部通过。

## 四、边界

- 只有当远端 shell 真的发 OSC 133 时才有退出码；纯提示符匹配推断的完成没有状态，**不伪造成功**；
- 只写状态栏，不改变标签的活动点（失败与「有未读输出」是两件事）；
- 没有把退出码做进侧栏标记（那需要另一套行标记，留作后续）。
