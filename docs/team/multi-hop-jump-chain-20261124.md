# 多跳 ProxyJump 落地：链存在会话自己身上（2026-11-24 第 141 轮）

上一轮（第 140 轮）查清了不能靠共用跳板连链，并把五步方案定死。本轮一次做完，没有拆开提交。

## 一、改了什么

| 层 | 改动 |
| --- | --- |
| 模型 | `SessionProfile.jump_profile_ids: Vec<String>`（第一跳在前）；旧的 `jump_profile_id` 保留为**只读兼容**字段，读旧文件仍有效，`canonicalize_jumps()` 在每次保存前把它折进列表，不再写回 |
| Store | `jump_chain` 直接按列表解析，**逐项**校验（存在、是 SSH 传输、不循环、长度上限）；仍然展开「某跳自己也有跳板」的旧式嵌套；`save` 与 `normalize_jump_hosts` 都先折叠再过滤无效项 |
| 传输 | `TransportKey` 的跳板指纹从单个 id 改为列表 |
| 导入 | `ProxyJump a,b` **按顺序**写进该会话的列表，**不再改任何其他 profile**；`jumps_ignored` 与两条文案删除 |
| 对话框 | 跳板从单选改为**编号列表**：加一跳、单独移除；顺序即路径 |
| 其余 | 重连等价判断、快照白名单、会话面板的跳板提示、journal 指纹全部改用列表 |

## 三、顺带修掉的一条真实缺陷

`dialogAudit.browser.test.ts` 是「对话框里每个控件都够大、可点」的审计。本轮表单变短后，颜色色块落进了审计视野：**20×20 的色块低于 24×24 的下限，且相邻色块的 24px 圆相交**。已把色块与网格一起改成 24px，审计通过。这不是本次功能引入的问题，是之前一直没被看见的命中区域缺陷。
