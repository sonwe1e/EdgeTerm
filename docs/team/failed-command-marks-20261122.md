# 失败命令在侧栏留痕（2026-11-22 第 28 轮）

上一轮把退出码接到状态栏，但状态栏只是一时的：命令一多，失败的那条仍然只存在于输出里。本轮让失败在**侧栏**留下位置——它跟着命令行本身，滚多远都还在。

## 一、行为

| 情况 | 侧栏 |
| --- | --- |
| D;0 / 未知状态 | 普通命令标记（既有强调色竖线） |
| D;非0 | 命令标记改为**错误色**竖线，行号也用错误色 |
| 没有 OSC 133 的 shell | 普通命令标记（退出码未知，不臆断失败） |

## 二、实现

| 位置 | 变化 |
| --- | --- |
| TerminalCommands | `commandExits` 与 `commandStarts` 同步增删；`commandFailures()` 返回失败命令的起始行 |
| finishCommand(exit, promptRow) | 完成时同时登记标记与该命令的退出码；OSC 133 D 传光标行，提示符匹配路径不传退出码 |
| terminal.ts | OSC 133 D 用光标行调用 finish；gutter 上下文多一个 `commandFailures` 集合 |
| 侧栏 | 每行缓存增加 `failed`，只翻转 `is-failed`；CSS 把失败命令行描成错误色 |

顺带修掉一个此前没被发现的缺口：**带 OSC 133 的 shell 之前根本没有命令行标记**——标记原本只在提示符匹配路径登记，而 D 路径直接关闭命令。现在两条路径都在 finishCommand 里登记，OSC 133 用户的侧栏命令行标记也因此出现。

## 三、验证

浏览器 commandExitStatus 1/1（扩展）：写入 C/输出/D;7 后，状态栏显示失败，且侧栏恰好有 **1 个 `.gutter-row.is-failed`**、同时仍带 `.is-command`（它既是命令边界也是失败）；再跑一条 D;0 → 状态栏不残留、失败标记仍然是 1（成功不新增）。

全量（定稿树）：前端单测 182 文件／1752 用例、浏览器契约 60 文件／259 用例、typecheck、format:check（545 文件）、lint（仅生成绑定 2 条既有警告）、生产构建全部通过。

## 四、边界

- 失败只影响命令行标记的颜色，不改变行号/时间戳的其它语义；
- 只有 shell 明确报告非 0 才标记；未知一律按普通命令处理；
- 不提供「跳到上一个失败命令」（可作为后续）。
