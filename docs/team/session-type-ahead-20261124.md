# 会话树里的输入即跳转（2026-11-24 第 101 轮）

一长串会话里用方向键找一台机器太慢。文件管理器、邮件客户端都有「敲首字母跳过去」，会话树此前没有。

## 一、规则

| 操作 | 结果 |
| --- | --- |
| 敲 `l` | 跳到下一个名字以 l 开头的**会话** |
| 敲 `la`（600ms 内） | 同一次搜索收窄到以 `la` 开头的会话 |
| 停顿超过 600ms 后再敲 | 开始新的搜索 |
| 连按 `l` | 在首字母为 l 的会话之间轮转（搜索从当前行之后开始并环绕） |
| 无匹配 | 什么都不动，且**不滚动页面**（键已被接管） |
| 带 Ctrl/⌘/Alt 或 `?`、`/` 等既有键 | 仍走原有路径（`/` 打开筛选、快捷键表照旧） |

只匹配会话行：分区标题（SSH / Telnet 会话）与组名不参与——输入是在找机器，不是在找标题。

## 二、实现

- 纯函数 `nextTypeAheadRow(rows, fromIndex, query)`：大小写无关的前缀匹配，从当前行之后开始并环绕；空串或无匹配返回 `null`。它被单测覆盖，树的组件只负责缓冲与派发。
- 树的键盘模型里在方向键分支**之前**接管无修饰键的可打印字符，`preventDefault` + `stopPropagation`，这样页面不会跟着滚动。

## 四、边界

- 缓冲区只在组件内，不跨面板、不持久化；
- 输入法组合（IME）期间的按键会被当作可打印字符——中文会话名暂不能靠拼音首字母跳转，这一点写在这里以免被误认为缺陷；
- 只在树本身有焦点时生效；筛选框内打字仍然是筛选。
