# 上一轮的标记，在窄面板和长名字下还看得见吗（2026-11-24 第 98 轮）

第 97 轮在会话行里加了 `Recent` 标记。行是密集布局：颜色点 + 名字 + 标记 + 两个悬停按钮。**名字很长、面板又窄**时，标记会不会被挤成 0 宽、或者被挤出可视区？外壳视觉门里的夹具没有「最近用过」的会话，所以它从来覆盖不到这一行。

## 一、做法：先写一条能抓住这个风险的断言

- 320px 宽、档案名长到能占满整行；
- 写入 `recentProfiles` 让标记出现；
- 断言标记**宽度 > 12px**（没被压扁）且**右边界不超出所在行**（没被挤出去）。

布局上这条断言成立的原因：`.row-label` 是 `flex: 1` 且 `text-overflow: ellipsis`，名字先让位；标记按内容宽度保留。也就是说标记的可见性**依赖这条既有规则**——规则若被改，这条用例会立刻失败。

## 二、过程中的一个错误

第一次跑失败，报 `ReferenceError: page is not defined`：这个夹具只从 `vitest/browser` 导入了 `userEvent`，我加了 `page.viewport` 却忘了导入 `page`。**失败的测试未必在说产品有问题**，先读错误类型再看断言。

## 四、边界

- 只测一个宽度与一个长名字：这是回归护栏，不是布局穷举；
- 该断言不涉及字体缩放（`panelFontSize` 变化由外壳普查与显示设置用例覆盖）。
