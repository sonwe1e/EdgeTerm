# 让读者写下的命令跟着设置一起走（2026-11-23 第 54 轮）

项目自己的规则写在 `src/persistKeys.ts` 开头：**没有登记在这个表里的偏好，对「恢复默认设置」和设置的导出/导入都是不存在的。** 第 46–53 轮加的两样东西正好违反了自己的规则：

| 键 | 是什么 | 本轮之前 |
| --- | --- | --- |
| `edgeterm.snippets` | 常用命令 | 导出设置里没有；恢复默认不清；导入不带 |
| `edgeterm.startupCommands` | 各连接的启动命令 | 同上 |

这两样都是读者自己写下的内容，丢了比丢一个字号更让人恼火。

## 一、修法

| 位置 | 变化 |
| --- | --- |
| `persistKeys.ts` | 新增并登记 `SNIPPETS_STORAGE_KEY`、`STARTUP_COMMANDS_STORAGE_KEY` |
| `snippets.ts` / `startupCommands.ts` | 键常量改为引用登记表，避免两处字面量漂移 |
| `storePreferenceActions.ts` | 导入后立刻从存储重读这两项到 store；恢复默认时同时清空 store 状态（不只是删键） |

第三项是关键：这两项既是存储里的偏好、又是 store 的状态。只删键而不清状态，界面会继续显示已经不存在的命令；只写键而不重读，导入要等重启才生效。

## 二、验证

| 用例 | 断言 |
| --- | --- |
| `settingsCommands.test.ts`（3） | 导出包含两个键及其内容；导入后 store 与存储同时更新；恢复默认后键被删除且 store 清空 |

三件事各有一条断言，正是登记表承诺的三件事（导出携带、导入生效、恢复清空）。

## 三、教训

「加一个偏好」在这个仓库里是**两步**：写模块，然后登记。第 46 轮和第 53 轮都只做了第一步。本轮补登记，并把「导入/恢复要同步 store」这半个坑也一起填了——登记表只管存储层，store 层的东西得自己记得刷新。
