# 观察标记的跳转（2026-11-23 第 35 轮）

第 34 轮把观察字「看得见」做完了，但当时的边界写得很清楚：还不能跳。本轮补上另一半，让「带错误/警告的行」成为可以逐个走查的对象。

## 一、行为

| 动作 | 结果 |
| --- | --- |
| 下一个观察标记 | 从当前落点往下找第一条带错误/警告的行并滚到它 |
| 上一个观察标记 | 从当前落点往上找，第二次按继续往上，不回到原处 |
| 到顶或到底 | 返回「没有更早/更晚的标记」，状态栏说明 |
| 缓冲区里没有任何标记 | 状态栏提示「缓冲区里没有带错误或警告的行」 |
| 缓冲里也没有失败命令标记 | 两套跳转互不干扰，各自报告 |

## 二、实现

| 位置 | 变化 |
| --- | --- |
| terminal.ts | `jumpToWatchMark(direction)` 与 `watchMarkLines()`，复用已有的 `jumpToLines` 走查与「落点高亮」 |
| shortcuts.ts | 新命令 `prevWatch` / `nextWatch`，默认不绑定（与失败命令跳转一致），但在快捷键表、设置与命令面板中可见可绑定 |
| App.tsx | 统一分发器的两个分支；失败时写入状态栏提示 |
| MenuBar.tsx | 「上一个/下一个观察标记」菜单项，显示当前绑定 |

**落点是共享的**：命令跳转与观察字跳转用同一个「上次落点」，所以「上一个」永远意味着「从我正在看的地方往上」，不管上一步是哪种跳转。这是有意的：读者关心的是位置，不是跳转的种类。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `terminalWatchJump.test.ts`（2） | 60+ 行缓冲里两处标记：上一个→落在更晚的标记、再上一个→更早的标记、再上一个→false；下一个→回到更晚、再下一个→false；无标记时两个方向都 false |
| `watchWords.browser.test.ts`（2） | 记号：恰好 2 行被标记、清屏归零；跳转：命令面板执行「Next Watch Mark」后视口里出现被标记的行；清屏后再执行，状态栏出现「没有带错误或警告的行」 |

## 四、一处测试脚手架教训

jsdom 里 5 行内容的缓冲区不足一屏，`scrollToLine` 被夹到 0，`viewportY` 恒等于 0。断言改成「落点在可见范围内」，并用 60+ 行的缓冲让滚动真的发生。

## 五、边界

- 默认不占用任何按键（与失败命令跳转同一策略：罕见的走查动作交给设置/面板）；
- 只走查观察字，不把查找框的命中混入（查找有它自己的 `3/12` 索引与 Enter/Shift+Enter）；
- 全屏程序与 Agent TUI 不产生观察标记，因此也无处可跳。
