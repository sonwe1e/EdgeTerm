# 命令导航（2026-11-22 第 8 轮）

长输出之后，读者需要的不是"上一条命令的文本"（第 7 轮已交付），而是**在命令之间走动**。本轮加上：

| 入口 | 行为 |
| --- | --- |
| `Ctrl+Shift+↑` / `⇧⌘↑` | 跳到上一条已结束的命令 |
| `Ctrl+Shift+↓` / `⇧⌘↓` | 跳回下一条 |
| View 菜单 / 命令面板 | 同上（可改键） |

## 一、实现

- **历史是 marker 列表**（[terminalCommands.ts](../../src/terminalCommands.ts)）：每完成一条命令就压入一个起点 marker，上限 200；裁剪时被丢弃的 marker 自己报告 `isDisposed`，导航跳过它们。
- **走查从上次落点继续**（[terminal.ts](../../src/terminal.ts)）：参照点是 `commandJumpLine ?? 光标行`。没有这个状态，连按两次"上一条"会停在同一条命令上。
- **落点必须看得见**：滚动到该行（复用控制器已有的 `scrollToLine`，它会算上冷历史的首行偏移），并给这一行 1.2 秒的强调色底纹。
- **同一时刻只有一个底纹**：新的跳转先清掉旧的。
- 找不到方向上的命令时，状态栏说明"这个方向没有可跳转的命令"。

## 二、验证中发现并修掉的问题

初版每次跳转都新建一个 decoration，1.2 秒后才消失。连按两次时：

1. **界面上同时有两个底纹**（旧的还在闪）；
2. 测试用 `querySelector(".command-jump")` 读到的是**旧的那个**，于是第二次跳转被判定落在错误的行上。

修复为"单一活动底纹"后两个问题一起消失。这不是测试假象：两个高亮同时存在本身就是错误的状态提示。

另外确认了 `scrollToLine` 的落点不等于目标行：目标在视口内时它不滚动，落在最后一屏时贴底。验收因此改为两层——**目标行在视口内**，以及**落点行由底纹的渲染位置算出**，而不是直接比较 `viewportY`。

## 四、边界

- 历史上限 200 条；滚出回滚缓冲的命令不再可导航（marker 被裁剪）。
- AI 会话的一轮对话不进入命令历史（与第 7 轮一致）。
- 尚未在行号栏（gutter）给命令行加标记；这是下一步的自然延伸。
- 只覆盖 Chromium + 受控 IPC；真实服务器下的提示符形态由既有启发式处理。
