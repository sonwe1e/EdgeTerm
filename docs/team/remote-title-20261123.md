# 程序自报的窗口标题（2026-11-23 第 39 轮）

延续上一轮「静默的协议信号」的排查：`term.onTitleChange`（OSC 0/2）同样没有任何处理。程序通过它说自己正在做什么——`vim notes.txt`、`tail -f`、嵌套 ssh 的提示——而界面完全不显示。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| 程序设置窗口标题 | 状态栏会话详情旁出现该标题（超出宽度省略，悬停看全文） |
| 程序更新标题 | 状态栏随之更新 |
| 程序把标题设为空 | 状态栏该项消失 |
| 标题带控制字符或超长 | 去掉控制字符、去空白、截断到 120 字符 |
| 用户给标签改过名 | **标签名不变**：自报标题只出现在状态栏 |

## 二、为什么放状态栏而不改标签名

第 43–46 轮定下的规则是：改名是用户的，标签名由用户拥有。自报标题是**程序此刻的说辞**，会随 `vim` 退出、随嵌套 ssh 切走；把它写进标签名会和用户的命名打架，也会让标签在 1 秒内闪变。状态栏是旁注的位置：服务会话身份，同时不争夺标签名。

## 三、实现

| 位置 | 变化 |
| --- | --- |
| `terminal.ts` / `terminalShared.ts` | `term.onTitleChange` → 回调 `onTitleChange(title)` |
| `actions.ts` | 回调里调用 `noteTabTitle(id, title)` |
| store | `Tab.remoteTitle?` 与 `noteTabTitle`：清洗、去重（同值不产生新数组） |
| `StatusBar.tsx` | 会话详情组里新增 `.status-remote-title`，`max-width: 28ch` 省略，`title` 属性给全文 |

## 四、验证

| 用例 | 断言 |
| --- | --- |
| `tabRemoteTitle.test.ts`（5） | 原样保留；去控制字符与空白（`vim\u0007 \u001bnotes` → `vim notes`）；400 字符截到 120；空标题清除；同值不改数组 |
| `remoteTitle.browser.test.ts`（1） | 真实 xterm 写 `OSC 0`：状态栏出现 `vim notes.txt`；写 `OSC 2`：更新为 `tail -f /var/log/syslog`；**标签名保持 `title` 不变**；`title` 属性保留全文 |

## 四点五、验证记录

单测 187 文件／1779 用例通过。浏览器首次全量 270/271（一条失败未复现），带日志重跑 271/271 全绿——该次失败**未被定位**，不声称已修复。

## 五、边界

- 只显示在状态栏，不参与标签命名、不参与排序或搜索；
- 不做标题的持久化（另一个会话的新标题不该被记住，也不该在恢复时冒充）；
- xterm 只在 OSC 0/2 时上报；`printf '\033]0;x\007'` 这类程序均覆盖。
