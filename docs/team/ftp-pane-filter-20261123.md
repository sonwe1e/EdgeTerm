# 双栏文件浏览器也有筛选了（2026-11-23 第 73 轮）

上一轮把筛选给了 Filer 面板。FTP/SFTP 双栏浏览用的是另一个组件（`FileBrowser`），那里一直没有筛选：在含上千个文件的远端目录里，两边都只能靠打字跳转。

## 一、交付

| 位置 | 变化 |
| --- | --- |
| 双栏每侧 | 路径栏下方新增筛选栏（与 Filer 同一套样式与计数文案） |
| 数据流 | 筛选同样进入排序 memo，选择、键盘、行渲染都读同一份 `sortedEntries` |
| 目录变化 | `path` 改变时清空筛选（与 Filer 一致） |
| 筛选变化 | 改变筛选值时清空本侧选择（`{ paths: [], anchor: null }`） |
| 无障碍 | `aria-label` 带面板标题：「筛选当前文件夹 — SFTP 服务器」，两栏同名也能区分 |

## 二、验证

| 用例 | 断言 |
| --- | --- |
| `ftpKeyboard.browser.test.ts`（4，新增 1） | 三条目夹具：输入 `file-b` → 只剩 `file-b.txt`、计数 `1 of 3`；`Esc` 清空后回到三条 |

## 三、两次自我修正

1. `onSelectionChange(new Set())` 类型不对：这个组件的选择模型是 `{ paths: string[], anchor }`，不是 `Set`。typecheck 抓到。
2. 断言 `1 of 3` 时实际是 `1 / 3`——夹具默认中文；在该用例开头设 `setLanguage("en")`，避免把语言当断言前提。

## 四、边界

- 筛选只在当前目录内生效；空目录不显示筛选栏；
- 两栏各自独立筛选：它们本来就是两份目录。
