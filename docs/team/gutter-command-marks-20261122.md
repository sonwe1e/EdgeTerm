# 行号栏的命令标记（2026-11-22 第 9 轮）

第 8 轮的导航有一个发现性问题：不知道快捷键的人看不见"命令从哪里开始"。本轮把命令起点画进行号栏：

- **左侧 2px 强调色竖条**（inset box-shadow，不改变两栏网格布局）；
- **行号换成可读的强调色并加粗**（`--accent-bright`，深色主题下也达标）。

于是长输出里能看到一条"时间线"，知道每条命令的输出从哪一行开始、到哪一行结束。

## 一、实现

- 行号栏的上下文新增 `commandLines: ReadonlySet<number>`（[terminalLineGutter.ts](../../src/terminalLineGutter.ts)），由 `TerminalCommands.commandLineList()` 生成。
- **每次绘制读一次集合**，不是每行读一次：逐行构造 Set 会把 O(命令数) 的工作放大到每帧每行。
- 行缓存（`rowPaint`）增加 `command` 字段，与 `is-empty`/`is-cursor` 一样只在变化时切换 class。
- 备用屏幕、Agent TUI 等"抑制内容"的情况下复用共享的空集合，不分配。
- 标记跟随绝对行：滚动、裁剪都自动对齐；被裁剪掉的命令行自然失去标记。

## 三、边界与已知依赖

- 行号栏的重绘键只包含视口/光标/内容末尾，不含"是否新增了命令"。标记能及时出现，是因为命令结束时必然写入新的提示符行（改变内容末尾）——这是命令完成的定义。若某个程序在命令结束后不写任何内容，标记要等到下一次滚动/写入。
- 标记目前只是视觉提示，不可点击；可点击跳转是下一步的自然延伸。
- AI 会话轮次不进入命令历史，因此也没有标记（与第 7、8 轮一致）。
