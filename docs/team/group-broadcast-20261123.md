# 按组选择性广播（2026-11-23 第 33 轮）

积压清单第三项。此前同步输入只有「逐会话勾选」：十台生产机要一台台点掉，而这正是出错的地方。本轮允许整组一起加入或排除。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| 某分组被排除 | 该组所有成员都收不到同步输入 |
| 组内某个会话另外被勾掉 | 两条排除叠加，不互相覆盖 |
| 排除后还有其它收件人 | 状态栏报真实人数（例如 2 → 1） |
| 排除后一个都不剩 | 同步输入自动关闭，并说明原因 |
| 组里没有当前打开的目标 | 该组不出现在目标列表里（不提供空开关） |

广播目标的判定仍然只有 `broadcastTargets` 一个函数（第 29 轮定下的规则），组排除是它的第四个参数，而不是第二套规则。

## 二、实现

| 位置 | 变化 |
| --- | --- |
| broadcast.ts | `BroadcastTab.profile.groupId` + 第四个参数 `excludedGroups`；组在排除表里即跳过 |
| store | `broadcastExcludedGroups` 与 `setBroadcastGroup(groupId, included)`，与逐会话表并列 |
| sessionInput / App / StatusBar / BroadcastTargets | 四处消费者都传两份排除表；人数仍由同一函数算出 |
| 目标弹层 | 有成员在目标里的分组显示为一行开关（Group: 名称），位于逐会话行之上 |

## 三、验证

| 用例 | 断言 |
| --- | --- |
| 单测 broadcast.test.ts | 排除整组后只剩组外成员；与逐会话排除叠加；未知组名不影响任何人；空排除表与从前一致 |
| 单测 storeBroadcastActions.test.ts | 排除组后人数如实减少且模式保持开启；最后一个收件人随组离开时模式自动关闭并说明 |
| 浏览器 broadcast 5/5（新增 1 条） | 目标弹层里出现 Group: Production；点掉后 store 记录该组、敲键只到组外会话；再点回来该组成员重新收到 |

## 四、两处脚手架教训

1. **分组是挂载后从宿主加载的**：`loadGroups()` 会用宿主返回覆盖 store，夹具里预先写入的组因此被清空，必须在挂载后再固定。
2. 该文件的 `written(id)` 返回的是拼接后的字符串，不是数组；断言空值时用 `toBe("")`。

全量（定稿树）：单测 182 文件／1757 用例、浏览器契约 61 文件／265 用例、typecheck、format:check（546 文件）、lint（仅生成绑定 2 条既有警告）全部通过。

## 五、边界

- 组排除不持久化（与同步输入本身一致：破坏性模式绝不在下次启动偷偷恢复）；
- 只按「保存的会话所属分组」判定，不按标签当前所在面板；
- 嵌套分组不继承：只排除被勾掉的那一层，不连带子组。
