# 连接目标：接受 ssh:// 前缀，并把地址拆解写清楚（2026-11-24 第 90 轮）

第 89 轮的目标框只认 host、user@host、host:port。两种常见输入落空：从工单或 wiki 复制来的 “ssh://root@host:22”，以及不带端口的方括号 IPv6 “[::1]”。另外第一版的 IPv6 分支写成一个 “colon > 0 && startsWith("[") && !endsWith("]")” 的复合条件，读起来要靠猜。

## 一、交付

| 输入 | 结果 |
| --- | --- |
| ssh://root@example.com:2200 | 用户 root、端口 2200 |
| SSH://example.com | 前缀大小写无关 |
| [::1] | 无端口 |
| [::1]:2222 | 端口 2222 |
| ::1 | **拒绝**：不带方括号时端口无法判定 |
| [::1]x | **拒绝** |

地址现在由专门的 splitAddress 拆：方括号地址找右括号，其余按唯一那个冒号拆端口；出现两个以上冒号又没加方括号，即视为写法错误。判「这算不算一个目标」的规则没有变——有 @、有端口、主机带点或方括号地址。

## 二、验证

src/quickConnect.test.ts 6 条：三种基本写法加方括号 IPv6；ssh:// 前缀（含大小写）；十二条拒绝清单（空、短语、@host、user@、端口 0/99999/非数字、空格、单词、裸 IPv6、右括号后多余字符）；标签名与资料填充；未指定字段保留默认。

## 三、边界

- 只识别 ssh:// 一种前缀：ftp:// 与 sftp:// 不是这条入口的语义，它们要走会话编辑器；
- 地址里有空格就当作搜索短语，不做「去掉两侧空格再试」的宽容处理：搜索框不该猜。
