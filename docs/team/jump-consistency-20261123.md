# 缓冲区走查的统一实现与菜单路径的缺陷修复（2026-11-23 第 37 轮）

积压项清空后，本轮是一次质量轮：读近期反复改动的 `App.tsx` 与 `MenuBar.tsx`，把重复和一处真实的行为不一致修掉。

## 一、发现的缺陷

命令跳转有三个家族——命令、shell 报告失败的命令、观察字标记。键盘与命令面板都会在走空时提示（「没有更早的命令」「没有失败命令可跳转」「缓冲区里没有带错误或警告的行」），但**菜单里的同名项直接调用 controller，走空时什么都不说**：点了菜单没有任何反应，看起来像菜单项坏了。

## 二、改法

| 位置 | 变化 |
| --- | --- |
| `terminalJump.ts`（新） | `jumpInActiveTab(family, direction)`：取当前标签、调用对应走查、走空时写状态栏，返回是否落地 |
| `App.tsx` | 三个各自的 `useCallback`（jumpCommand / jumpFailed / jumpWatch，共 35 行）删除，分发器的 6 个分支改为调用同一函数 |
| `MenuBar.tsx` | 6 个菜单项同样改为调用它——菜单、键盘、命令面板从此是同一条代码路径 |

净效果：`App.tsx` 少 3 个回调、多 6 行分发；一份实现替代三份，菜单不再静默。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| 既有单测（`terminalCommandExit` / `terminalWatchJump`） | 三个家族的走查与两端停止逻辑未变 |
| 既有浏览器用例 | 失败命令跳转（面板路径）与观察字跳转（面板路径）仍然落地 |
| `watchWords.browser.test.ts` 新增 1 条 | **菜单路径**：缓冲区没有标记时点 View → Next Watch Mark，状态栏出现「没有带错误或警告的行」——旧实现此断言必然失败 |

## 四、质量评估（本轮读过的文件）

- `App.tsx`（约 1000 行）：分发器是长 switch，但每个分支一行、语义清楚，暂时不值得再抽象；重复的三份跳转是唯一真正的坏味道，已消除。
- `MenuBar.tsx`：菜单项用 `withActive` 处理选中/复制这类「有标签才有意义」的动作，逻辑一致；跳转是例外（要在走空时提示），现已单独归类。
- `terminalJump.ts`：新文件只做一件事，依赖 store 与 registry 两个既有模块，无新概念。

全量（定稿树）：单测 185 文件／1770 用例、浏览器契约 63 文件／269 用例、typecheck、format:check（554 文件）、lint（仅生成绑定 2 条既有警告）全部通过。

## 五、流程反思（本轮）

- 本轮没有新功能，验证成本压到最低：改完先 typecheck + lint（约 20 秒），再跑受影响的单测与两个浏览器文件（约 40 秒），最后全量一次。
- 一个可复用的判断：**同一动作有多条入口时，优先抽成模块函数，而不是复制回调**——复制的那份迟早与另一份分叉（本轮就是菜单那份分叉了）。
