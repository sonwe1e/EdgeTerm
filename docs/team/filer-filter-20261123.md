# 文件面板能就地筛选（2026-11-23 第 70 轮）

文件面板此前只能靠输入首字母跳转（第 N 轮加的 type-to-select），没有任何筛选：面对 1000 个文件的目录，想找 `file999.txt` 只能一路翻或打字跳到附近。FileZilla、WinSCP、资源管理器都有筛选框。

## 一、交付

| 位置 | 变化 |
| --- | --- |
| 路径栏下方的筛选栏 | 输入即就地筛选（按名称、不区分大小写）；非空时右侧显示「{shown} / {total}」 |
| 键盘 | 列表里按 `/` 聚焦筛选框；筛选框里 `Esc` 先清空筛选 |
| 数据流 | 筛选发生在 `sortedEntries` 这一个 memo 内：选择、type-to-select、方向键、虚拟滚动**都自动作用于筛选后的列表** |

## 二、判断：筛选必须进入同一条数据流

如果只在渲染层过滤（例如给虚拟列表另传一份数组），选择集、方向键与 type-to-select 仍会指向被隐藏的行，读者会遇到「选中了看不见的文件」。把筛选放在排序 memo 里，`sortedEntries` 就是屏幕上的那一份，其余代码一行不改。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `filerSelection.browser.test.ts`（6，新增 2） | 1000 个文件的夹具：输入 `file999` → 只剩 `file999.txt`、计数为 `1 of 1000`；`Esc` 清空后 `file0` 回来。列表聚焦时按 `/` → 焦点进入筛选框 |

## 四、一次测试修正

第一次写 `/` 用例时先给行按钮 `.focus()`：行是按钮但不在 Tab 顺序里，聚焦不成立，keydown 根本没经过列表处理器。改为聚焦列表容器（它有 `tabIndex=0`）后通过。

## 五、边界

- 筛选只在当前目录内生效，不递归子目录；
- 空目录不显示筛选栏（没有可筛的东西）；
- 不在筛选框时输入字母仍是 type-to-select（原生行为），两者不冲突。
