# 审计：终端核心 + 重连/通知（2026-11-25 第 201 轮）

两个只读审计。**核心终端面干净（0 条）；重连/通知面 3 条，本轮修 2 条，1 条待办。**

## 终端核心：无缺陷

审计逐条追了五类可疑点，都干净，并给出了证据：

- **选区在 reflow/resize 后丢失**：应用从不跨 resize 重建选区，交给 xterm；应用自有的选区状态只有**捕获到的文本**，不是范围（`terminalClipboard.ts:40-44`），且在新一次按下时故意清空。没有会失同步的应用层范围。
- **复制丢字符类**：`copySelection` 原样写 `getSelection()`，不做后处理；两处转换都有意且有成文注释（拒绝全空白、只修剪行尾空白）。OSC 52 载荷按会话自己的编解码器解，不强推 UTF-8。
- **查找环绕方向错/丢查询**：向前环绕回到第一个匹配，向后回到最后一个；变更检测同时比较 `source` 与 `flags`，所以切换「区分大小写」也会重算。
- **链接开错目标**：文件链接在点击时重新解析该行，引用已消失就放弃；目录经稳定行坐标解析。
- **渲染器丢行**：DOM 回退画整个视口；语义渲染器走视口加一段有界 backlog，有循环链表保护。

两条**边界**（不是缺陷，正确性依赖 xterm.js 而非应用代码，若有桌面验证值得手查）：宽度变化导致 reflow 时的选区重映射；`copyLastCommandOutput` 对跨行命令的输出范围。

### R2 为什么未修

审计给的最小改动是去掉那个 `false`。但那句 `false` 带着一段成文理由：「除非另一个界面（主机密钥对话框）拥有下一次尝试」。这确实是真的——`onReconnect` 用 `store.hostKeyPrompt?.sessionId === id` 守着，Enter 不会抢走对话框的尝试。

也就是说：改动是安全的，但它推翻了一段**有意写下并仍然成立**的注释。本轮没有桌面对话框的实机验证，我不想在没有观察到「对话框开着时按 Enter」的真实行为之前，就删掉一个正当的守卫。**记为待办，并附上审计的完整论证**，下一条在有桌面验证时做，或者先补一条覆盖「对话框开着 + Enter」的用例。

## 确认无缺陷（重连/通知面）

- **重试用陈旧凭据**：`reconnectSession` 从 store 重新推导 profile，标签页专用 secret 受 `sameConnectionIdentity` + 认证类型 + 密钥路径三重检查；有 `reconnectWiring.test.ts:513-541` 覆盖。
- **重连循环/退避**：前端从不自动重试（Enter 与电源按钮都是一次性）；后端各处有 `MAX_RETRY_DELAY`、`1 << retry`、`MAX_AUTH_ROUNDS = 16`、`PASSWORD_ATTEMPTS = 3`。
- **通知不清除**：状态栏计时器以 `error` 为依赖，消除错误会重启它，错误期间设的通知仍会随后清除。
- **语言键**：`src/` 引用的全部 1358 个 `t()` 键在两语言都存在，占位符集合逐键一致。
- **消息里的主机/端口错**：`connect_hop`、`profile.address()`、`verify.rs`、跳转 `Via.label` 对各类型默认端口（ssh/sftp 22、ftp 21、telnet 23）口径一致。

**未观察（不作断言）**：`transport.rs:680` 的 `authenticate` 不在 `HANDSHAKE_TIMEOUT` 窗口内（代码有意如此，MFA 属于人）。我没有观察 russh 的 keepalive 是否在认证完成前运行，因此无法说「接受 TCP 后在认证阶段沉默的对端」会让标签挂住还是最终被判死。

## 第 202 轮：R2 用保住守卫的方式修掉了

第 201 轮我把 R2 记为「未修」，理由是那个 `false` 带着一段仍然成立的成文注释（对话框开着时 `onReconnect` 有守卫，Enter 不会抢走对话框的尝试）。

本轮换了一条**不碰那个守卫**的路：对话框的 `onCancel` 原来只调 `setHostKeyPrompt(null)`，现在改调新增的 `declineHostKey(prompt)`——它清提示，并补写一次 `sessionClosedNotice()`。`failSession` 的那个 `false` 原样保留，注释也原样保留。

效果是一样的（取消后终端里有了「按 Enter 重连」），但没有任何守卫被删，也没有任何注释被推翻。**上一轮我判断「必须删守卫才能修」是错的——那条注释说明的是对话框**开着时**的行为，而缺陷发生在对话框**关掉之后**，两者不冲突。**

顺带清掉了 App.tsx 里因此不再使用的 `setHostKeyPrompt` 选择器。
