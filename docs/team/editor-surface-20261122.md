# 内置编辑器表面（2026-11-22 第 16 轮）

内置编辑器是唯一“对话框里装着一个编辑器”的表面：CodeMirror 正文 + 一行小 chrome（目标、路径、编码、重载/关闭/保存）。它此前只有功能测试，没有任何可见性/可点性测量。

## 一、覆盖

`src/test/editorAudit.browser.test.ts` 4 条：

| 断言 | 说明 |
| --- | --- |
| 深色/浅色两种主题下三套门禁零缺陷 | 对比度、点击尺寸、文字截断，并要求 inspected 下限 |
| 关闭与保存按钮 ≥24×24 | 显式测量，不依赖收集器的 16px 下限 |
| 对话框内每个焦点停靠点都有可见焦点环，环色 ≥3:1 | 冻结过渡后测量 |
| 有改动时点关闭会先确认；拒绝保留、同意才清空 | 拒绝路径、保留内容、确认的 kind 与文案、同意路径 |
| 界面印着“Ctrl+S to save”，就真的按一次 | 写入调用、写入内容、状态栏变 Saved、和弦不进正文 |

## 二、结果：没有发现可修的缺陷

三套收集器在两种主题下都是零问题；编辑器的两个按钮都是 24px；焦点环存在且达标。本轮因此是**覆盖与安全契约**，不是修复——如实记录，不把“没有发现”包装成改进。

唯一修正的是我自己的断言：对话框 chrome 只有两个按钮，最初写“读到 >2 个目标”是错的；下限必须与表面真实控件数一致，否则测试会因为断言而非缺陷失败。

## 三、验证

全量：前端单测 175 文件／1725 用例、浏览器契约 51 文件／248 用例、typecheck、format:check（528 文件）、lint（仅生成绑定 2 条既有警告）、生产构建全部通过。

## 四、边界

- 只覆盖内置编辑器的对话框表面；CodeMirror 的内部部件（行号槽、折叠标记、搜索面板）不是应用目标。
- 只覆盖 Chromium 与受控文本 IPC；真实 SFTP 写回、冲突（hash 变化）与“保存时不确认”分支不在本轮。
- 无截图对比（会话内无法目视）。
