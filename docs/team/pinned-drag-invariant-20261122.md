# 固定标签的拖拽边界（2026-11-22 第 25 轮）

第 23 轮把固定标签放到条带最前面，但留下一个洞：**拖拽**仍然可以把固定标签拖进未固定的中间，或把未固定标签拖到固定区里——「固定 = 在最前」的承诺当场失效。本轮把这个洞补上，并让拖拽时的落点标记与真实结果一致。

## 一、规则（clampStripIndex）

| 被拖的标签 | 允许落点 |
| --- | --- |
| 未固定 | 至少在所有固定标签之后（floor = 固定数量） |
| 已固定 | 只在本条带的固定区内（ceiling = 固定区末尾） |

落点是「除自己以外的标签」空间，与 placeTab 的读法一致；跨面板拖拽时按**目标条带**的固定数量计算，所以拖进别的面板也守同一条规则。

同一函数也用于**落点标记**：拖动未固定标签经过固定区时，标记停在固定区之后，而不是先画在固定区里再被丢弃。

## 二、验证

单测 tabsPinnedDrag.test.ts 4/4：

1. 未固定的标签拖到 0/1 被抬到 2（固定数量），拖到 3 原样；
2. 已固定的标签拖到 3 被压回 1（固定区末尾）；
3. 目标条带没有固定标签时，固定的来客落在 0，未固定的照常 0…n-1；
4. 经过 placeTab 的真实移动：未固定标签拖到最前仍落在两个固定标签之后；固定标签右拖仍在固定区内。

全量：前端单测 180 文件／1740 用例、typecheck、format:check（541 文件）、lint（仅生成绑定 2 条既有警告）、生产构建通过；浏览器契约 58 文件／257 用例（定稿树上重跑）。

## 三、边界

- 只约束同一条带的顺序，不改变固定标签归属的面板；
- 拖拽本身仍由指针事件驱动（未在浏览器里合成完整拖拽手势）；
- 不持久化固定状态（同第 23 轮）。
