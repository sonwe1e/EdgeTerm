# 输入延迟：状态栏的「按键到回显」读数（2026-11-23 第 36 轮）

积压清单最后一项是「RTT/健康度」。先核实后端：`src-tauri/src` 里没有 keepalive 计时、没有往返统计、也没有可用来做网络 ping 的命令。要在后端新增真实 RTT，需要一条会真正走 SSH 层的往返测量，而本环境没有可用的服务器可供验证——那种改动只能声称「大概能跑」，不符合本项目的验证标准。

于是换一个同样有用、且能被完整验证的口径：**输入延迟**——从按键送出到远端回显返回的时间。它包含网络往返与远端 shell 的读取与回显，正是远程写命令时能感觉到的那个数。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| 按键送出、回显返回 | 状态栏出现读数（最近 5 次的中位数，整数毫秒） |
| 回显之后命令继续打印 | **不计入**：那不是一个往返 |
| 15 秒没有新的往返 | 读数自行消失，而不是显示一个旧数字 |
| 时钟倒退或间隔超过 60 秒 | 丢弃该样本（休眠、挂起机器） |
| 会话关闭 | 该会话的样本一并清除 |
| 文件会话（SFTP/FTP） | 不显示：没有 shell 回显这回事 |

## 二、实现

| 位置 | 变化 |
| --- | --- |
| `inputLatency.ts`（新） | `InputLatency`：`markSent` / `markOutput` / `reading` / `reset`；中位数、过期、异常间隔；按会话的注册表与订阅 |
| `sessionInput.ts` | 每次真正写出按键后 `markSent(now)`（连接中的字节先缓冲，不计时） |
| `terminal.ts` | `write(bytes)` 的第一批输出 `markOutput(now)`：这是网络输出唯一的汇合点 |
| `StatusBar.tsx` | `useSyncExternalStore` 订阅，快照就是格式化后的字符串（稳定值，React 比较廉价），读数过期时通过定时器重新渲染把它撤下 |
| `terminalRegistry.ts` | `disposeController` 调用 `forgetLatency`，读数不超出会话寿命 |

## 三、为什么叫「输入延迟」而不叫 RTT

回显关闭时（密码输入、全屏程序）远端不会回任何东西：这时没有读数，而不是给出一个错误的数。名字必须与可测量的事实一致。

## 四、验证

| 用例 | 断言 |
| --- | --- |
| `inputLatency.test.ts`（8） | 首个往返 42 ms；只有第一次输出计入；5 个样本取中位数（10/20/30/40/90 → 30）；时钟倒退与 120 秒间隔被丢弃；15 秒后过期；新样本与过期都通知订阅者；注册表按会话隔离、`forgetLatency` 后为空 |
| `typingLatency.browser.test.ts`（1） | 真实键盘输入后**没有**读数（桩不返回），注入回显后出现读数且形如 `12 ms`；文件会话不显示由渲染条件保证 |

## 五、边界

- 不是网络 RTT：不含 TCP/SSH 握手，只在有回显时成立；
- 中位数窗口是 5 个样本，不做分位数曲线；
- 只在状态栏显示，不写日志、不做历史图表；健康度图表留待将来真正有后端往返数据时再做。
