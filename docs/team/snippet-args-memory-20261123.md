# 带参数的常用命令，记得上次填的值（2026-11-23 第 60 轮）

`ssh {{host}}`、`deploy {{env}}` 这类命令每跑一次都要重填一遍参数。本轮记住这个会话里每条命令上次填的值。

## 一、行为

| 情况 | 结果 |
| --- | --- |
| 第一次运行带参数的命令 | 空的参数框，全部填完才能发送（原有行为） |
| 再次运行同一条命令 | 参数框预填上次的值，**立即可以发送** |
| 关掉应用 | 值不保留——它属于这一次坐着干活，不属于保存的命令 |
| 复制出来的副本 | 各记各的：副本是新命令，不继承源的值 |

## 二、判断：为什么只记在内存里

参数值常常是环境名、主机名、一次性代号。把它写进设置会让「保存的命令」带上读者没打算保存的上下文，也会让导出/恢复带上这些值。记在内存里，重启即忘，是更保守也更符合直觉的选择；要固定下来，就把它写进命令本身。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `snippets.browser.test.ts`（15，新增 1） | `deploy {{env}}` 首次填 `prod` 并发送 → 再次打开参数框已预填 `prod`、发送按钮可用 → 直接发送，`write_session` 收到第二次 `deploy prod\r` |

## 四、边界

- 只在同一个应用会话内有效，刷新或重开就清空；
- 只按命令 id 记忆：改名不改 id（原地编辑保留 id），值继续有效；删除后重建是同名新条目，从头开始。
