# 决策记录

## D1：缺陷修复范围

用户要求只修复既有功能。本轮保留当前架构，从输入协议、异步归属和会话生命周期切入；不能以整理代码或相邻需求扩大功能。可疑代码需要触发证据，未复现的疑点不包装成已确认缺陷。

## D2：Pi 的本机兼容修复覆盖真实入口

证据：Pi 1.4.0 的 `package.json` 将 `bin.pi` 指向 `dist/bundle/cli.js`，该入口加载含独立 `TuiAltScreen` 实现的 bundle chunk。旧补丁改动依赖包的 `dist/tui-alt-screen.js`，旧验收启动 `dist/cli.js`，都不能证明 npm 命令生效。

选择：在现有 Windows 兼容脚本中对 SDK 模块及真正加载的 bundle 使用同一启动后钩子，重发鼠标模式。限制版本、入口、源码形状并保留可还原备份；验收依据 npm 声明的命令入口。兼容脚本仍为显式本机修复，不嵌入 EdgeTerm，也不新增 Pi 依赖。

替代方案：强制所有备用屏滚轮转为方向键会把 Pi 事件交给输入编辑器，违背对话滚动目的；EdgeTerm 无法恢复被 ConPTY 消耗且根本未到前端的模式请求。改造整个 PTY 后端代价更大，当前没有支持这种改造的证据。Pi 更新改变启动顺序或 bundle 结构时应重新审查，不能强行套用 1.4.0 补丁。

## D3：输入和授权归属于连接

终端控制器可为保留历史而跨重连复用，控制器寿命不等于连接寿命。剪贴板读取携带连接 revision，连接结束后作废；OSC 52 的单次会话允许在结束或策略变化时清除。全局明确选择“允许”仍按全局策略工作。结束时只清理所属会话的待确认弹窗，其他会话不受影响。

## D4：用户显式按键优先

在 xterm 按键入口先查用户快捷键，再应用 Alt+方向键及 control-H 兼容转换。保留未改绑键的原 Shell 行为。真实 App 浏览器回归同时断言标签动作和没有额外 Shell 写入；仅断言标签切换会漏掉双重执行。

## D5：快速打开区分键盘滚动与指针动作

旧实现用 mouseenter 改选行；方向键滚动让新行来到静止鼠标下方，也会触发 mouseenter，覆盖键盘选择。固定鼠标的真实浏览器用例已复现 file-25 被改为 file-12。改用 mousemove 选行，让实际鼠标移动继续生效，键盘滚动保留自己的选择；不新增输入模式或计时器。

## D6：列宽检查纠正坐标，不改变产品

全量浏览器运行一次出现约 12px 列宽误差。固定预览 iframe 为 0.85 缩放后，旧验收输入稳定出现约 14px 误差：起点经 `pagePoint` 换算，但 80px 距离直接加在外层坐标，实际列内移动超过 80 CSS px。验收辅助函数同时换算距离，缩放反例及原有列宽检查通过。未更改 Filer 的列宽契约，也未放宽 1.5px 断言容差。

## D7：通过 Pi 已有设置控制正常退出输出

退出 Pi 后刷出历史的原生负例，在 Pi 自己的 TUI 日志里出现 640 个历史标记；源码也明确在 `fullscreenExitOutput = transcript` 时切回 regular 并渲染整份对话。因此不应在 EdgeTerm 丢弃终端输出或清空 Shell 历史。采用 Pi 已提供的 `resume-hint`，保存会话并保留恢复命令；本机全局设置已经修改，当前进程需 `/reload`，项目显式设置仍按 Pi 的覆盖规则生效。

验收扩展为正常退出 Pi、等待 Shell 标记、确认鼠标模式释放、两端没有历史回放、保存消息逐项相同。恢复命令直接写 stdout，必须在 PTY 侧核对，不能从 TUI 日志未出现就判为缺失。未发模型请求。没有增加新的 bundle 修补或产品功能。

## D8：资源预算是尽力而为，不是启动前置条件

证据：受限主机（agent 沙箱、容器、部分企业策略）拒绝 `ProcessorAffinity`/优先级调用，旧入口在任务启动前抛错，`doctor` 连同 typecheck、test、build 全部无法运行——诊断入口恰好在最需要它的环境里失效。

选择：affinity 与优先级改为按主机能力尽力而为；拒绝时在 stderr 说明“预算未生效、可能用满整机”，继续执行；`doctor` 用 `cpuMask: unbounded` 与 `priority: unchanged` 如实报告。入口契约用例同时校验“有预算”和“降级且有告警”，不接受静默降级。

替代方案：保持硬失败（在没有沙箱的正常桌面上无害，但让受限环境完全不可用）；静默降级（会让预算承诺失真）。若将来需要在 CI 上强制预算，加一个显式失败开关即可，不需要改回默认硬失败。

## D9：先补可验证的一致性，再谈打包自动化

证据：便携包、诊断包与校验和目前只存在于已停用的 `release.yml` 和人工步骤中；本轮环境无法真实出包（vitest/cargo 也需放宽权限），写一个没人跑过的打包脚本，比缺脚本更危险。

选择：只做能当场验证的事——版本四处一致性的只读守卫、手工发版产物的忽略规则、把真实命令顺序写进发布索引；把“便携包/诊断包脚本”列为已知缺口。

替代方案：直接抽 `release.yml` 的 shell 步骤成 `scripts/package-release.mjs`。未采纳的原因是不能在本轮验证其产物，违背“未经验证的结论不写成事实”。

## D10：面板偏好与显示值分离

证据：`loadPanelSizing()` 返回已按当前窗口 fit 的宽度，`App` 把它当作偏好，挂载 250ms 后就写回 storage；窗口 1000px 时 500/500 被改写成 339/339，放大到 1600px 也回不去，与 App 自己的注释相反。

选择：新增 `loadPanelSizingPreference()`，读取时只做固定范围夹取、不做窗口适配；保存、窗口 resize 后的重新 fit、底栏拖动都以它为准。`fitSides` 与视觉行为不变。

替代方案：延迟或跳过首次保存。只掩盖挂载时的覆盖，窗口缩一次再放大仍会丢偏好。

## D11：Sender 的重复次数只统计真实写入

证据：`ids.length === 0` 的 tick 仍执行 `sent + 1` 与 `times` 判定，`times: 1` 时一个 tick 后就停表并显示 “repeated the command 1 times, done”，而 `writeSession` 一次都没调用；模块此前没有任何测试。

选择：用 `sendUnits` 已有的 `outcome.sent` 判定是否计数；无目标时保持计时（会话可能重连），与“目标被关闭才停表”一致。状态文案同时改走语言目录，与其他 Sender 消息一致。

替代方案：无可写会话就停表。会让断线重连期间的 keepalive 提前结束，代价高于收益。

## D12：本轮基线、范围与三项功能边界（用户确认，2026-11-02）

证据：用户方案基于 `8805e77`，但当前 HEAD `48a12a0` 已多 25 个提交——`onBinary → writeSessionBytes` 已接通（terminal.ts:509 / actions.ts:110），`src/workbench/` 已删除且编辑器迁到 `src/editor/`，因此方案中"补齐二进制输入""删除工作台但要保留编辑器"两条已不适用。

选择：以当前 HEAD 为基线；四项功能全做；只提交不发版；真机不可验项最后列清单交用户复验。

④ 的路径范围只保证 Linux 风格（`File "…", line N`、`path:N`、`path:N:C`、相对路径），Windows 盘符路径不作为验收要求。相对路径归属用"行锚定 cwd → 会话当前 cwd"的顺序回退：解析不出归属时仍尝试会话当前目录，只有文件确实不存在才报错，不弹确认框打断用户（用户明确"体验优先"）。

⑤-B 首版只支持报告同目录的相对资源；`/assets/…` 这类根路径引用不在首版范围。允许把 `hyper`/`hyper-util` 加为直接依赖——两者已在 Cargo.lock（1.11.0 / 0.1.20，经 tauri 传递），不引入新 crate。

替代方案与代价：④ 若严格"无法可靠归属就不开"，会频繁弹确认，违背用户对体验的要求；⑤-B 若支持任意根路径，需要根目录上移与 URL 重写策略，超出首版。


## D13：远程预览的三个落地取舍（2026-11-02）

证据：hyper 的 `server` feature 强制依赖 `httpdate`（Date 头），因此本轮 Cargo.lock 新增一条传递依赖；`PreviewSession` 只回传 id/url/root/port，不回传 owner 与报告路径；文件链接的归属目录在历史输出里只能靠行锚定推断。

选择：
1) 接受 `httpdate 1.0.3`（纯 Rust、约 5 KB、无系统依赖），不为单一 Date 头手写 HTTP/1.1。
2) 前端用一个本窗口的 `(sessionId, 报告路径) → PreviewSession` 映射记录自己启动的预览（`previewActions.ts`），Filer 菜单据此显示"停止预览"；跨窗口或重启后的预览仍由 Rust 注册表持有，前端不猜测。
3) 文件链接的相对路径按"该行输出时的锚定 cwd → 会话当前 cwd → 状态栏报错"顺序尝试；读取即验证，成功才开编辑器，避免空壳与确认弹窗（用户要求体验优先）。

替代方案与代价：给 PreviewSession 补 owner/report 可以让前端完全无状态，但会改动 Rust 契约且不影响行为；严格"锚定不到就报错"更保守，但会在长会话历史里频繁打断用户。
