# 决策记录

## D1：缺陷修复范围

用户要求只修复既有功能。本轮保留当前架构，从输入协议、异步归属和会话生命周期切入；不能以整理代码或相邻需求扩大功能。可疑代码需要触发证据，未复现的疑点不包装成已确认缺陷。

## D2：Pi 的本机兼容修复覆盖真实入口

证据：Pi 1.4.0 的 `package.json` 将 `bin.pi` 指向 `dist/bundle/cli.js`，该入口加载含独立 `TuiAltScreen` 实现的 bundle chunk。旧补丁改动依赖包的 `dist/tui-alt-screen.js`，旧验收启动 `dist/cli.js`，都不能证明 npm 命令生效。

选择：在现有 Windows 兼容脚本中对 SDK 模块及真正加载的 bundle 使用同一启动后钩子，重发鼠标模式。限制版本、入口、源码形状并保留可还原备份；验收依据 npm 声明的命令入口。兼容脚本仍为显式本机修复，不嵌入 EdgeTerm，也不新增 Pi 依赖。

替代方案：强制所有备用屏滚轮转为方向键会把 Pi 事件交给输入编辑器，违背对话滚动目的；EdgeTerm 无法恢复被 ConPTY 消耗且根本未到前端的模式请求。改造整个 PTY 后端代价更大，当前没有支持这种改造的证据。Pi 更新改变启动顺序或 bundle 结构时应重新审查，不能强行套用 1.4.0 补丁。

## D3：输入和授权归属于连接

终端控制器可为保留历史而跨重连复用，控制器寿命不等于连接寿命。剪贴板读取携带连接 revision，连接结束后作废；OSC 52 的单次会话允许在结束或策略变化时清除。全局明确选择“允许”仍按全局策略工作。结束时只清理所属会话的待确认弹窗，其他会话不受影响。

## D4：用户显式按键优先

在 xterm 按键入口先查用户快捷键，再应用 Alt+方向键及 control-H 兼容转换。保留未改绑键的原 Shell 行为。真实 App 浏览器回归同时断言标签动作和没有额外 Shell 写入；仅断言标签切换会漏掉双重执行。

## D5：快速打开区分键盘滚动与指针动作

旧实现用 mouseenter 改选行；方向键滚动让新行来到静止鼠标下方，也会触发 mouseenter，覆盖键盘选择。固定鼠标的真实浏览器用例已复现 file-25 被改为 file-12。改用 mousemove 选行，让实际鼠标移动继续生效，键盘滚动保留自己的选择；不新增输入模式或计时器。

## D6：列宽检查纠正坐标，不改变产品

全量浏览器运行一次出现约 12px 列宽误差。固定预览 iframe 为 0.85 缩放后，旧验收输入稳定出现约 14px 误差：起点经 `pagePoint` 换算，但 80px 距离直接加在外层坐标，实际列内移动超过 80 CSS px。验收辅助函数同时换算距离，缩放反例及原有列宽检查通过。未更改 Filer 的列宽契约，也未放宽 1.5px 断言容差。

## D7：通过 Pi 已有设置控制正常退出输出

退出 Pi 后刷出历史的原生负例，在 Pi 自己的 TUI 日志里出现 640 个历史标记；源码也明确在 `fullscreenExitOutput = transcript` 时切回 regular 并渲染整份对话。因此不应在 EdgeTerm 丢弃终端输出或清空 Shell 历史。采用 Pi 已提供的 `resume-hint`，保存会话并保留恢复命令；本机全局设置已经修改，当前进程需 `/reload`，项目显式设置仍按 Pi 的覆盖规则生效。

验收扩展为正常退出 Pi、等待 Shell 标记、确认鼠标模式释放、两端没有历史回放、保存消息逐项相同。恢复命令直接写 stdout，必须在 PTY 侧核对，不能从 TUI 日志未出现就判为缺失。未发模型请求。没有增加新的 bundle 修补或产品功能。

## D8：资源预算是尽力而为，不是启动前置条件

证据：受限主机（agent 沙箱、容器、部分企业策略）拒绝 `ProcessorAffinity`/优先级调用，旧入口在任务启动前抛错，`doctor` 连同 typecheck、test、build 全部无法运行——诊断入口恰好在最需要它的环境里失效。

选择：affinity 与优先级改为按主机能力尽力而为；拒绝时在 stderr 说明“预算未生效、可能用满整机”，继续执行；`doctor` 用 `cpuMask: unbounded` 与 `priority: unchanged` 如实报告。入口契约用例同时校验“有预算”和“降级且有告警”，不接受静默降级。

替代方案：保持硬失败（在没有沙箱的正常桌面上无害，但让受限环境完全不可用）；静默降级（会让预算承诺失真）。若将来需要在 CI 上强制预算，加一个显式失败开关即可，不需要改回默认硬失败。

## D9：先补可验证的一致性，再谈打包自动化

证据：便携包、诊断包与校验和目前只存在于已停用的 `release.yml` 和人工步骤中；本轮环境无法真实出包（vitest/cargo 也需放宽权限），写一个没人跑过的打包脚本，比缺脚本更危险。

选择：只做能当场验证的事——版本四处一致性的只读守卫、手工发版产物的忽略规则、把真实命令顺序写进发布索引；把“便携包/诊断包脚本”列为已知缺口。

替代方案：直接抽 `release.yml` 的 shell 步骤成 `scripts/package-release.mjs`。未采纳的原因是不能在本轮验证其产物，违背“未经验证的结论不写成事实”。

## D10：面板偏好与显示值分离

证据：`loadPanelSizing()` 返回已按当前窗口 fit 的宽度，`App` 把它当作偏好，挂载 250ms 后就写回 storage；窗口 1000px 时 500/500 被改写成 339/339，放大到 1600px 也回不去，与 App 自己的注释相反。

选择：新增 `loadPanelSizingPreference()`，读取时只做固定范围夹取、不做窗口适配；保存、窗口 resize 后的重新 fit、底栏拖动都以它为准。`fitSides` 与视觉行为不变。

替代方案：延迟或跳过首次保存。只掩盖挂载时的覆盖，窗口缩一次再放大仍会丢偏好。

## D11：Sender 的重复次数只统计真实写入

证据：`ids.length === 0` 的 tick 仍执行 `sent + 1` 与 `times` 判定，`times: 1` 时一个 tick 后就停表并显示 “repeated the command 1 times, done”，而 `writeSession` 一次都没调用；模块此前没有任何测试。

选择：用 `sendUnits` 已有的 `outcome.sent` 判定是否计数；无目标时保持计时（会话可能重连），与“目标被关闭才停表”一致。状态文案同时改走语言目录，与其他 Sender 消息一致。

替代方案：无可写会话就停表。会让断线重连期间的 keepalive 提前结束，代价高于收益。

## D12：本轮基线、范围与三项功能边界（用户确认，2026-11-02）

证据：用户方案基于 `8805e77`，但当前 HEAD `48a12a0` 已多 25 个提交——`onBinary → writeSessionBytes` 已接通（terminal.ts:509 / actions.ts:110），`src/workbench/` 已删除且编辑器迁到 `src/editor/`，因此方案中"补齐二进制输入""删除工作台但要保留编辑器"两条已不适用。

选择：以当前 HEAD 为基线；四项功能全做；只提交不发版；真机不可验项最后列清单交用户复验。

④ 的路径范围只保证 Linux 风格（`File "…", line N`、`path:N`、`path:N:C`、相对路径），Windows 盘符路径不作为验收要求。相对路径归属用"行锚定 cwd → 会话当前 cwd"的顺序回退：解析不出归属时仍尝试会话当前目录，只有文件确实不存在才报错，不弹确认框打断用户（用户明确"体验优先"）。

⑤-B 首版只支持报告同目录的相对资源；`/assets/…` 这类根路径引用不在首版范围。允许把 `hyper`/`hyper-util` 加为直接依赖——两者已在 Cargo.lock（1.11.0 / 0.1.20，经 tauri 传递），不引入新 crate。

替代方案与代价：④ 若严格"无法可靠归属就不开"，会频繁弹确认，违背用户对体验的要求；⑤-B 若支持任意根路径，需要根目录上移与 URL 重写策略，超出首版。


## D13：远程预览的三个落地取舍（2026-11-02）

证据：hyper 的 `server` feature 强制依赖 `httpdate`（Date 头），因此本轮 Cargo.lock 新增一条传递依赖；`PreviewSession` 只回传 id/url/root/port，不回传 owner 与报告路径；文件链接的归属目录在历史输出里只能靠行锚定推断。

选择：
1) 接受 `httpdate 1.0.3`（纯 Rust、约 5 KB、无系统依赖），不为单一 Date 头手写 HTTP/1.1。
2) 前端用一个本窗口的 `(sessionId, 报告路径) → PreviewSession` 映射记录自己启动的预览（`previewActions.ts`），Filer 菜单据此显示"停止预览"；跨窗口或重启后的预览仍由 Rust 注册表持有，前端不猜测。
3) 文件链接的相对路径按"该行输出时的锚定 cwd → 会话当前 cwd → 状态栏报错"顺序尝试；读取即验证，成功才开编辑器，避免空壳与确认弹窗（用户要求体验优先）。

替代方案与代价：给 PreviewSession 补 owner/report 可以让前端完全无状态，但会改动 Rust 契约且不影响行为；严格"锚定不到就报错"更保守，但会在长会话历史里频繁打断用户。

## D14：A2 终端冷存储的四个落地取舍（用户确认，2026-11-07）

证据：A1/W2 基线（快照校准，docs/team/STATE.md 2026-11-07）——xterm 6.0 每行急切分配 `Uint32Array(cols×3)`，真实内存 = JS 堆 ~205–240 B/行 + rows×cols×12，与内容形态无关；20 个 10k 行标签 ≈234 MB，1M×200 列单标签 ≈2.6 GB。对应路线图 §6 维护者问题 1–3 与 9。

选择（用户 2026-11-07 逐项确认）：
1) 冷历史仅内存（§6-1）：不落盘；A3 的加密落盘不在本轮范围。
2) 上限默认：会话 64 MB 压缩数据或 100 万行先到为准，全局 256 MB，超限丢弃最旧块并提示（§6-2 建议值）。
3) 历史展示**必须无缝滚动**（§6-3 选了路线图列为 A4 的高风险项而非第一版独立只读视图）——xterm 6 能否在顶部前置历史行成为与"裁剪前导出"并列的高危假设，可行性 spike 提前；若证伪，带证据回报用户重选形态。
4) 块压缩引入 `lz4_flex` 直接依赖（§6-9），版本随 Cargo.lock 固定。

替代方案与代价：独立只读视图工作量小、风险低（路线图第一版方案），但用户明确要无缝；zstd 压缩率更好但 C 绑定与"<5 MB 安装包"卖点冲突；flate2 零新依赖但解压速度不适合交互式搜索解块，未被选择。

## D15：视觉验收用测量门禁，不设 24px 一刀切（2026-11-22）

证据：真实 Chromium 测量发现 shell 有 4 处指针目标不合格（面包屑 `/` 仅 5×15、折叠行 196×14 等），另有 1 处 light 主题对比度 4.21:1；同一份测量也把 11px 的 sash 命中区、`sr-only` 文本误报为缺陷。若按"所有控件 ≥24px"一刀切，会把设计上合格的紧凑工具条与已实现间距例外的控件也判坏。

选择：门禁实现 WCAG 2.2 SC 2.5.8 的间距例外（以控件为中心的 24px 圆不与其它目标相交即通过），另设 16px 可用性下限单独报告；label 包裹的输入框按标签计；`sr-only` 与拖拽 sash 的 `:after` 命中区显式豁免并在测试中写明理由。门禁必须带负向控制：同一棵刚通过的树注入旧盒子模型后必须报错，否则"全空"没有意义。

替代方案：把阈值降到 20px 换取全绿——拒绝，它会让 5px 的面包屑继续通过；或对全部控件强制 24px——拒绝，会破坏四套主题既定的紧凑密度与真实间距例外。

## D16：层叠阶梯只覆盖共享 app 根堆叠上下文的浮动层（2026-11-22）

证据：全库 24 条 `z-index` 中多数位于组件自己的堆叠上下文（标签条内部、FTP 面板内部、对话框内部），对它们做全局编号既无收益也易误改；真正互相竞争的是共享 app 根上下文的浮动层，其中拖拽幽灵与状态浮层同为 1000。

选择：新增 `--z-menu/--z-drop/--z-hud/--z-popover/--z-drag/--z-dialog` 并只替换这五类浮动层（拖拽幽灵改为 1001）。组件内部的 z-index 保留局部语义，不纳入全局阶梯。

替代方案：把全部 24 条 z-index 收进一张全局表——拒绝，组件内部的层序应由该组件自己维护，跨文件编号会把局部实现细节固化成公共契约。

## D17：命令面板复用既有命令表，不新增第二套定义（2026-11-22）

证据：快捷键表 `SHORTCUT_COMMANDS` 已有 19 条命令的动作、标签、说明与可改键绑定；菜单、快捷键设置、终端键过滤都读同一张表。另建一份面板命令表会让标签、键位与"实际能执行什么"三处漂移，也让"可改键"只覆盖其中一处。

选择：面板目录由既有表 + store 快照（面板、标签、会话、主题）+ 设置对话框回调构建；标签复用菜单与快捷键消息键；命令以注入回调执行，模块保持纯函数。`commandPalette` 本身进入快捷键表（Ctrl+Shift+P / ⇧⌘P），因此自动出现在快捷键设置里并可改键；View 菜单顶部再加一条带键位提示的入口。面板不把自己列为候选行。

替代方案：独立的面板命令清单（可自由命名、不必可改键）——拒绝，它会把"入口收敛"变成第三套真相；只保留快捷键、不加菜单入口——拒绝，没有可发现性的功能等于没有。

## D18：检索用排序阶梯 + 唯一分组标题，最近使用只做加权（2026-11-22）

证据：浏览器实测暴露两类问题——只按"相邻同组"分组会让 Actions 标题出现三次、并因重复 React key 留下陈旧行；页脚计数与可见行数因此不一致。

选择：
1. 匹配分数从高到低为 完全相等 > 前缀 > 词首 > 子串 > 子序列，命中后加最近使用加权；同分按目录顺序，保证结果稳定。
2. 每条命令带英文标签作为隐藏检索词，中文界面可以用英文搜索。
3. 一个分组只出现一次标题：空查询按目录分组顺序，检索时按各分组最佳匹配排序；列表的扁平顺序是方向键、`aria-activedescendant` 与页脚计数的唯一来源。
4. 最近使用只加权、不单独分组：避免同一命令在"最近"和原分组里出现两次，也避免空查询时把目录顺序打乱。

替代方案：检索时展平成一个无标题列表（更接近纯相关度）——保留分组，因为它让"这个面板里都有什么"在输入前就能读懂；把最近使用做成独立分组——拒绝，重复条目比一点加权更让人困惑。

## D19：键盘焦点用真实聚焦 + 计算样式差验收，并接受祖先承担焦点指示（2026-11-22）

证据：真实 Chromium 中，程序化聚焦只有在一次真实 Tab 建立键盘模态后才匹配 `:focus-visible`；焦点环常带 80–120ms 过渡，同步快照会读到 `oklab` 插值中间值；`aria-activedescendant` 列表的行 `tabIndex=-1`，不是焦点停靠点。三条任一处理错都会产生假缺陷或假通过。

选择：
1. 扫查依次做"真实 Tab → 冻结过渡 → 逐个聚焦 → 比较元素与两级祖先的 10 个可见属性"，并只评 `focus()` 后 `document.activeElement` 真的命中者。
2. 允许祖先承担焦点指示（整行高亮、容器环），所以比较链包含两级祖先；不要求每个控件自己画环。
3. 每条扫查都要有负向控制：中和一个已知焦点样式后必须报错，否则"全绿"无意义。
4. 不为"看起来像控件"的元素补焦点样式：先确认它是否真是 Tab 停靠点（行不是，容器是）。

替代方案：静态检查 CSS 里有没有 `:focus-visible` 规则——拒绝，规则存在不等于可见（被更高优先级覆盖、变量失效、颜色与背景相同都会失效）；只测计算样式而不建立键盘模态——会漏掉所有依赖 `:focus-visible` 的控件。

## D20：同步输入按"常驻可见、随时可关、绝不自动恢复"设计（2026-11-22）

证据：一次误键入会同时写进多台生产机，这是全应用爆炸半径最大的模式。竞品的做法（Xshell Synchronized Input、SecureCRT 发送到所有会话）都把开关放在显眼位置；而"上次退出时还是开的"是所有此类事故的共同前提。

选择：
1. 目标规则做成纯函数：仅已连接、非文件会话；源会话不重复写入。
2. 开启条件在 store 里判断：没有第二个可接收会话时拒绝并说明原因；开/关都写状态栏。
3. 状态栏常驻 warning 墨色指示 + 接收会话数，**指示即关闭按钮**。
4. **不持久化**；最后一个接收方消失时自动关闭。
5. 源会话握手期只进待发缓冲，不向其它会话广播；xterm 的协议应答（DA/DSR/CPR/XTVERSION/DCS）不进广播。

替代方案：跟随偏好持久化（"我上次就是这么用的"）——拒绝，破坏性模式必须每次显式进入；放进标签栏按钮——拒绝，标签栏只在溢出时出现动作区，且可见性取决于滚动状态，不适合安全开关。

## D21：对话框与 shell 共用同一套测量门禁，并要求"证明看见过"（2026-11-22）

证据：会话/设置/快捷键/关于是使用者一年只打开几次、却承载最危险操作（改设置、清快捷键、导入配置）的表面；空树审计会给出毫无意义的全绿。

## D22：焦点指示器按颜色验收（3:1），不确定就计数（2026-11-22）

证据：焦点环与表面同色时（1:1），所有计算属性都变化，键盘用户却看不见；第 3 轮的变化式收集器对此无能为力。

选择：
1. 增加 `focusRingContrastIssues`：聚焦后读 outline 颜色，按 offset 符号选元素自身或父级表面，低于 3:1 报缺陷。
2. 只测 outline。box-shadow 环可能是内嵌、扩散、多层或光晕，重建其实际颜色是猜测；一律计入 `indeterminate` 并在报告中给出数量。
3. 每个通过必须同时满足：有可见变化（第 3 轮）+ 环 ≥3:1（本轮）+ inspected 数量下限；三者缺一即不通过。
4. 每条门禁都要有能失败的负向控制：把环设成表面色，必须报错。

## D23：命令输出复制以 marker 区间为准，空输出不清空剪贴板（2026-11-22）

证据：xterm 的 `selectLines(start, end)` 两端都是 0 基闭区间；行号在回滚裁剪和历史前置后会指向别的内容；空文本写入会把用户刚复制的东西抹掉。

3. 空输出返回 false 并给出状态栏说明，不写剪贴板。
4. 命令面板中两条命令的标签必须自身可区分（"…Output" / "…Line"），不依赖排序决定 Enter 命中哪一条。

## D24：命令导航从上次落点继续，且同一时刻只有一个落点底纹（2026-11-22）

## D25：命令标记画在行号栏，且每帧只读一次集合（2026-11-22）

## D26：行间距作为离散档位的全局偏好，默认保持既有渲染（2026-11-22）

3. 应用路径与字号相同：隐藏时暂存、显示时落地，然后 `refreshFontMetrics()`。
4. 全局偏好，不按标签；与字号、字体家族一致。

## D103 — 命令行面板里「什么算一个连接目标」

**决定**：目标必须自己说出来——有 `@`、有端口、主机名带点，或方括号地址；否则当成搜索短语。

**为什么**：搜索框同时是目标框。第一版把任何单词都解析成主机，搜索 `zzzz` 时本该出现的「没有匹配」被一行「连接到 zzzz」顶掉，既有空状态用例当场失败。

## D104 — 「最近连接过」是偏好，不是会话

**决定**：只记标签（`root@host:22`），上限 4 条、重复前移，存在已注册的偏好键 `edgeterm.quickConnect.recents`；作为普通命令参与**排序**，不硬插到列表最前面。

**为什么**：置顶会被面板的分组渲染覆盖（动作组在前），而随排序走既不打断分组结构，输入 `10.0.` 这类非目标片段也能搜到。记标签不记资料，是因为它只服务于「再连一次」，不是会话档案。

## D105 — 记住的主机只有一个写者

**决定**：列表放在 store（`quickConnectRecents` + `rememberQuickTarget`），命令行面板与终端 `ssh://` 链接都调用同一个动作。

**为什么**：第二个入口（`actions.ts`）拿不到 App 的局部状态，曾出现「从面板连的会记住、从链接点开的不记」。传回调只会把状态维护成两份。

## D106 — 给 xterm 插件的 `urlRegex` 不能自带 `g`

**决定**：`SSH_URI_REGEX` 用 `/ssh:\/\/[^\s"<>]+/i`，并配守卫用例断言 `global === false`。

**为什么**：`WebLinksAddon` 会拼 `new RegExp(source, flags + "g")`；自带 `g` 得到 `gig` 并抛出，而且抛在链接提供者里，连带弄坏同一终端上的文件链接。

## D107 — 未使用的导出怎么处理

**决定**：只编译的负控制（`checkGeneratedContract`）与生成文件的类型保留；无调用点的普通导出删除；有诊断价值但没人调用的工具（`styleCensus`）接进视觉门，变成不变量。

**为什么**：死代码让读者花时间判断它是否还活着；而「写出来却没人调用」的诊断工具等于不存在——它的价值取决于有没有门在使用它。
## D108 — 空窗口的最近会话复用既有条目结构

**决定**：关掉所有标签后的空窗口，用既有 `.term-empty-entry` 结构列出最多 3 个最近用过的已保存会话；空状态整体作为滚动容器（`.term-empty { overflow: auto }`），不为其单独新增样式或高度上限。

**为什么**：新增结构会带来新的字阶、圆角与配色，需要再过一遍视觉普查；而空状态本来就放不下时可以整体滚动，条目在 378×465 / 18px 的实测尺寸下依然可达。

## D110 — 会话树的 type-ahead 规则

**决定**：树有焦点时，无修饰键的可打印字符触发跳转；同一段 600ms 内的输入收窄同一次搜索；搜索从当前行之后开始并环绕；只匹配会话行；无匹配时什么都不动，且按键不滚动页面。带修饰键的按键与 `/` 继续走既有路径。

**为什么**：树里找机器是高频动作，方向键太慢；而参与标题与组名会让「敲 l 跳到 Lab box」变得不可预测。缓冲区放在组件内、不持久化，是因为它描述的是此刻的搜索，不是偏好。

**已知边界**：输入法组合期间的按键按可打印字符处理，中文名暂不能靠拼音首字母跳转。
