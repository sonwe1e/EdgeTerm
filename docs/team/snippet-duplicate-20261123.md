# 常用命令可以复制一份再改（2026-11-23 第 59 轮）

读者想要的常常是「照这条改一条」，不是「从头再打一条」。此前只能新建，然后手动重打命令。

## 一、行为

| 动作 | 结果 |
| --- | --- |
| 点行内「复制」按钮 | 生成同名加 `copy` 后缀的新条目，命令相同，原条目一个字都不动 |
| 名字已被占用 | 依次试 `X copy`、`X copy 2`、`X copy 3`…，第一次就找到空位 |
| 名字等于上限 | 结果裁到 `MAX_NAME_LENGTH` 以内 |

## 二、两条判断

1. **复制不能覆盖源**：名字是查找与「再保存即替换」的键，复制若占了源的名字，等于悄悄改掉读者以为没被动过的那条。`copyName` 只会返回空名字。
2. **大小写不敏感**：与既有的名字查找一致，`logs COPY` 也算占用。

## 三、验证

| 用例 | 断言 |
| --- | --- |
| `snippets.test.ts`（12，新增 4） | 空位得到 `Logs copy`；被占则 `Logs copy 2`、`Logs copy 3`；大小写不敏感；超长名字裁到上限 |
| `snippets.browser.test.ts`（14，新增 1） | 点复制后 store 里是 `Logs` 与 `Logs copy` 两条，命令相同，原条目仍在 |

## 四、边界

- 复制不打开编辑表单，只给出一条可继续改的副本；要改就点它的编辑按钮；
- 复制不发送任何命令。
## 五、更正（第 64 轮）：当时「绝不覆盖源」这句话是错的

第 59 轮的 `copyName` 是**先拼后缀、再裁到上限**。名字本身已经用满 60 个字符时，`"X…X copy"` 裁回 60 位正好等于原名——`saveSnippet` 按名字覆盖，于是「复制」把**源条目改成了副本的内容**。当时的单测只断言长度不大于上限，没断言结果与既有名字不同，所以它通过了。

一个独立的负向对照复现了这条老逻辑：

```
old: "xxxxxxxx…x"（60 个 x）  overwrites source: true
new: "xxxxxxxx…x copy"（60 字符）distinct: true
```

修法：按后缀长度**先缩短词干**再拼后缀，后缀永不被裁掉；并在所有计数都用尽后继续计数，而不是交回一个已占用的名字。新增两条单测（60 字符名、连续 4 个副本）与一条浏览器用例（界面上点复制后是**两条**条目）。
