# 复制命令的快捷键（2026-11-22 第 14 轮）

第 7 轮的两条复制命令此前只能从 Edit 菜单与命令面板调用——对键盘用户等于不存在；而且命令面板里是**手写的第二份定义**。本轮把它们并入快捷键表，于是：

| 命令 | 和弦（可改键） |
| --- | --- |
| 复制上一条命令的输出 | `Ctrl+Shift+O` / `⇧⌘O` |
| 复制上一条命令行 | `Ctrl+Shift+L` / `⇧⌘L` |

- 快捷键对话框、命令面板、Edit 菜单现在显示**同一个和弦**；
- 命令面板里的手写条目删除，面板条目由快捷键表生成——一份定义，一个动作；
- 两个和弦都不是控制字节，shell 收不到任何输入（O=output，L=line）。

## 一、验证

- 单元：快捷键表相关的既有用例（全部命令有默认值、和弦不冲突、可改键）通过。
- 真实浏览器：新用例按 `Ctrl+Shift+O`，剪贴板得到上一条命令的输出、状态栏显示"Copied to the clipboard"，并断言 **shell 没有收到任何字节**（记录型 IPC 的 `write_session` 为空）——只断言剪贴板会放过"把控制字符写进会话"的实现。
- 全量：前端单测 175 文件／1725 用例、浏览器契约 49 文件／243 用例、typecheck、format:check（526 文件）、lint（仅生成绑定 2 条既有警告）、生产构建全部通过。

## 二、同一轮的覆盖补齐

状态栏弹层此前只测了正常态。本轮补上**失败态**：

| 弹层 | 数据 | 断言 |
| --- | --- | --- |
| Transfer Center | `status: failed`，error "permission denied"，失败文件列表 | 失败原因可见 + 三套门禁零缺陷 |
| Forward Center | `status: error`，error "bind: address already in use" | 错误行可见 + 三套门禁零缺陷 |

两种失败态都没有新的缺陷（第 12 轮修掉的两处尺寸问题已在正常态覆盖），所以本轮只增加了覆盖，没有追加修复——如实记录。

## 三、边界

- 和弦可改键；改键后菜单与面板同步显示。
- 没有已结束命令时，两条命令给出状态栏说明而不是静默（第 7 轮行为不变）。
- 失败态只覆盖传输与隧道两类弹层，不含资源监视弹层。
