# 同步输入（广播）（2026-11-22 第 4 轮）

目标：补上运维场景里最常用、而本仓库完全没有的能力。Xshell 的 Synchronized Input、SecureCRT 的"发送到所有会话"、Termius 的广播输入都是同一件事：一条命令同时送进多台机器。

## 一、规则（[broadcast.ts](../../src/broadcast.ts)）

只把字节送到"确实能接收"的会话，规则集中在一个纯函数里：

| 条件 | 结果 |
| --- | --- |
| 源会话自身 | 永不重复写入（它走原来的路径） |
| `state !== "connected"` | 跳过（connecting/closed/error 没有可写的远端） |
| 文件会话（SFTP/FTP） | 跳过（那是浏览器，不是 shell） |
| 其它 SSH / 本地 / 串口 / telnet | 接收 |

**协议应答也跳过**：xterm 的 DA、DSR、CPR、XTVERSION 与 DCS 应答和键入走同一条 `onData` 通道；不过滤的话，一个面板对程序查询的应答会被灌进所有其它 shell。`isTerminalResponse` 只匹配固定的协议报告形态（方向键 `\x1b[A` 这类键入不会命中），并有专门的"不得误判键入"用例。

## 二、安全的形状（交互细节）

同步输入是全应用里爆炸半径最大的模式，所以它的交互按"永远看得见、随时能关、绝不背着用户恢复"设计：

- **开关的判断在 store**（[storeBroadcastActions.ts](../../src/storeBroadcastActions.ts)）：没有第二个可接收会话时拒绝开启，并在状态栏说明原因；开启/关闭都回报结果。
- **状态栏常驻指示**（warning 墨色 + 广播图标 + 接收会话数），**指示本身就是关闭按钮**；点一下就退出该模式。
- **不持久化**：重启后绝不自动恢复。破坏性模式不能靠"上次是开的"重新武装。
- **自动关闭**：最后一个接收方消失（关标签、断线、切到文件会话）时自动退出并回报。
- **握手期不广播**：源会话还在 connecting 时，键入仍进入原来的待发缓冲，不会先发给别人。

## 三、入口

| 入口 | 行为 |
| --- | --- |
| `Ctrl+Shift+B` / `⇧⌘B` | 进入可改键的快捷键表，快捷键对话框自动列出 |
| Session 菜单 | 可勾选项，勾选状态与状态栏一致 |
| 命令面板 | 从同一张快捷键表生成，可搜"Broadcast"或"广播" |

## 四、验证

- 单元 12 条：目标筛选五种排除、应答过滤（含"键入不得误判"）、输入漏斗（关闭只写源、开启写全部、握手期只缓冲不广播、文件/断开目标排除）、store 守卫（拒绝/理由/自动关闭前提）。
- 真实浏览器 3 条：[broadcast.browser.test.ts](../../src/test/broadcast.browser.test.ts) 用真实 xterm 与记录型 IPC — 一次键入必须同时到达两个 shell、关掉后另一侧不再收到、没有第二会话时拒绝开启、最后一个接收方消失后自动关闭。
- 全量：前端单测 173 文件／1715 用例、浏览器契约 44 文件／223 用例、typecheck、format:check（516 文件）、lint（仅生成绑定 2 条既有警告）、生产构建全部通过。

## 五、边界

- 只在 Chromium + 受控 IPC 下验证；没有对真实服务器验证"同一命令在两端的行为差异"。
- 广播目标是"所有可接收会话"，暂不支持按面板分组只发给其中几台（Xshell 可按标签组）；这是下一轮候选。
- 协议应答过滤按固定形态精确匹配；未知的厂商私有报告不会被识别为应答（会被当作键入广播），属于已知边界。
