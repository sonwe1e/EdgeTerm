# 筛选属于它所在的文件夹；被筛掉的行不再保持选中（2026-11-23 第 71 轮）

上一轮加了筛选，但留下两个语义问题：

1. **切换目录后筛选还在**：读者进到新目录，看到的是一个被旧关键词过滤过的列表，而他并没有要求过。
2. **被筛掉的行仍处于选中状态**：全选三行再筛选，选中集里仍有看不见的文件；此后一次删除或移动就会作用在读者看不到的文件上。

## 一、交付（两处）

| 位置 | 变化 |
| --- | --- |
| 目录变化 | `useEffect` 在 `path` 改变时清空筛选：筛选属于输入它的那个文件夹 |
| 筛选内容变化 | 改变筛选值时清空选择：看不见的行不该留在选中集里 |

## 二、验证

| 行为 | 证据 |
| --- | --- |
| 筛掉的行不再保持选中 | `filerSelection.browser.test.ts`：先选中 `file1.txt`，输入 `file999` 后选中集为空 |
| 切目录后筛选清空 | `filerFilterNavigation.browser.test.ts`（第 72 轮补齐）：自有 mock 的 `/root` → `/root/sub`；筛成 `1 of 2` 后双击目录进入，新目录列出 `b.txt` 且筛选值为空 |

第 71 轮在这里写下的「未覆盖」已在第 72 轮补上。当时失败的原因不在产品：新用例被放进已有夹具文件时，用路径编辑框导航会把该文件后续用例拖进超时；换成一个**只有一条用例、自有 mock** 的文件后，同一条行为一次通过。

## 三、边界

- 清空选择只在筛选值真的改变时发生；在筛选框里按 `Esc` 清空同样会改变值，因此也会清空选择（与「筛选变化」一致）。
- 目录内容变化（刷新）不清空筛选：读者仍在同一个目录里。
