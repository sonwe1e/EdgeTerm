# 瞬态标记跟随会话状态（2026-11-23 第 41 轮）

上一轮补标题清理时发现的是同一类问题：两个新加的「瞬态指示」都不看会话状态——关闭的会话仍然显示最后一个程序标题，带铃铛的标签即使会话已关闭也继续挂徽标。

## 一、修正

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| 状态栏标题项 | 只要 `tab.remoteTitle` 存在就显示 | 仅 `tab.state === "connected"` 时显示 |
| 标签铃铛徽标 | 只要 `tab.attention` 就显示 | 关闭（`closed`）的标签不再显示 |

判断依据：这些都是「这一次连接」的事实。会话断开后，`vim` 早就不在了，铃铛也不会有人来应——留着就是让读者去确认一个已经不存在的东西。

## 二、验证

| 用例 | 断言 |
| --- | --- |
| `remoteTitle.browser.test.ts` 新增 1 条 | 连接时显示 `vim notes.txt`；把标签置为 `closed` 后状态栏该项为空 |
| `tabBell.browser.test.ts` 新增 1 条 | 带 `attention` 但已 `closed` 的标签不出现 `.tab-bell` |

两条都是**先构造成因、再断言结果**：前者真实写入 OSC 标题后才关闭，后者直接构造带徽标状态的已关闭标签。

## 四、边界

- 只按 `connected` 判定；`connecting` 时标题本就为空，`error` 时状态栏已被错误提示占据；
- 铃铛只对 `closed` 隐藏；`error` 标签仍显示徽标（错误状态本身已有红色指示，二者并存不冲突）。
