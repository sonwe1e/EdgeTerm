# OpenCode 多标签性能测试记录

## 2026-10-28：长会话滚动与标签切换

在 Windows 11 26300、WebView2 156、i7-13700KF、RTX 4090 驱动
32.0.16.2101 上，使用本机 OpenCode 2.2.0、真实 ConPTY 和独立的本地
OpenCode 服务测试。窗口内容区域为 1441×901 CSS 像素，EdgeTerm 使用默认
GPU 设置。测试启动的 EdgeTerm 和服务进程限制在 4 个逻辑 CPU 并设为较低
优先级；测试期间没有运行构建或其他测试。

会话是导入的合成数据，不含用户会话，也没有调用模型：短会话 16 条，长会话
480 条（240 组问答，包含段落、列表和代码）。8 个 EdgeTerm 标签分别运行独立
的 OpenCode 客户端，其中 7 个打开相同的长会话；服务端和测试项目均使用独立
数据目录。短会话、2 标签长会话和 8 标签长会话各发送 30 次向上滚轮并检查画面
变化，再滚回；8 标签按顺序切换 3 轮。每次切换样本包括 Playwright 快捷键派发、
确认选中标签以及等待两个动画帧，并非按键到像素呈现的端到端延迟。

优化前使用本次修改之前的工作区构建，已包含此前的终端优化；优化后为本次工作区
构建。旧版与中间方案交替测试各两次，补齐选区与同步绘制处理后，最终版连续测试
两次；每次使用新的便携数据目录。样本很少，且第一次旧版切换明显更慢，不能把
单次百分比当作稳定收益。

| 构建与顺序 | 切换中位数 | 切换 95 分位 | 切换最大值 | 前端长任务 |
| --- | ---: | ---: | ---: | ---: |
| 旧版 1 | 160.1 ms | 459.3 ms | 568.0 ms | 0 |
| 旧版 2 | 58.2 ms | 66.4 ms | 66.6 ms | 0 |
| 最终版 1 | 41.7 ms | 73.6 ms | 78.1 ms | 0 |
| 最终版 2 | 41.8 ms | 79.4 ms | 83.2 ms | 0 |

每行只有 24 个切换样本，95 分位尤其容易受单次开销影响。滚轮阶段四轮的动画帧
间隔 95 分位为 8.4–8.5 ms，均未观察到超过 50 ms 的前端长任务；这不代表滚轮
输入到 OpenCode 内容呈现的延迟，也不能排除 OpenCode 自身或其他会话内容造成的
卡顿。

CPU 采样中，两轮旧版的 `getContext`、`getShaderParameter` 和 `loseContext`
分别合计约 122 ms；两轮新版在快速切换阶段没有采到这些函数。仅延迟 GPU 恢复的
中间方案曾出现两次长任务，最长 157 ms，其 DOM 回退渲染器逐字符测量占用了较多
采样时间；最终方案批量测量可见字符后，两轮未观察到这类长任务。采样时间是
诊断线索，不是精确的函数计时或因果归因。

原始结果、CPU profile 和合成内容截图保留在
`.tmp/opencode-perf-20261028/{baseline,baseline-repeat,final,final-repeat}-metrics/`，
不属于发布文件。旧、新可执行文件 SHA-256 分别为
