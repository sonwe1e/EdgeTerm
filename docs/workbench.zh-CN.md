# 实验工作台（第一阶段）

面向“同一套框架、多台服务器、多个实验目录”的远程开发与运行管理。目标是把“服务器 / 项目 / 实验变体 / 一次运行”分开记录，减少同时打开多个 VSCode 窗口的需要，而不是在 EdgeTerm 里复制完整 IDE。

## 1. 数据模型与身份规则

### 不建项目的临时编辑

文件面板的单文件菜单提供“在内置编辑器中编辑”，可直接编辑本地 UTF-8 文本及已连接 SSH/SFTP 会话的远程文本，不需要先建立项目。编辑器显示目标路径和服务器身份，“保存到服务器”会写回原会话对应的服务器；本地按钮为“保存到本地文件”。原来的外部“打开 / 打开方式”仍可使用，FTP 目前沿用外部编辑。

单文件上限 4 MiB，拒绝二进制；SSH/SFTP 复用工作台的编码、BOM、换行和 SHA-256 冲突检查。本地保存使用同目录临时文件替换，检查打开时及替换前的哈希，Windows 使用 `ReplaceFileW` 保留目标 ACL。外部进程与本程序之间没有文件系统级哈希 CAS，最后一次检查和替换之间仍存在竞态窗口。

未保存内容在关闭、重新读取和退出程序时要求确认；保存失败或冲突保留草稿。保存期间继续输入的内容仍标为未保存，重新读取期间的新输入不会被读取结果覆盖。临时编辑内容只保存在当前进程内存中，不进入项目草稿恢复列表，程序崩溃恢复未提供。真实远程服务器和跨平台保存仍需按测试方案验收。

首次创建项目时，可以在表单内“新增 SSH 服务器”，保存后自动选中并保留已填写的项目内容。误点背景不会关闭项目表单，主动关闭有修改的表单时需要确认。

```text
ServerRef (profileId, name, host, port, username)
   └── Workspace (name, root, env, commands, runRoot)
          └── Experiment (baseline | variant, root?, branch?, baselineId)
                 └── RunRecord (command, env, gpu, code, snapshot, runDir, logPath, status)
```

- **服务器身份**：`profileId` 是链接；`host/port/username` 是创建项目时保存的身份快照。项目卡片、编辑器工具栏、运行对话框和运行详情都显示 `user@host:port`。
- **不依赖标签 id**：项目、实验和运行记录里都没有终端标签 id。终端标签只额外带一个 `workspaceId`，用来在工作台和终端视图之间关联显示。
- **登录被改动**：如果保存的登录仍存在，但主机、端口或用户名与项目快照不同，连接会被拒绝并提示编辑项目刷新身份，避免把训练启动到另一台机器却沿用旧记录。
- **实验根目录**：实验可以覆盖代码目录。基线默认使用项目根目录；消融变体可以指向同一服务器上的另一个目录。实验只记录分支名，不会自动 `checkout`。

记录保存在应用配置目录的 `workspaces.json`（与 `sessions.json` 同级，写入时仅当前用户可读）。文件损坏时保留原文件并拒绝写入，不会用空数据覆盖。工作区记录目前**不参与**设置/会话数据的导出导入，这是第一阶段的明确边界。

## 2. 使用流程

1. 左侧 **项目 → 新建项目**：选择已保存的 SSH 登录，填写名称、代码目录、环境（如 `conda activate vfi`）、可选运行目录和常用命令（训练 / 验证 / 推理 / Shell）。
2. **实验 → 新建实验**：第一个通常是基线；变体选择基线并可选填自己的代码目录、分支和备注。
3. 点击 **连接**：打开或复用该登录的 SSH 会话。不会在切换项目时自动拨号，避免意外触发 MFA。
4. 右侧 **文件** 打开文件；顶部按钮或 `Ctrl/Cmd+P` 快速打开，`Ctrl/Cmd+Shift+F` 搜索代码。
5. **新建运行**：选择实验和命令，填写环境、GPU、是否快照代码。启动后底部显示运行状态、代码标识、快照、目录和日志。
6. **终端** 视图保留原有终端工作区；从工作台打开的终端会 `cd` 到项目目录并带上环境前缀，标签上显示项目与主机。

快捷键：`Ctrl/Cmd+S` 保存，`Ctrl/Cmd+P` 快速打开，`Ctrl/Cmd+Shift+F` 项目搜索。编辑器内 `Ctrl/Cmd+F` 使用 CodeMirror 的查找替换。

## 3. 编辑器与保存语义

- **按需加载**：CodeMirror 6 只在打开第一个文件时动态导入，主包中不含编辑器代码。构建产物把编辑器拆成多个按需 chunk（`codemirror-*.js` 及语言包 chunk）。
- **文件身份**：`workspaceId + 远端绝对路径`。同一路径在基线和消融目录中是两个不同文档。
- **读取上限**：单个文件 4 MiB；二进制、无法按 UTF-8 或会话编码解码的文件明确拒绝。只读取打开的文件，不扫描数据或 checkpoint 目录。
- **保存**：`project_write_text` 以打开时的 SHA-256 作为 CAS 期望值。服务器副本变化时返回 `conflict`，不覆盖。
  - 锁按**文件**而不是会话：键为 `user@host:port` + 服务器 `realpath` 解析后的父目录 + 文件名。同一登录的多个 EdgeTerm 会话（或同一文件的不同拼写、符号链接目录）因此共用一把锁，不会同时通过哈希检查。
  - 顺序为“写唯一备份 → 写唯一临时文件 → 重新读取目标并比对哈希 → 替换 → 校验大小 → 删除备份”。临时/备份文件是与目标同目录的隐藏文件 `.<name>.edgeterm-<随机>.tmp|.bak`，替换失败或结果不确定时路径会随错误一起返回。
  - **替换方式**：已有目标的保存不直接依赖 SFTP v3 `RENAME`。该操作按协议拒绝覆盖，部分服务器（如 Windows OpenSSH、部分 NAS）严格照此实现，这正是保存报“无法替换”的来源。依次尝试：服务器声明的 OpenSSH `posix-rename@openssh.com` 扩展（原子覆盖）→ v3 `RENAME` → 先把目标移开再 rename 临时文件（第二步失败时把备份移回原位）→ 最后才原位重写并回读校验。前三种要么是旧内容、要么是新内容；最后一种不原子，但只有它能在服务器拒绝一切 rename 时完成保存。
  - rename 前会重新读一次目标，把“检查—替换”窗口压到一次往返。SFTP 没有条件写，POSIX rename 也是无条件原子操作：**在最后这次读取与 rename 之间写入的外部程序仍会赢**。因此这里能保证的是“EdgeTerm 内部的并发保存不会互相覆盖、外部修改通常会被发现”，不能描述为对任意外部写入的原子 CAS。
  - 大小校验失败、替换结果不可读时返回 `uncertain`，保留备份与临时文件；编辑器保留草稿并提示重新加载确认，不会把它当成已保存。
- **状态**：`loading / synced / dirty / saving / conflict / failed` 分别显示；未保存内容另有一个持久化状态（`pending / saved / failed`）。
- **草稿持久化**：未保存内容写到应用数据目录 `drafts/`，**一个草稿一个文件**（原子替换：临时文件 → fsync → rename），不再使用 localStorage，也没有“超出预算就淘汰旧草稿”的逻辑。写失败会返回错误并显示在编辑器上：标签保持打开、草稿标记为未写入、提供“重试 / 复制内容 / 丢弃并关闭”。关闭标签时若草稿写不进去，关闭会被拒绝，而不是静默丢弃。旧版本留在 localStorage 的草稿在首次启动时迁入磁盘，全部成功后才删除旧键。
- **草稿恢复**：草稿记住写入时的远端哈希。哈希仍匹配则恢复为未保存状态；不匹配则同时保留草稿和服务器副本，显示冲突条，提供“重新加载服务器副本 / 用草稿覆盖 / 继续编辑”。来自其他服务器身份的草稿不会自动套用或删除，并会提示来源；顶栏“草稿”列出全部未保存内容（项目、服务器、路径、时间、大小），可打开、复制或显式丢弃。
- **远端变化检测**：激活文档时和每 10 秒做一次 size/mtime 探测，不下载内容；保存时的哈希校验才是最终依据。
- **内存边界**：打开文档的目标数量是 8 个，超出时优先释放最久未使用且已同步的文档；未保存文档不会被释放，因此实际可到 16 个硬上限，再打开会被拒绝并说明原因。文件列表和 Git 状态各保留最近 8 份缓存。日志视图只保留最后 512 KiB，服务器上的日志文件不受影响。
- **编辑状态**：切换文件时销毁 DOM 视图，但每个文档保留 `EditorState`（撤销/重做历史、选区、折叠）与滚动位置，返回时恢复并把键盘焦点交回编辑器；同一相对路径在不同项目下是两份独立状态。**服务器重载**（含冲突时选择“重新加载服务器副本”）会重建文档状态并清空撤销历史，避免撤销回到已不存在的版本；冲突时选择“用草稿覆盖”写入的正是当前编辑器内容，历史保留。**关闭标签**或文档被 LRU 释放时丢弃历史。未同步内容仍由草稿负责，编辑器状态不写盘。
- **差异**：Git 变更列表读取 `git status --porcelain -z`；单文件差异读取 `git diff HEAD`，上限 512 KiB。非 Git 目录仍可打开、保存和比较。跨项目比较使用与 Filer 相同的只读比较器，两侧各最多 4 MiB，支持两台不同服务器。

## 4. 运行语义

运行目录默认 `<项目根>/.edgeterm/runs/<runId>`，包含：

```text
manifest.json  本次运行绑定：执行目录、快照校验、未同步文件、链接的数据目录、工具
meta.json      启动时的完整记录（代码、命令、环境、GPU、路径、快照、绑定）
command.sh     实际执行的脚本（含执行目录、环境前缀与 GPU 选择）
launch.sh      wrapper：清理旧标记、写状态、重定向日志、记录退出码
run.log        标准输出与错误
exit_code      进程退出码
env_ok         环境准备成功的标记（缺失即说明训练命令没有执行）
state / pid    tmux 或脱离进程的状态
code/          可选的代码快照
```

- **代码标识**：记录分支、commit、脏文件列表、`git diff HEAD` 的 SHA-256 与字节数；差异超过上限时标记 `diffTruncated`。未跟踪文件只记录路径，其内容不进入 diff 摘要。
- **快照**：可选的“代码快照”按启动时工作区复制代码/配置/脚本文件到 `code/`，排除 `.git`、虚拟环境、缓存、数据、权重、输出等目录；最多 2000 个文件。复制分两步（先打包再解包）以拿到真实退出码，然后统计 `code/` 的文件数与清单比对：数量一致且未被截断才记为 `verified`。它是代码副本，不是环境副本。
- **执行方式**（运行清单 `binding` 的 `execution`）：
  - **在项目目录中运行**（默认）：命令 `cd` 到项目/实验根目录；`code/` 只是留档，证明启动时那里有什么。界面明确写“项目目录”。
  - **在本次运行的代码副本中运行**：要求快照 `verified`，否则拒绝启动（不会退回到项目目录并继续声称隔离）；命令 `cd` 到 `code/`。数据/权重目录通过“链接的数据目录”显式挂入（项目内相对路径，符号链接），任何一条链接失败即拒绝启动。`EDGETERM_PROJECT_ROOT` 始终导出，绝对路径仍指向原项目——这一点在界面上写明，不暗示编辑与运行已完全隔离。
  - 快照缺失、截断或复制失败时，`binding.snapshotVerified` 为 false，隔离启动不可用。
- **未同步编辑**：启动前前端把仍在编辑器中、尚未保存到服务器的文件列表交给后端；`requireClean` 默认开启，列表非空时拒绝启动。用户可在运行对话框中勾选“仍然启动，使用服务器版本”，此时列表会写入 `binding.unsynced`，运行详情可见“启动时未同步”。因此不会在没有提示的情况下用远端旧版本启动。
- **执行方式**：服务器有 tmux 时用命名会话（`et-<runId>`），支持附着；没有 tmux 时用 `setsid`/`nohup` 脱离进程，只能看日志，不能附着。界面会明确提示。
- **调度系统**：探测 `sbatch/qsub/bsub/srun`。`sbatch/qsub/bsub` 只记录“已提交”，不会把提交命令的退出当作训练完成；`srun` 是前台运行，仍以进程退出码为准。
- **启动结果不确定**：运行记录在启动命令执行**之前**写入（`starting`）。启动命令的返回读不到时，记录改为 `unknown` 并返回警告，界面提示先刷新确认，绝不把它当成“没启动”。用同一 run id 重试会被拒绝（记录已存在，或远端 tmux/pid 仍存活）。
- **状态**：`starting/running/submitted/finished/failed/lost/stopped/unknown`。连接断开或会话关闭时，运行记录保留上次状态并显示“可能已过期”，不会推断为完成。重连后只查询 tmux/进程与日志，**不自动重新启动**。
- **环境**：`command.sh` 先 `cd` 到实际执行目录；若环境文本包含 `conda activate`，会先 source 服务器上的 `conda.sh`（通过 `conda info --base` 定位）。环境段在 `set -e` 下执行：`conda activate` 或 `export` 失败会立刻终止，训练命令不会在错误解释器下运行；成功后才写 `env_ok`。如果退出码非零且没有 `env_ok`，状态说明写“环境准备失败，训练命令未执行”，而不是笼统的“训练失败”。
- **GPU**：只有纯数字/逗号（如 `0,1`）会导出 `CUDA_VISIBLE_DEVICES`；其他写法只记录，不猜测框架。
- **恢复/重跑**：从运行详情点“继续 / 重跑”会用原命令、环境和 GPU 启动一次新运行，并记录 `resumedFrom` 链接。它不声称复现原运行，也不自动寻找 checkpoint。

## 5. 多主机资源

- 每个服务器只保留一个采样任务；同一登录下的多个项目共享。
- 前台每 5 秒、窗口隐藏时每 30 秒；隐藏时只刷新过期样本。
- 卡片显示 CPU / 内存 / 第一个 GPU，弹层列出全部 GPU、磁盘、网络和采样时间；失败时保留上次数值并标记错误。
- 采样复用原有 `sample_resources` 和 `session::exec`，不新增常驻 agent。工作台打开时状态栏不再重复采样同一主机。

## 6. 复用与边界

复用：SSH 连接池与自动复用、会话标签与终端、Filer 的目录/文件操作、`remote_edit`（外部程序打开文件并回传；编辑器不再走它）、`file_diff` 的有界比较、`resource_monitor`、端口转发（终端视图，工作台未接入）。

并发与持久化的边界（明确不承诺的部分）：

- 两个 EdgeTerm 进程（两个窗口）之间没有共享锁文件；同一台机器上的两个进程仍可能同时保存同一文件，靠 rename 前的重读缩小窗口，但不能消除。
- 外部程序（Vim、rsync、训练脚本写配置）不参与这把锁；它们在“最后一次重读”与“rename”之间写入会被覆盖。SFTP 没有条件写，客户端锁无法约束它们。
- 草稿按文件写在应用数据目录，不做数量淘汰；磁盘写满时表现为可见错误与保持打开的标签，不会静默删除其他草稿。草稿不做云端同步，也不在数据导出中。

未做/不在第一阶段：

- 完整插件生态、语言服务器、断点调试、终端多路复用 UI。
- 自动把代码差异转换为实验配置；差异只作为记录和比较入口。
- 自动识别任意调度系统的作业状态（只识别提交命令并如实标为“已提交”）。
- 自动检测 checkpoint 并恢复训练；没有训练框架的 checkpoint 规则。
- 工作区/运行记录的导出导入、多人共享、跨设备同步。
- FTP 项目工作区（项目操作要求 SSH/SFTP 会话）。
- 真实插帧项目的训练/验证/推理/评测适配（见第 10 节）。

### 7.1 本轮：多文件编辑连续性

最终代码上的检查（全部在本轮改动之后重新运行）：

```text
npm run test:browser                      11 个文件 / 57 个用例通过（新增编辑器连续性 5 个）
vite build（临时输出目录）               通过；主包 710,135 B，CodeMirror/TOML 仍是按需 chunk
npm run lint                              通过（仅生成文件 bindings.ts 的 2 条 noExplicitAny 警告）
cargo test --manifest-path src-tauri/Cargo.toml --lib
                                          386 个通过；25 个真实环境用例 ignored（串行重跑）
cargo fmt --check                         通过
npm run check:bindings                    通过（123/128 命令，5 个事件）
```

一次并行运行（前端单测、浏览器测试、Rust 测试同时启动）时，Rust 侧有 2 个 `file_transfer` 限速用例失败；随后单独重跑 386 个全部通过，失败项是共享机器负载下的计时断言，与本轮前端改动无关。

旧实现上的失败证据：改动前 `CodeEditor` 以 `key={doc.id}` 卸载即销毁视图，重挂载用文本重建 `EditorState`。用同一组真实 CodeMirror 浏览器测试运行旧代码，5 个用例中的前 4 个（第 5 个是修复后补的）有 3 个失败：

```text
keeps undo history, selection and scroll when another file is opened and closed
  expected +0 to be 946            （选区回到 0，滚动位置也归零）
keeps two projects' copies of the same relative path apart
  expected false to be true        （返回原文件后 undo 已无历史）
drops undo history when the server content replaces the document
  expected true to be false        （重载后 undo 把旧版本撤了回来）
```

## 8. 性能测量

### 8.1 本轮已测：编辑器切换与输入（本机组件级）

用真实 `CodeEditor` + CodeMirror 在 headless Chromium（1200×760）中测量，文件为 4000 行 Python，每项 24 个样本：

```text
保留状态的切换（热）  中位 31.9 ms（30.0–48.0）
丢弃状态后重建（冷）  中位 32.6 ms（29.9–49.6）
单次插入派发          每次样本 200 次插入求平均：中位 8.5 ms（1.6–9.0）
```

热切换与冷重建的差异（约 0.7 ms）落在噪声范围内：保留撤销历史没有让文件切换变慢，因为两种路径都要新建 `EditorView` 并布局。8.5 ms 是直接调用 CodeMirror 事务的派发成本，不是端到端键盘延迟，也不包含 React 渲染或 IPC。

边界：这是浏览器标签页里的组件测量，不是 EdgeTerm 桌面进程树；没有三个真实项目、没有 SSH、没有保存往返、没有远端搜索。**不能用它宣称内存或网络收益。**

### 8.2 仍需真实三项目工作流的对照

当前**没有**与同等 VSCode 工作流的真实对照测量，不能承诺固定内存或 CPU 降幅。需要按以下口径测量后再给结论：

- 场景：3 个项目（2 台服务器、同服务器 2 个目录），每个项目 2000 个代码文件，2 个终端各 5000 行输出，1 个运行日志 20 MiB。
- 对照：3 个 VSCode 窗口（Remote-SSH）与 EdgeTerm 单窗口；同一机器、同一服务器、同一构建模式（release），预热后各测 3 次。
- 指标：整个应用进程树的 RSS 与 CPU 时间/占用率、首次可交互时间、切换项目到可编辑的时延、保存往返、网络字节（SSH 通道）、WebView2/渲染进程内存。
- 归因：把“本机计算（渲染、语法高亮）”“远端处理（grep、git、日志尾读）”“网络等待（往返）”分开记录；少一个窗口、分包和数量上限都不能直接当作性能结论。
- 当前可说明的机制：CodeMirror 动态导入、文档 LRU 目标 8 个/硬上限 16 个、列表与 Git 缓存各 8 份、日志视图 512 KiB、文件读取 4 MiB/差异 512 KiB、采样 5/30 秒。它们只说明上界，不说明实测收益。

## 9. 仍会迫使返回 VSCode 的环节

本轮**没有真实项目任务**，因此无法按“实际被迫返回”的次数排序；下面是基于当前实现和这次编辑器修复的判断，接入真实任务后应以记录到的事件重新排序。

| 环节 | 类别 | 当前状态 | 判断 |
|---|---|---|---|
| 跨文件跳转定义、补全、诊断 | 功能缺失 | 只有语法高亮、缩进、查找替换、快速打开、有界项目搜索 | 改动跨 3 个以上 Python 文件、需要追调用链时最可能迫使返回；是否优先取决于真实任务，不预设“必须有语言服务器” |
| 断点调试 | 功能缺失 | 只能看日志、退出码与运行状态 | 需要单步排查数据/形状问题时无法替代 |
| Git 提交历史、暂存区、三方合并 | 功能缺失 | 只有工作区 diff 与跨项目同路径比较 | 合并冲突或回滚到历史版本时要回 VSCode |
| 笔记本、图片/权重预览 | 功能缺失 | 不支持 | 插帧结果若以图片/视频呈现，需要外部查看器 |
| 跨项目对比入口 | 已有功能难以找到 | 入口在“变更”标签的每行操作里 | 属于可发现性问题，不是缺功能；真实任务中若多次找不到再调整入口 |
| 运行日志与结果 | 已有功能难以找到 | 需先在侧栏选中运行，日志在运行面板底部 | 同上；若频繁发生，应把“最近运行”提到项目卡片 |
| 撤销/选区/滚动/焦点 | 状态恢复失败 | 本轮修复 | 已由 5 个真实 CodeMirror 用例覆盖；服务器重连后的编辑器状态未测 |
| 保存、搜索、日志尾读的响应 | 响应过慢 | 未在真实服务器测量 | 需要真实项目才能区分远端处理与网络等待 |
